Checkbox 复选 · 设计规格（数据录入组件 #25 · 任务清单 #25，subcategory=form · 门禁 A）

组件 ID：ui.checkbox ｜ 定位：通用复选勾选框（方形圆角勾选框 + 可选 label）——单只 Checkbox（独立二态勾选标记）与 CheckboxGroup（垂直多选列表，数据驱动）两种形态；勾选框 20pt/20dp、选中 primary 底白勾、label 后置；点按切换=onChange(选中集) 回调并回显；选中态半受控（selectedValues 外部可驱动回显）。对标 NutUI checkbox / Ant Checkbox 收敛为库内自有设计语言；与业务收编 AgreementCheckRow（协议富文本行=圆形 12dp 小勾）明确区分：协议场景继续用收编行，本组件=通用方框复选。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-06，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 多选标签/偏好（兴趣、账本、提醒日），CheckboxGroup 垂直列表逐项勾选；② 单只独立勾选（Cell 行尾"启用/开启 XX"二态标记）；③ 编辑回显：宿主已持选中 value 集，CheckboxGroup 回显勾选并高亮；④ 条件筛选多选（列表页筛选项勾选组合）
不适用（N/A）① 「已阅读并同意协议」富文本行（协议名主色可点跳转）→ AgreementCheckRow 业务收编（android/foundation/design/AgreementCheckbox.kt），本组件不承载富文本链接；② 二元即时开关（拨动式开/关、状态持久切换）→ Switch 类独立组件/既有开关（若清单立项）；③ 单选排他（多选组内只能选一）→ Radio 单选（清单另行立项）
五态适配默认态 ✅ 未选=白底描边方框（边框 textTertiary）+label 主文字；选中态 ✅ 勾选框 primary 实心底+白色对勾，label 保持主文字（可加主色? 不加=与协议行一致不加色，纯框区分）；禁用态 ✅ 整项灰 40%（textTertiary）不可点；已选中+禁用=灰底灰勾保留勾选呈现；加载/失败 N/A（宿主自理）
与现有组件关系deps=[DesignTokens]；与 FormFieldRow #28 兼容=Checkbox/CheckboxGroup 作为内容槽放入字段行（行高随组件撑开）；与 Cell（内容区）兼容=单只 Checkbox 可置于 Cell 内容位；与 Menu 半受控回显、InputNumber 外部驱动=同一状态惯例；与 AgreementCheckRow（业务收编，不进库级清单）=场景重叠仅协议行

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
勾选框20pt/20dp 方形，圆角 6（radiusSm 系）；未选描边 1.5pt/1.5dp 边框 textTertiary、白底；选中=底 primary、勾白方形圆角勾选框=库内复选视觉（区别于协议行圆形 12dp）
对勾白色对勾字符/矢量 13pt/13dp，勾选框内居中文本字符 or 矢量实现平台差异表内放行（见 §05）
label后置、与勾选框间距 8（spaceSm）、Md16 主文字、单行省略无 label=纯勾选框（高仍 20+ 命中区 20）
组行高/间距CheckboxGroup 垂直列表，行间距 4（spaceXs 组内紧凑）+行上下内 padding 10；整组内容宽=宿主容器宽列表项右缘不拉伸（勾选框+label 左起、命中区=整行可点）
禁用态disabled=textTertiary 40% 灰（勾选框描边/实底/对勾与 label 全灰）；disabled 项不可点无回调已选中 disabled=灰底灰勾=保留勾选语义可读
数据驱动CheckboxOption(value, label, disabled) → 独立 value 落库；CheckboxGroup(options, selected?, onSelect) 集合同步与 CascaderOption/TabItem/MenuOption 数据驱动惯例同构

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 组件形态：ACE 三选

选项后果评估
A：独立通用复选组件双形态——单只 Checkbox（勾选框+可选 label，Cell/表单内嵌用）+ CheckboxGroup（options 数据驱动垂直多选列表）双端各自实现；方形圆角勾选框 20 + primary 底白勾视觉✅ 场景覆盖完整：列表多选与单只二态都落库级 API；方形圆角=区别于协议行圆形视觉、互不干扰；垂直列表一期足够（表单/筛选主场景）；双端实现纯绘制+点击=轻量可靠推荐 A：单只+组双形态
B：仅做 CheckboxGroup 垂直列表（不做单只）Cell 内嵌/表单行内"启用 XX"场景无组件可用（宿主被迫自绘方框）淘汰：单只是最小原子
C：复用/改造 AgreementCheckRow 圆形勾选为通用复选（圆形视觉全面铺开）协议行=场景专用富文本+小号 12dp 圆点+点击区分协议链接，通用复选语义（标签列表多选）硬套会带出富文本复杂度与视觉错位淘汰：业务收编不动，独立新视觉

P2 · 数据模型：ACE 三选

选项后果评估
A：CheckboxOption(value, label, disabled) 数据驱动 + CheckboxGroup(options, selected: Set<value>?, onSelect)；单只=Checkbox(label?, checked, onChange)✅ value 稳定落库、disabled 项内联可配；外部按 set 回显（编辑场景）；与库内 option 数据驱动惯例同构；label 纯展示（富文本=协议行职责）推荐 A：数据驱动惯例
B：仅 label 字符串数组（无独立 value）多选结果落库歧义（同名文案/文案变体）；外部回显无法按 value 稳定匹配淘汰：同库惯例已弃（见 Menu P2）
C：Node 多态结构（value 可嵌套 children 组）分组多选=树形嵌套复杂度一期不需要；垂直扁平列表足矣（分组标题=宿主分组渲染多组 CheckboxGroup）淘汰：二期（嵌套分组再议）

P3 · 状态控制：ACE 三选

选项后果评估
A：半受控——selected（Set）可选传；nil=内部自持当前勾选集，每次点按=切换该 value 并回调 onChange(newSet)；外部赋值 selected=同步刷新渲染（编辑回显/重置），不触发 onChange（同 InputNumber/Menu 惯例）；单只 checked 同规则（nil 自持）✅ 表单提交=宿主拿 onChange 回传集；编辑回显=外部 selected 驱动；自持=轻量可用；库内状态惯例一致推荐 A：库内半受控惯例
B：纯受控（selected 必传，每次点击宿主回写）简单受控无内部态；但宿主每次点按都要回写新集合（多数场景宿主本就要存结果，可接受）；灵活性弱于 A（不传即不可用）可接受但过度（A 的受控超集）
C：纯自管理（不暴露 selected 外设）编辑回显/重置驱动无门（同 Menu P3-C 结论）淘汰

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：方形勾选框+label 后置+Checkbox/CheckboxGroup 双形态+disabled（项级/已选禁用保留勾）+半受控 selected+demo 四段（单只基础/组多选/禁用/受控外部驱动）；对勾=白勾单字符/矢量✅ 复选核心闭环（勾/取消/禁用/外部回显/集合同步）逐项可验；无动画无嵌套=验收路径清晰推荐 A：核心闭环可验收
B：一期含 indeterminate 半选（组内部分选中父项横杠）半选=三态复杂度+宿主全选/批量父项语义耦合，非复选基础需求淘汰：登记二期
C：一期含勾选动画/横向 wrap 排列/勾选 label 主色联动动画与多方向布局=范围膨胀；label 变色与协议行视觉惯例不一致淘汰：登记二期/不做

05 · 平台差异表（表内放行，表外必须双端统一）

维度iOSAndroid放行原因
勾绘制UILabel "✓" 字符 / 或 CAShapeLayer 描勾Icons.Filled.Check ImageVector（agreement 收编同款）平台矢量机制不同、视觉一致（表内放行）
点击按压反馈touchDown 压暗瞬态（无系统 ripple）clickable 系统 ripple / 组行 combosable 点击无涟漪（agreement 无涟漪先例）系统级原生差异（同全库先例，表内放行）
命中区整行 UIControl/UITapGestureRecognizer，label 一并可点Row.clickable 整行可点两端命中区一致=整行（表内放行机制差异）
状态回写命令式：外部赋值 selected → 显式刷新子勾选框视图（demo onChange 宿主回写 selected 属性）声明式：selected State/参数变化自动重组命令式/声明式机制不同、宿主回写后视觉一致（库内惯例，表内放行）
文字省略/折行UILabel truncateTailText maxLines=1 ellipsis两端单行省略一致指向（表内放行）
无障碍VoiceOver：勾选框 isAccessibilityElement+label+value 选中态TalkBack：语义/selected 状态系统无障碍层各读屏实现不同（表内放行）
尺寸单位 / 命名pt；CheckboxOption/CheckboxGroup struct + CheckboxView（独立 Checkbox.swift）dp；data class CheckboxOption + @Composable Checkbox/CheckboxGroup（Checkbox.kt）Token 同值不同单位；命名差异见门禁 B（表内放行）

06 · API 草案（双端一致契约，门禁 B 据此登记 api.json）

端API
共用CheckboxOption(value, label, disabled=false)
selected: Set<String>?（选中 value 集；nil=内部自持）；onSelect(value: String, checked: Bool) 或 onChange(selectedSet)（有效点按触发；disabled 幂等无回调；外部赋值 selected 不触发 onChange）；单只=Checkbox(label? , checked: Bool?, onChange(Bool))
iOSfinal class CheckboxView: UIView（勾选框+label+整行命中）；final class CheckboxGroupView: UIView
init(options: [CheckboxOption], selected: Set<String>? = nil, onChange: ((String, Bool) -> Void)? = nil)；`var selected` 外部赋值驱动回显刷新；`var options` 可更新（disabled 变化重渲染）
Android@Composable fun Checkbox(label: String? = null, checked: Boolean?, onCheckedChange: (Boolean) -> Unit, ...)
@Composable fun CheckboxGroup(options: List<CheckboxOption>, selected: Set<String>? = null, onChange: (String, Boolean) -> Unit, modifier)
内部 Column 垂直排列，selected 参数变化自动重组回显
