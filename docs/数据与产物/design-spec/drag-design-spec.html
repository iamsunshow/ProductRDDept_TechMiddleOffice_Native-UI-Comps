Drag 拖拽排序

组件 ID：ui.drag ｜ 任务清单 #47 ｜ 通用功能组件区 ｜ TMO 组件库 v1.4.0

定位：长按列表项可拖拽重新排序——用于收藏管理、章节排序、字段排序等场景。

1. 场景与边界（SCQA）

Situation

记账 App 中收藏分类排序、自定义记账模板字段排序、报表维度排序等场景需要用户手动调整列表顺序。

Complication

双端无统一拖拽排序组件，各业务页自实现逻辑散乱、动画不一致、无平台对齐。

Question

需要一个可复用的拖拽排序组件，支持长按拖拽、实时跟随手指、释放后动画落位、回调新顺序。

Answer

Drag——声明式 API：传入 items 列表 + onReorder(from,to) 回调；iOS 用 UITableView + drag delegate，Android 用 Compose 拖拽 + animateItemPlacement。

3. API 契约

Props

参数类型默认值说明
itemsList<T>必传数据列表（泛型 T 需 Identifiable）
key((T) -> Any)必传每项唯一标识（iOS 用于 diffable dataSource）
itemContent@Composable / (T) -> UIView必传每项渲染内容
onReorder(from: Int, to: Int) -> Unit必传拖拽完成回调（from→to 索引）
enabledBooleantrue是否启用拖拽（false=纯列表不可拖）
handleBooleanfalsetrue=需长按 handle 手柄拖拽；false=整行长按拖拽

Events

事件参数说明
onReorder(from: Int, to: Int)拖拽释放后回调新位置（from=原索引 to=目标索引）

编号决策点选项选定理由

B. 仅手柄触发
C. 两种模式均支持		Chandle 参数切换：默认 false 整行长按，true 时仅手柄可拖

P4一期范围A. 基础拖拽排序+handle+enabled+onReorder+demo4段
B. 二期=跨列表拖拽/多选拖拽		A一期覆盖单列表排序 95% 场景

7. 平台差异表

差异点iOS（UIKit）Android（Compose）判据
拖拽机制UITableView drag delegate + performDropWithLazyColumn + Modifier.pointerInput detectDragGesturesAfterLongPress表内放行（平台原生差异，视觉一致）
落位动画tableView.reloadData 或 moveRow 动画animateItemPlacement()表内放行（均 0.25s easeOut 视觉一致）

8. 反目标

不做原因
跨列表拖拽二期增量，一期单列表排序已够用
多选批量拖拽二期增量
网格拖拽一期只做纵向列表排序
拖拽中实时回调一期仅释放后回调
