DesignTokens 设计令牌

组件 ID：foundation.design-tokens ｜ 任务清单 #91 ｜ 底层能力 foundation ｜ TMO 组件库 v1.4.0

定位：全库视觉唯一基准——颜色（AppColor）/ 字号（AppFont）/ 间距（AppSpace）/ 圆角（AppRadius）/ 文本排版（AppText）五组编译期常量，所有组件的视觉取值必须来源于此（Token 零硬编码红线）。

1. 场景与边界（SCQA）

Situation

双端 95+ 组件共享同一套视觉语言（主色 #16A34A、字号阶梯 12–32、间距 4–24、圆角 6/10/14、行高倍率 1.8），设计稿与代码必须一一对应。

Complication

若各组件自行写死色值 / 字号 / 间距，视觉语言将快速漂移（同名不同值、双端不一致），且无法全局审计。

Question

需要一份可被双端同时引用的令牌基准，值来自唯一数据源，且能被组件、Demo、验收三者共同校验。

Answer

DesignTokens——双端同构的五组常量（AppColor / AppFont / AppSpace / AppRadius / AppText），数值与 docs/design/tokens.json 对齐；iOS 为 enum 静态常量，Android 为 object 常量并提供 Material3 主题桥接。

2. 组件边界与划界

组件职责与 DesignTokens 划界
ConfigProvider #3运行期主题作用域栈（可覆盖令牌并向下继承）ConfigProvider=运行期「覆盖与继承」机制，DesignTokens=编译期「默认值基准」；ConfigProvider 的默认解析结果即 DesignTokens
各 UI 组件渲染与交互组件只「消费」令牌，不得自带色值/字号字面量（违反=门禁 A/C2 打回）
docs/design/tokens.json设计侧数据源json=设计侧事实源，DesignTokens=代码侧镜像；二者数值必须一致（不一致=设计对齐缺陷）

7. 平台差异表

差异点iOS（UIKit）Android（Compose）判据
单位类型字号 CGFloat(pt) / 间距 CGFloat(pt)字号 TextUnit(sp) / 间距 Dp表内放行（数值同值，单位体系为平台原生）
颜色构造UIColor(hex:) 扩展Color(0xFF...) 直接构造表内放行（输出色值一致）
主题桥接无（UIKit 无 Material 主题体系）KeepAccountsTheme（Material3 映射）表内放行（Android 侧额外适配 Compose 组件生态；iOS 通过令牌直取）
文本样式 APINSAttributedString + UILabel 扩展TextStyle 辅助函数表内放行（排版参数同值）
