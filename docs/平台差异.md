# 双端差异豁免白名单（diff-api）· 判据页

> 地位：组件库双端差异豁免的**人读判据页**。数据本体=`docs/数据与产物/diff-api.json`（差异 API 注册表），与 `docs/数据与产物/api.json` **共同描述完整组件特征**：
> - `api.json` = 双端一致的契约（props/events/状态/平台状态）；
> - `diff-api.json` = 契约统一前提下，允许保留的系统级原生差异豁免（白名单）。
> 白名单之外的差异一律禁止。配套：设计对齐与令牌复用规则见《产研部-唯一权威手册》第二章（docs 入口 `docs/README.md`）；验收门禁 A 检查项与验收标准正文见手册第二章（docs 侧 `验收标准.md` 壳已于 2026-09-04 收拢删除）。

## 这是什么（大白话）

开发 iOS/Android 时总会遇到系统逼出来的差异（手势、返回键、水波纹、hover…）。`diff-api.json` 就是「这些差异被批准豁免的清单」：**表内差异=系统原生差异放行；表外差异=未登记即差异化=验收打回**。

## 何时读、怎么用

- 开发遇到双端不一致 → 先查 `diff-api.json`：在表内=放行；不在表内=必须双端统一，禁止差异化。
- 验收（门禁 A / C2 命名比对 / 发版）→ 对照 `diff-api.json` 裁决：表内放行、表外打回。
- 新差异确属系统级原生 → 登记 `diff-api.json`（注明原因与来源坐标），登记才生效。

## 注册表字段说明

| 字段 | 含义 |
|---|---|
| `id` / `component` | 关联 `api.json` `components[].id`；`system`=跨组件通用差异（不绑定单组件） |
| `scope` | `contract`=契约层语义差异（契约名已双端统一）/ `implementation`=实现层差异（视觉结果一致）/ `system`=系统能力差异 |
| `contract_point` | 在 `api.json` 内的契约坐标（如 `events.onLongPress`、`props.dismissOnBackPress`） |
| `ios` / `android` | 两端各自行为/取值 |
| `rationale` / `source` | 豁免原因 + 登记来源坐标（design-spec 章节 / api.json 位置） |
| `registered_in` | 登记时的组件库版本 |

## 登记规则（治理=不能私改）

1. 出现双端差异 → 先评估是否**系统级原生差异**：是 → 登记 `diff-api.json`（注明原因）；否 → 双端必须统一，禁止差异化。
2. 未登记即差异化 → 视为违规，验收门禁打回。
3. 已有条目如需修改 → 走组件治理变更（治理规则正文在产研部唯一手册=入口壳 `docs/README.md`），不能私自改。
