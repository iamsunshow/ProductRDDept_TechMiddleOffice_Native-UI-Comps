Loading 加载中 · 设计规格（操作反馈区 #50 · 门禁 A）

组件 ID：ui.loading ｜ 定位：全屏/区域遮罩加载指示器——双类型（circular 环形/spinner 多线）+ 双方向（horizontal/vertical）+ 可选文案，不内置遮罩（宿主组合 Overlay #6 做全屏加载），对标 NutUI React Loading + Vant Loading。
组件库版本 设计阶段锁定基线 = v1.4.3（2026-09-08，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 异步操作加载指示（提交表单/登录/保存等需等待的场景）；② 全屏遮罩加载（与 Overlay 组合，阻断用户交互）；③ 区域内联加载（按钮内/卡片内局部加载）；④ 双类型选择：circular（环形旋转，默认）/ spinner（多线跳动）；⑤ 双方向排列：图标+文案 horizontal（水平，默认）/ vertical（竖向）
不适用（N/A）① 列表底部滚动加载 → InfiniteLoading（ui.infinite-loading）#49；② 有进度值的环形/条形进度 → CircleProgress（ui.progress-circle）#64 / Progress（ui.progress）#73；③ 首屏骨架占位 → Skeleton（ui.skeleton）#57；④ 下拉刷新 → PullRefresh（ui.refresh）#55；⑤ Toast 轻提示 → Toast（ui.toast）#59
五态适配默认态 ✅ 加载指示器持续旋转展示；禁用 N/A（加载是瞬态行为，无"禁用"语义，不加载则不渲染）；其余态 N/A（Loading 无选中/错误/完成态，加载结束即移除组件）
与现有组件关系deps=[DesignTokens]（颜色/字号/间距 token，零硬编码）。与 InfiniteLoading #49 划界：InfiniteLoading=列表内联底部状态条（四态+滚动触发），Loading=全屏/区域遮罩加载指示（纯展示，无状态机，无滚动监听）；与 CircleProgress #64 划界：CircleProgress=有进度值环形进度（value 0~1），Loading=无进度值无限旋转加载指示；与 Overlay #6 划界：Overlay=通用遮罩层（zIndex/动画/点击穿透），Loading=加载指示器（不内置遮罩，宿主组合 Overlay 做全屏加载=与 NutUI Loading+Overlay 组合模式一致）

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
图标默认尺寸 sizesizeLg 18pt/18dp（默认）circular=外径 size×size+border 2.5；spinner=高 size+5 线宽 3 间距 3
文案默认字号 textSizesizeSm 14pt/14dp（默认）文案色=textSecondary，与图标同色（可配 color 覆盖）
默认颜色 colortextSecondary（默认）图标色+文案色统一 color 参数，可配 primary 等覆盖
方向排列 gaphorizontal=spaceSm 8 / vertical=spaceSm 8图标与文案间距，水平=横排居中，竖向=纵排居中
circular 动画iOS UIActivityIndicatorView / Android CircularProgressIndicator系统级原生加载动画，不自制旋转
spinner 动画5 线跳动 scaleY 0.4↔1 / 1s ease-in-out infinite双端自绘 5 线 Canvas/UIBezierPath，交替延迟 -0.4s~-0s
全屏遮罩（宿主组合）Overlay visible=true + Loading vertical 居中遮罩色 rgba(17,24,39,.4) 由 Overlay 承载，Loading 不内置

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 一期形态：ACE 三选

选项后果评估
A：纯加载指示器模式——组件 = 图标（circular/spinner）+ 可选文案 + 方向排列，不内置遮罩，宿主组合 Overlay 做全屏加载✅ 语义单一只做"加载指示"，遮罩交给 Overlay（与 NutUI Loading+Overlay 组合模式一致）；内联/全屏双路径覆盖（按钮内/卡片内=裸用，全屏=Overlay 包裹）推荐 A：单一职责，遮罩复用 Overlay #6 不重复造轮子
B：自包含遮罩模式（组件内置 Overlay 全屏遮罩 + visible 开关）组件即插即用，但与 Overlay #6 职责重叠，遮罩参数（色/透明度/点击穿透）重复暴露。淘汰：与 Overlay 职责重叠，破坏单一职责
C：纯图标模式（无文案参数，文案宿主自行拼接）双端文案一致性无法保证，且"图标+文案"是基础体验。淘汰：文案是基础需求

P2 · 图标类型：ACE 三选

选项后果评估
A：双类型 circular（环形旋转，默认）+ spinner（5 线跳动）✅ 覆盖 NutUI/Vant 主流两种加载图标；circular=系统原生（iOS UIActivityIndicatorView/Android CircularProgressIndicator），spinner=双端自绘 5 线 Canvas/UIBezierPath推荐 A：双类型是 NutUI 标准，circular 系统+spinner 自绘覆盖全场景
B：仅 circular（系统菊花）简洁但缺 spinner 选项，与 NutUI type=spinner 对不齐。淘汰：spinner 是主流加载图标之一
C：自定义 icon slot（JSX.Element/UIView 传入）灵活度最高但双端一致性难保证（iOS UIView vs Android Composable），且一期无 Lottie 依赖。淘汰：登记二期（anti_goals）

P3 · iOS 实现路径：ACE 三选

选项后果评估
A：circular=UIActivityIndicatorView 系统 / spinner=CAShapeLayer+5 线 CABasicAnimation 自绘✅ circular 用系统原生动画（零自制）；spinner 用 CoreAnimation 5 线 scaleY 交替（与 Android Canvas 同构）；颜色/大小参数化推荐 A：系统原生优先+自绘补齐 spinner
B：全自绘（CABasicAnimation 旋转 CAShapeLayer 圆环）不利用系统 UIActivityIndicatorView，多此一举。淘汰：系统原生优先
C：Lottie SDK 依赖引入三方库依赖，与库内零三方依赖原则冲突。淘汰：anti_goals 已登记

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：双类型（circular/spinner）+ 双方向（horizontal/vertical）+ 可选文案 + color/size/textSize 参数 + Demo 4 组 1:1✅ 覆盖 NutUI 全部主流场景；circular 系统+spinner 自绘双路径；内联/全屏双展示推荐 A：范围收敛但覆盖完整
B：一期仅 circular+horizontal（无 spinner/vertical）与 NutUI type/direction 对不齐，功能残缺。淘汰：spinner/vertical 是基础
C：一期即支持自定义 icon slot + Lottie增加三方依赖+双端一致性风险。淘汰：登记二期

05 · 平台差异表（表内放行，表外必须双端统一）

维度iOSAndroid放行原因
circular 实现UIActivityIndicatorView（系统菊花）CircularProgressIndicator（Compose 圆形进度）系统级原生差异：各自系统加载动画
spinner 实现CAShapeLayer+5 线 CABasicAnimation scaleYCanvas+5 线 animateFloat scaleY语义一致：均为 5 线交替跳动（表内放行，控制点 1:1 对齐）
文案渲染UILabel 文本Text 文本同一文案双端渲染（表内放行）
方向排列UIStackView axis=.horizontal/.verticalRow/Column Arrangement语义一致：均为 flex 排列（表内放行）
全屏遮罩宿主 Overlay #6 + keyWindow 挂载宿主 Overlay #6 + Dialog/Popup遮罩由 Overlay #6 统一承载，Loading 不内置（表内放行）
