InputNumber 数字输入 · 设计规格（数据录入组件 #? · 任务清单 #30，subcategory=form · 门禁 A）

组件 ID：ui.input-number ｜ 定位：步进式数字输入控件（内容组件，无弹层/无键盘拉起面）——宿主传入数值与步长，用户点 − / + 按钮按 step 增减，中间显示当前值；支持 min/max 边界（到达边界对应按钮禁用置灰）、precision 小数位、disabled 整组件 40% 置灰、半受控 value 外部驱动；一期不做键盘直输（键盘拉起=宿主/Input 组件职责），不做长按连续步进。对标 Vant Stepper / NutUI InputNumber 收敛为库内自有设计语言（圆角按钮式步进器 + 半受控值 + 边界禁用），与已验收录入三件（Address/CalendarCard/Cascader）同属数据录入区。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-06，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 数值微调型字段：数量（购物车/下单）、份数、人数、步长固定的小数/整数数值；② 边界受限步进：min/max 区间内连续增减（到达边界按钮置灰不可继续）；③ 小数精度固定场景（金额分、比例 0.1 步长等）由 precision 收敛展示值；④ 编辑回显：宿主已有 value 外部传入同步显示
不适用（N/A）① 自由文本/数字键盘录入（无步长语义、允许任意小数、位数长）→ Input（#29 缺口）/宿主；② 滑杆区间 → Range（#36）；③ 金额大数精确计算 → 宿主精度策略（MoneyFormat 工具）；④ 长按连续加速步进/滑动手势改值=二期
五态适配默认态 ✅ − / + 按钮主色图标、值主色居中；边界态 ✅ 值=min 时 − 禁用灰 40%、=max 时 + 禁用灰 40%；禁用态 ✅ disabled=true 整控件 40% 置灰不可点（含按钮/值）；加载/失败 N/A（无异步）
与现有组件关系deps=[DesignTokens]；与 Input（#29）划界=本组件=步进式限定增减，Input=自由文本（含键盘）；与 Slider/Range 划界=本组件=离散步进按钮无滑动；表单内嵌=Form（#28）字段行 content

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 组件定位：ACE 三选

选项后果评估
A：步进器（− 值 +）——min/max/step/precision/disabled 半受控 value；纯点按增减，无键盘✅ 核心"步进改数"闭环收敛：边界禁用/禁用态/小数精度都确定；内容组件无弹层无键盘=双端轻量可靠；与 Form/Input 分工清晰推荐 A：收敛可验收
B：步进 + 中点值可键盘直输（点值弹出数字键盘直接录入）键盘/光标/输入法态=Input 组件职责（#29 iOS 未实现）；值合法性需实时解析+容错（半输入态"1."等）；iOS TextField vs Android BasicTextField 键盘差异大淘汰：登记二期（值区可点直输，随 Input 能力收敛）
C：长按连续/加速步进 + 滑动手势改值一体长按计时器/加速度/拖拽手势双端差异大且需防误触；一期价值低淘汰：登记二期

P2 · 值语义与精度：ACE 三选

选项后果评估
A：Number/Double 值 + 显式 precision 决定展示与步进对齐——展示=value 按 precision 小数位；增减运算结果超过 precision 小数位则四舍五入到 precision；防浮点用放大整数/Decimal 语义✅ 契约单一数值类型（宿主落库友好）；precision 显式=展示确定；浮点误差在运算收敛时消除推荐 A：类型单一 + 精度显式
B：字符串值透传（宿主给定任意文本）加减法需解析字符串为数值再回写字符串=解析规则重蹈；"类型漂移"到宿主又弹回淘汰：类型漂移、无收益
C：整数值专用（Int）+ 小数另件金额/比例等常见小数步进场景（0.1/0.05）无处安放；两个组件重复淘汰：数值统一 Number 语义

P3 · 值控制模式：ACE 三选

选项后果评估
A：半受控 value——组件内部持当前值；宿主外部 value 赋值=同步刷新（编辑回显）；每次有效增减触发 onChange(value)；点已到边界按钮=无回调（不可增减）；受控外部改值不触发 onChange（宿主驱动）✅ 与库内半受控惯例一致（Tabs selectedValue/Cascader result）；编辑回显/外部重置成立；点边界按钮幂等无回调推荐 A：库内惯例
B：纯受控（value 恒由宿主传、每次变更回调宿主回填）宿主需持值并逐次回填=与库内多数半受控组件不一致；外部驱动与内部自增混用易乱可接受但过度（表单场景宿主本持值，仍可用 A 自管理）
C：纯内部自管理仅通知编辑回显/外部重置（如"清空恢复默认"）无门淘汰

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：步进按钮式 InputNumber——默认 + min/max/step/precision/disabled/半受控 value/边界禁用 + demo 四段（基础整数步进/边界禁用/小数精度 0.5/禁用与受控外部驱动）✅ 覆盖"离散限定增减"核心闭环；边界/禁用/精度/外部驱动四态 demo 可逐验；无键盘无弹层=纯内容组件轻量推荐 A：验收路径清晰
B：一期即含 值区可点键盘直输 + 长按步进键盘/长按计时=双端高成本面（P1-B/C 问题）淘汰：登记二期
C：一期即做 表单字段联动形态（随 Form 自带 label/error 一体）字段行排版=Form（#28）职责；本组件内容件嵌入即达淘汰：重复 Form
