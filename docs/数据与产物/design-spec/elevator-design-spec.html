Elevator 电梯楼层 · 设计规格（导航组件 #2 · 任务清单 #14，subcategory=nav · 门禁 A）

组件 ID：ui.elevator ｜ 定位：数据驱动分组内容 + 右侧楼/字母索引导航的"定位器"——点击索引跳转对应分组、内容滚动联动高亮索引，对标 NutUI React Elevator（楼层/城市选择类）。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-04，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 内容分组多、需快速定位的分组列表（楼层导览/城市选择/账单月份分组/榜单分区）；② 右侧竖排"楼/字母"索引条，点击即跳分组、内容滚动自动高亮当前分组（双向联动）；③ 分组行点击可回传事件（如选中城市/跳业务页）
不适用（N/A）① 悬浮式页面导航菜单 → FixedNav（ui.fixed-nav）；② 单层扁平长列表的右侧快捷跳转（不分组、随屏滚）→ SideBar（ui.side-bar）；③ 联动选择器（左类右子）→ TreeSelect/Cascader；④ 纯滚动吸顶 → Sticky（ui.sticky）
五态适配默认态 ✅ 分组列表 + 右侧索引；交互态 ✅ 索引点击=分组跳转、内容滚动=索引高亮联动；选择态 ✅ 分组行点击（onSelect 可选）；禁用/加载/成功/失败 N/A（数据列表组件，由外层数据态控制，本组件一期不含骨架/占位）
与现有组件关系deps=[DesignTokens]（视觉全 token）；分组行=组件自有极简行视觉（primary 标题 + 细分割线），不依赖 Cell（Cell 带五态/箭头重交互，语义不同）。与导航批划界：SideBar=页面级快速索引；FixedNav=悬浮菜单；Elevator=自带内容的分组定位器

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
分组行高56pt/56dp（= Cell.minHeight 同库规范行高）行内容=标题 primary 字号 Sm/Md + 细分割线 gray4；视觉与 Cell 一致但不依赖 Cell 组件
分组标题行高32pt/32dp，bg=primaryMuted，标题=primary 强调分组 key 竖排在标题条（如 1F/2F、A/B/C）
右侧索引条宽 44pt/44dp，索引字 Sm 级 gray → 当前=primary 加粗索引字高 24pt/24dp 热区（可点），垂直居中靠右，一条边线分隔
内容行文本textPrimary / textSecondary（desc 场景）标题行名称，副文案二期（desc 数据）
滚动容器高度宿主布局给定（组件不强约束）自包含滚动列表：iOS 组件内 UITableView / Android 组件内 LazyColumn

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 容器与联动模式：ACE 三选

选项后果评估
A：自包含定高——组件=内置分组滚动列表 + 右侧索引，高度由宿主约束（双端同构：iOS UITableView / Android LazyColumn），双向联动在组件内部闭环✅ 与楼层/城市页整块使用匹配；联动算法组件内闭环=宿主零配置；滚动 delegate/state 无外部冲突（自包含）。推荐 A：行为可控、双端 1:1 最稳
B：外置列表托管（组件只渲染索引条，操作外部滚动容器）对应 NutUI containerId 模式，但需要宿主为每分组行暴露定位 API，iOS 逐行 position 映射成本高且脆。淘汰：一期登记二期（外部容器联动）
C：整页全高接管（组件铺满并接管导航栏滚动）与页面导航/安全区耦合，破坏"布局上下文宿主定"。淘汰

P2 · 索引来源：ACE 三选

选项后果评估
A：默认由 floors 分组 key 自动生成索引 + index 参数显式覆盖✅ 对齐 NutUI（index 不传自动取 key）；自定义场景（城市字母只留含数据字母）用显式 index。推荐 A：一个 index 参数覆盖两用法
B：仅自动生成场景受限（楼层 key 有 1F/负1F 之外跳脱时无法裁剪）。淘汰
C：仅显式传楼层快速场景也要手填索引，冗余。淘汰

P3 · 双向联动判定：ACE 三选

选项后果评估
A：点击索引=分组首行滚动到可视区顶部（跳转动画同系统滚动）；内容滚动中=当前可视首分组标为当前索引高亮（iOS 用 tableView scrollViewDidScroll + 首可见 section；Android snapshotFlow 派生 firstVisibleItemIndex）✅ 双向联动闭环；判组依据"可视首分组"与手指滚动直觉一致。推荐 A：同构且实现直白
B：按分组中心线判组（更多 anchor 魔法）与直觉差异小但实现复杂，收益低。淘汰
C：无滚动高亮（索引只做点击跳转）导航体验打折（用户不知身在哪个分组）。淘汰：核心语义=A

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：分组标题行 + 文本行（56pt）+ 行点击回调（可选）+ 索引点击/滚动高亮双向联动 + demo 四段可验收✅ 覆盖楼层/城市核心；行点击 onSelect 覆盖业务选中/跳转诉求。推荐 A：范围收敛
B：一期支持行副标题/图标等富行内容自定义需要 cell 复用协议抽象，与 Cell 组件职责重叠。淘汰：登记二期（行内容插槽）
C：吸顶 sticky 分组标题随滚吸附与自包含容器内标题吸顶实现可做，但一期分组标题非 sticky（简化，列表定位已够）。淘汰：登记二期

05 · 平台差异表（表内放行，表外必须双端统一）

维度iOSAndroid放行原因
分组滚动容器UITableView（plain）LazyColumn系统级原生差异：平台列表容器不同
滚动高亮联动实现scrollViewDidScroll + indexPathsForVisibleRows 判当前 sectionsnapshotFlow 读 firstVisibleItemIndex 反查分组系统级原生差异：Delegate vs 状态快照
索引跳分组动画scrollToRow(at: .top, animated: true)animateScrollToItem系统级原生差异：各自系统滚动动画
行高/分组标题高56pt / 32pt56dp / 32dpToken 同一数值不同单位（表内放行，同 Grid/Layout 先例）
数据模型floors: [(key: String, items: [String])]，index: [String]?同构数据类 ElevatorFloor(key, items)契约同构（表内放行，命名差异见门禁 B）
