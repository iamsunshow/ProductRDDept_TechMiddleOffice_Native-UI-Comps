NumberKeyboard 数字键盘 · 设计规格（数据录入组件 #? · 任务清单 #32，subcategory=form · 门禁 A）

组件 ID：ui.number-keyboard ｜ 定位：内嵌式数字键盘面板（常驻内容视图、无自带遮罩/浮层）——3 数字列＋1 操作列（右列「确认」竖条）的 4×4 键格；数字键 1~9、底行（小数/自定义底键、0、退格）由开关与 extraKey 配置；点键=纯事件回调（数字/小数/自定义文本走 onInput，退格走 onDelete，确认走 onConfirm），键盘自身不持有文本值（值由宿主输入模型持有）。对标 NutUI NumberKeyboard 收敛为库内自有设计语言；一期无遮罩/弹层/乱序（弹层随 Popup #54 / Overlay #6 二期组合），业务金额键盘 AmountKeyboard 为强业务独立扩展不混入。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-06，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 敏感/高定制输入键盘：支付金额、短信验证码、身份证号等不希望唤起系统键盘的受控输入区底部放置的自绘数字键盘（宿主用 Stack/Column 把键盘固定到输入区下方=底部常驻或随 Overlay/Popup 二期悬浮）；② 记账/转账类"金额数字 + 确认"录入面板的通用键盘底座（金额格式化/校验=宿主或业务 AmountKeyboard）；③ 需要固定按键尺寸与盲打的数字输入位
不适用（N/A）① 键盘自带的遮罩/弹层/底部抽屉过渡与点击外部收起 → 二期（随 Popup #54 / Overlay #6 组合）；② 金额语义（¥、千分位、两位小数、最大金额）→ 业务 AmountKeyboard（business.amount-keyboard）或宿主封装；③ 非数字自定义键盘（字母/符号/乱序 randomKey/振动/连击删除动画）→ 二期或宿主；④ 替代系统键盘的全局输入法 → 系统能力不收敛
五态适配默认态 ✅ 白底灰网格键格，数字键主文字 22、退格键次文字 14、右列确认 primary 白字；禁用态 ✅ disabled=整键盘灰 40% 不可点、confirmDisabled=仅确认列灰不可点（其余键正常）；可点态 ✅ 点键=立即回调（无延迟）；加载/失败 N/A；选中/展开 N/A（键盘无选项态）
与现有组件关系deps=[DesignTokens]；与 Input #29 划界=Input=单行文本输入控件（唤起系统键盘），NumberKeyboard=自绘键盘面板（配 Input 显隐/系统键盘关闭由宿主组合）；与业务 AmountKeyboard（business.amount-keyboard，记账金额专用=自带千分位/小数/确认金额）划界=本组件=通用裸键格仅事件回调、无金额语义；与 Popup #54/Overlay #6=一期键盘无浮层，宿主若需底部弹出用 Overlay/自身容器承载（二期再对齐 Popup）

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
键格布局4 列（3 数字列+1 操作列）等分；整件高=52×4=208pt/208dp（4 行）行 1-3=数字 1~9；行 4=底行三格（首格=自定义 extraKey 文本，否则 showDot=true 时显示 .、showDot=false 且无 extraKey 时空占位不可点；中格=0；末格=退格）；右操作列=跨 4 行整列「确认」竖条
键样式白底（bgCard）；键间网格线 hairline（iOS 1/scale pt vs Android 0.5dp=同库先例表内放行）；数字字号 22=sizeXl 主文字；退格键字号 14=sizeSm 次文字「删除」；确认列=primary 底白字 16=Md块状键盘惯例（无键间距圆角）；整件无外框=宿主决定圆角/背景；面板 intrinsic 高=208
状态色disabled/confirmDisabled=textTertiary 40% 灰（整面板或确认列）；空占位格=灰 40% 且不响应禁用点键不回调；灰格不可点
事件数字/小数/extraKey 文本 → onInput(字符)；退格 → onDelete()；确认 → onConfirm()键盘无文本状态（值在宿主）；confirmDisabled/disabled 外部受控

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 组件定位：ACE 三选

选项后果评估
A：内嵌式数字键盘面板（常驻内容视图）——4 行×4 列键格（1~9/.或 extraKey/0/退格 + 右列确认竖条），无自带遮罩/弹层/动画；宿主置于输入区下方（Stack 底部）或放入 Overlay/Popup 容器由宿主控制弹出；高度固定 208✅ 内容组件语义（同 Address/Cascader/Menu 无弹层先例）；双端实现=纯网格布局+按钮=轻量可靠；键盘"出现在哪/是否悬浮"由宿主容器决定=职责清晰、验收路径清晰；支付/验证码/身份证 demo 可直接验证按键与宿主文本联动推荐 A：无浮层收敛（悬浮版二期随 Popup/Overlay 组合）
B：键盘自带底部弹层+遮罩+滑入动画（NutUI NumberKeyboard 默认形态）Popup #54 未实现、Overlay #6 为通用遮罩层=弹层/动画机制需自建或等二期；键盘被"弹层"耦合=无法单独复用；双端弹层机制不齐（iOS 需 window/自绘浮层先例少）淘汰：登记二期（随 Popup/浮层机制立项）
C：不做通用，直接复用业务记账 AmountKeyboardAmountKeyboard=强业务（金额千分位/两位小数/记账语义）不可跨产品；通用数字键盘仍是表单/验证码等高频需求淘汰：业务收编≠通用组件

P2 · 键结构：ACE 三选

选项后果评估
A：内置固定键格（1~9 / 底行首格=extraKey 或 . 或空占位 / 0 / 退格 + 右列确认），以 showDot/extraKey 少量开关表达整数/小数/自定义场景；数字/小数字符与自定义文本统一走 onInput✅ 覆盖支付金额（.）、验证码（纯整数）、身份证（extraKey=X）三主流场景；键面稳定=双端 1:1 排布零歧义；键盘无配置复杂度推荐 A：固定键格+少量开关
B：键矩阵数据驱动（二维数组 rows=每键文本，可乱序/完全自定义）灵活但配置面大（键缺失/重复/宽高权重难约束）；随机乱序 randomKey=二期；绝大多数场景用默认键格可接受但过度（乱序二期再说）
C：按键文案即值模型（无 key 无 extraKey 概念）自定义底键（身份证 X）与确认列文案无法与数字事件区分淘汰：缺事件分类

P3 · 状态与事件：ACE 三选

选项后果评估
A：纯事件驱动无内部值——onInput(字符)/onDelete()/onConfirm()；键盘不持文本；disabled/confirmDisabled 外部受控（改值与校验=宿主 Input 模型职责）✅ 键盘零状态=复用最纯、无回显一致性问题；与 Input #29 受控 value 宿主持有惯例对齐（键盘=输入源之一）；demo 用宿主 text 状态验证输入回路推荐 A：库内输入控件惯例（值在宿主）
B：键盘内持 value 半受控（onChange 直通+外部可赋值）键盘与宿主各存一份文本=双状态源（同步/幂等面大）；键盘并无展示文本区=内部持值无收益淘汰：无展示区持值冗余
C：受控 value+onChange 键盘负责拼串把"输入文本校验/格式化"逻辑挤进键盘；与 Input 受控惯例重复且键盘职责越界淘汰：值处理宿主自理

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：一期=4×4 键格（1~9/底行 extraKey or . or 空/0/退格/右列确认竖条）+ confirmText 可改 + showDot/extraKey/confirmDisabled/disabled 开关 + demo 四段（金额/验证码整数限位/身份证 extraKey/禁用与外部确认禁用），键盘纯事件无内部值✅ 覆盖数字键盘三主流场景核心闭环；键格固定实现轻量；demo 逐验 onInput/onDelete/onConfirm/禁用四态清晰推荐 A：验收路径清晰
B：一期即含 遮罩弹层 + 滑入动画 + 点击外部收起浮层/弹层机制未立项（P1-B 问题）；动画与层级双端不齐淘汰：登记二期（随 Popup/Overlay 组合）
C：一期即做 乱序 randomKey + 长按退格连删 + 键盘振动安全乱序/触觉反馈=设备能力差异与动效面大，非核心输入回路；可后续扩展淘汰：登记二期
