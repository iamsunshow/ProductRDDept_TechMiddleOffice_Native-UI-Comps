## 一、设计评审清单（门禁 A）

> 验收方式：打开 HTML 设计规格页（浏览器），逐项目视打勾。

| # | 检查项 | 结论 |
|---|--------|------|
| 1 | 组件用途与场景描述清晰，与分类表一致 | ☐ 通过　☐ 打回 |
| 2 | 视觉呈现符合预期（打开页面看渲染效果） | ☐ 通过　☐ 打回 |
| 3 | 尺寸 / 间距 / 圆角 / 字号正确（页面标注 + token 引用） | ☐ 通过　☐ 打回 |
| 4 | 五态齐全：默认 / 禁用 / 加载 / 成功 / 失败（N/A 已标注） | ☐ 通过　☐ 打回 |
| 5 | 交互细节明确：点击反馈 / 动画 / 弹窗层级 | ☐ 通过　☐ 打回 |
| 6 | 双端差异已说明（登记 平台差异.md） | ☐ 通过　☐ 打回 |
| 7 | 与现有组件无重复（分类表核对） | ☐ 通过　☐ 打回 |

**评审结论（门禁 A）：** ☐ ✅ 通过，冻结设计，进入 API 阶段　☐ ❌ 打回，返工设计

## 二、API 评审清单（门禁 B）

> 验收方式：打开 API 契约页（api.json + www 组件详情页），逐项检查。

| # | 检查项 | 结论 |
|---|--------|------|
| 1 | `id` 命名规范（`ui.*` / `foundation.*`），与分类表一致 | ☐ 通过　☐ 打回 |
| 2 | props：命名 / 类型 / 默认值双端 100% 对齐 | ☐ 通过　☐ 打回 |
| 3 | events：回调名 / 签名双端一致 | ☐ 通过　☐ 打回 |
| 4 | 能力覆盖五态（或标注不支持） | ☐ 通过　☐ 打回 |
| 5 | `capabilities` / `scenarios` 已填（保证检索命中） | ☐ 通过　☐ 打回 |
| 6 | `visual_tokens` 已声明，token 已存在于 design-token.json | ☐ 通过　☐ 打回 |
| 7 | `platforms` 状态与实现计划一致 | ☐ 通过　☐ 打回 |
| 8 | api.json schema 校验通过 | ☐ 通过　☐ 打回 |

**评审结论（门禁 B）：** ☐ ✅ 通过，冻结契约，双端开始实现　☐ ❌ 打回，只改契约
