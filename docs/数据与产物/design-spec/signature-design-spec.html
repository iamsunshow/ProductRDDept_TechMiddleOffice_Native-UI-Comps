Signature 签名 · 设计规格

组件 ID：ui.signature 数据录入区 #40 subcategory=form 全新立项（双端均无签名近似件） 设计稿 2026-09-06 门禁 A

01 · SCQA 组件定位与边界

适用场景（S）

「手写签名」采集：① 协议/单据类确认=签收单、对账单、验收单、送达回执的签署；② 电子流程确认=审批通过签名、任务留档；③ 业务表单附签=收款/交接/承诺等需留本人笔迹的确认块。组件只出「白底签名画板=手指/笔随画留迹」，签名图片导出/上传、页面与弹层承载、保存与防篡改、业务校验（签名是否为空/是否重签）=宿主自理。

目标与冲突（C）

需求=库内缺「随手写即可出签名内容」的笔画采集组件；冲突=iOS 系统 PencilKit（PKCanvasView）能力强但画布/导出为 PKDrawing 生态、样式与库内设计语言不统一且不可全局 disabled 降级；Android 系统无原生签名控件、各三方库质量不一；若由宿主各自实现=每个业务重复造画布（touch 采集/坐标换算/防误触各写各的），无法复用于「演示 1:1 + C1 单测」的统一契约。

问题（Q）

库内是否新增手写签名画板内容组件 ui.signature（双端自绘统一契约）？

答案（A）

定位 是。新增 ui.signature=Signature 签名画板：内容级横长白底画板（bgCard + hairline 描边 + radiusLg 圆角对齐 Input #29 壳语言、宽宿主填充、高默认 96=2×表单交互行 48 基准，注释锚定）+ 手指/笔自绘笔画（圆头线帽、默认线宽 2、默认色 textPrimary，strokeWidth/strokeColor 参数可调）+ 空态水印「请在此区域签名」（textSecondary 30% 居中、首笔落下即消失）+ 底缘引导线（hairline、左右留 spaceLg）；命令式 clear()（宿主「重新签名」钮调用）+ onInkChange(Boolean hasInk)（首笔落 true/清空回 false=驱动宿主「提交」钮可用态）+ disabled（锁定=整板 40% 灰不可绘）。签名图导出=宿主职责（截取组件渲染：iOS UIGraphicsImageRenderer / Android view.draw 至 Bitmap），组件不内置图形对象返回（UIImage vs Bitmap 类型无法跨端统一）。

五态适配

默认态 ✅ 空板=水印「请在此区域签名」居中灰字（30%）、底缘引导线、onInkChange(false)=宿主提交钮禁用；绘制中态 ✅ 落笔即水印消失、笔画随指圆头留迹、onInkChange(true)；已签名态 ✅ 笔迹完整保留、板内不提供二次编辑撤销（撤销=宿主 clear() 重签或二期 stroke 撤销栈）；禁用态 ✅ disabled=整板 40% 灰（含已有笔迹）、触摸不采笔、无任何回调（签署锁定场景=宿主配合文案）；边缘态 ✅ 笔画越界=裁剪于板 bounds（宿主 clear() 后可重画）、空水印+已禁用组合=灰板无水印提示（宿主自理文案）；加载/失败 N/A（签名图上传/保存失败=宿主自理，组件零内部异步态）。

划界与依赖

依赖=DesignTokens（AppColor/AppSpace/字号）+ Input #29 壳语言（radiusLg/hairline=视觉复用惯例，非代码依赖）。与同区组件划界：Input #29 / textarea #42=键盘文本输入无笔画；ShortPassword #39 / NumberKeyboard #32=数字键盘系与手写无涉；未来 OTP 码组件=码类二期；Popup #54 / Overlay #6=签名承载（宿主 sheet/页面弹层组装）。业务（签署单、确认书、签收回执等）复用本组件，宿主自理：签名图片导出与上传、页面/弹层承载布局、保存与防篡改留痕、空签名/重签业务校验、锁定后解锁流。系统级 iOS PencilKit / Android 无原生对应=不收编（样式与契约无法统一）。

03 · 关键决策（P1–P4 投票表）

P1 组件形态与视觉基座

选项方案后果结论
A内容级横长白底签名画板（bgCard+hairline+radiusLg 对齐 Input 壳语言、水印+底缘引导线、自绘圆头笔画），宿主布 label/提交/弹层库内设计语言统一、双端契约一致、宿主组合自由；签名板作为纯内容件符合全库「内容组件宿主组装」惯例A 推荐 ✅
BiOS 封装 PencilKit（PKCanvasView）PK 强能力（压感/工具）但导出 PKDrawing 生态、样式不可控、双端无法 1:1、disabled 语义难全局化淘汰（不收编系统生态件）
C内置整壳签名组件（自带「重签/提交/标题」栏=宿主半组装完成）提交动作/业务栏=宿主职责且差异大，组件膨胀=混入壳与动作职责淘汰（宿主自理 label/按钮/弹层）

P2 笔画采集模型

选项方案后果结论
A双端自绘离散笔画=板内 stroke path 数组（iOS draw(_:)+UITouch began/moved/ended 换算板坐标追加 Path；Android Canvas drawPath+pointerInput awaitEachGesture 每手势一 stroke），线帽 round 直连采样点实现直白、采样点密时自然平滑、两端视觉 1:1、可 C1 单测（注入 stroke 数据断言 path 数）；无第三方依赖A 推荐 ✅
B贝塞尔中点插值平滑（增量二次曲线重排）更顺滑但两端插值算法难像素级 1:1、单测脆弱、收益低（签名体验主要受手指精度/采样率影响）二期候选（记录 anti_goals）
C记录原始点集由宿主渲染把渲染与坐标责任外抛=宿主无法「截组件即出图」、契约分散淘汰

P3 API 与状态（受控/事件/命令式）

选项方案后果结论
A无受控文本值（签名=异步笔迹流非表单值）+ onInkChange(Boolean hasInk) 回调 + clear() 命令式重签 + disabled 整板灰 + strokeWidth/strokeColor/height/placeholder 参数签名板无需宿主回写任何「值」（宿主只在提交时截组件图）；hasInk 驱动「提交」钮可用态=唯一必要事件；命令式 clear 对齐全库命令式件（NavBar/FixedNav）先例A 推荐 ✅
B组件内置「图形对象导出」API（返回 UIImage/Bitmap/路径对象）UIImage vs Bitmap 类型跨端无法统一=契约断裂；截组件渲染（宿主侧）天然跨端同构=导出本就该宿主自理淘汰（宿主截组件渲染为导出惯例，spec 注明）
C内置清除钮（板内右上小按钮=仿 Input 清除钮先例）签名板宿主流程常带「重签」按钮（位于表单提交区），板内小钮与表单按钮重复且破坏签名板简洁白底视觉淘汰（clear() 命令式由宿主钮驱动）

P4 一期裁剪与 Demo 四段

选项方案后果结论
A一期=height+placeholder+strokeWidth+strokeColor+disabled+onInkChange+clear() 命令式+demo 四段：D1 基础签名与重签（水印空态→绘制跟手→onInkChange 回显「未签名/已签名」→「重新签名」宿主 clear()）｜D2 导出收编（「生成签名图」=宿主截取组件渲染=段内缩略展示=证明宿主可拿矢量签名图）｜D3 参数变体（strokeWidth 1/2/4 与 strokeColor 变体三块板 1:1 对比=宿主可调深浅粗细）｜D4 禁用锁定与空笔迹提交流（「提交锁定」disabled=true 整板 40% 灰不可绘；空板点提交=宿主以 onInkChange(false) 禁用并提示「请先签名」）采集+事件+命令式+禁用+宿主导出承接+参数变体关键边界全覆盖；业务导出/上传=宿主边界清晰A 推荐 ✅
B一期内置笔画撤销/重做栈 / 压感 / 水印多行文案参数撤销栈=编辑器职责（宿主重签已覆盖）；压感=双端实现与契约复杂化；水印一行足够=增量膨胀二期候选/不混入（anti_goals）
C一期内置签名图上传/保存与失败态上传/留痕=业务安全职责且差异大=宿主自理淘汰（宿主自理）

06 · API 契约（供门禁 B api.json 立项登记）

#字段/参数类型必填说明
1onInkChange回调是(Boolean hasInk)：首笔落下=true（水印随之消失）；clear() 清空=false；disabled 期间无回调=驱动宿主「提交」钮可用态
2clear()命令式—宿主「重新签名」钮调用=清空全部笔画并回 onInkChange(false)；禁用态下调用忽略
3height数值否画板高，默认 96=2×48 表单交互行基准（注释锚定）；宽=宿主填充
4placeholderString?否空态水印文案，默认「请在此区域签名」textSecondary 30% 居中；nil/空=无水印
5strokeWidth数值否笔画线宽，默认 2（圆头线帽）
6strokeColor颜色否笔画颜色，默认 textPrimary
7disabledBoolean否整板 40% 灰、不可绘制、clear() 忽略、无任何回调（签署提交后锁定）
8导出 / 撤销栈 / 压感——签名图导出=宿主截取组件渲染（跨端同构）；笔画撤销/重做、压感、水印多行=二期（anti_goals 登记）
