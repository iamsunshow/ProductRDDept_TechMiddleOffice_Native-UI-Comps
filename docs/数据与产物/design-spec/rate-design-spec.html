Rate 评分 · 设计规格

组件 ID：ui.rate 数据录入区 #37 subcategory=form 全新立项（双端从零，无近似收编） 设计稿 2026-09-06 门禁 A

01 · SCQA 组件定位与边界

适用场景（S）

「按程度给个整数评价」的录入与展示：① 服务/商品/订单评价=下单后打分（商家服务、物流、售后的星级）；② 满意度调研=选项做成 1–5 星点击（比单选文本档更省空间、直觉）；③ 详情页只读展示既有评分=彩色星排不可点（readonly）；④ 十分制/其它自定义刻度=count 可配。宿主自带 label 文案与提交，组件只出「n 颗星点」内容行。

目标与冲突（C）

需求=「点星/滑星定整数分」的直觉且可再次取消；冲突=离散 RadioGroup #35 带长文本适合少量枚举互斥、Range #36 是连续数值区间（评分非区间）、Switch #41 只是二元；双端系统控件（Android RatingBar 视觉脱离库内设计语言、iOS 无系统评分控件）不可直接入库；字符 ★ 在 iOS/Android 字形渲染不一致（Android 默认字体缺实心★字形会 fallback）不能双端 1:1。

问题（Q）

库内是否新增通用「Rate 整数星级评分」内容组件？

答案（A）

定位 是。新增 ui.rate=行内 n 颗自绘星形评价点（默认 5）：值=已点亮整星数 Int（0~count，0=未评合法态），点击某颗=点亮到该颗并回调、再点当前值同一颗=清空归 0（评价可取消）；横向滑动=随手指连续点亮/收回松手定值（拖选语义，超左端熄灭、超右端全亮）；半受控 value + count + readonly（只读彩色）+ disabled（灰 40%）+ onChange；星形双端自绘五角星 path（不用字符、不依赖字体）；无 label/文案/提交=宿主自理。

五态适配

默认态 ✅ 点亮星=primary 填充、未点亮=textSecondary 30% 灰（空心同色描边视觉），value=0 时全灰（未评合法）；拖动态 ✅ 点击/滑动随手指实时点亮，松手回调定值（星本身无按压缩放、无涟漪，命中行=整行 40）；只读态 ✅ readonly=点亮星保持 primary 彩色展示、不可交互无回调（详情展示评分场景）；禁用态 ✅ disabled=整行 40% 灰（点亮星灰填、未点亮更浅灰）、不可交互无回调（与 readonly 并存时 disabled 压过=灰）；边缘态 ✅ value=0 合法（无评价=未评）、value=count 全亮合法；外部改 value 超界（<0 或 >count）=clamp 回显不触发 onChange；加载/失败 N/A（无内部异步态）。

划界与依赖

依赖=DesignTokens（AppColor/AppSpace）。与同区组件划界：RadioGroup #35=文本选项离散互斥一选一（Rate=无文本程度刻度、可清零可滑选）；Menu #31 / Picker #33=下拉选填大选项集；Range #36=双钮连续数值区间（Rate=整数离散等级点非区间）；Switch #41=二元开/关（Rate=0~n 多级评分）；InputNumber #30=步进改数值带数字回显（Rate=纯星级点选无数字编辑）。业务方（订单/服务评价、满意度调研、详情只读评分展示）复用本组件，宿主自理 label/分值文案/提交动作；与记账业务既有「月记账趋势」等图表星标无关（无星级前身件=纯从零）。

03 · 关键决策（P1–P4 投票表）

P1 组件形态与星形实现

选项方案后果结论
A整星行评价点（默认 5 颗）+ 双端自绘五角星 path：点亮 primary 填充、未点亮 textSecondary30% 描边空心；点击/滑动选整颗、可清零双端 1:1 字形可控、视觉贴合库内设计语言、无字体依赖；实现=五角星 path 复用一算法两端生成A 推荐 ✅
B字符星「★/☆」渲染点亮/未点亮iOS SF 与 Android 默认字体 ★ 字形不一致（部分字体缺失实心★ fallback 变形）=双端无法保证 1:1淘汰
C系统 RatingBar（Android）+ 自定义（iOS）不对齐Android 系统星级样式/间距脱离库内设计语言，双端体验分裂淘汰

P2 数值模型（值类型与刻度）

选项方案后果结论
AInt 0~count 整星计数：value=已点亮颗数，0=未评合法态；count 可配（默认 5，>0）评价=整数档最直觉；0 未评=宿主表单语义保留；十分制等用 count=10 即可A 推荐 ✅
BDouble 0.5 步长半星（allowHalf）半星展示/命中=需单独半星 path 与滑到半星逻辑=一期膨胀二期候选（allowHalf）
C固定 5 星不许配 count十分制/自定义刻度场景（招聘技能、问卷 1–10）无法表达淘汰

P3 状态与事件（半受控/回调/只读/禁用/可取消）

选项方案后果结论
A半受控：value Int? 可选（nil=内部自持初始 0）；外部赋值（含 clamp 后）仅同步回显不触发 onChange；点/滑选 k=onChange(k) 宿主回写、点当前值同一颗=onChange(0) 清空可取消；readonly=只读彩色不可交互无回调；disabled=整行 40% 灰不可交互无回调（与 readonly 并存 disabled 压过）与 #25/#35/#36 半受控惯例一致；录入（可清零）+ 展示（只读）双场景通吃A 推荐 ✅
B纯受控必传 value宿主须自管初始与每次事件=API 繁重；详情只读展示也强制绑值淘汰
