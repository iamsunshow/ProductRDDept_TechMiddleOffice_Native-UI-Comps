ShortcutBar 快捷栏 · 设计规格（导航辅助组件 · 任务清单 #82 · 收编缺口补独立立项 · 门禁 A）

组件 ID：ui.shortcut-bar ｜ 定位：页面中部横向等分入口栏——一行等宽入口按钮组（图标 + 文字标签），点击回传 onTap(index)；横滑滚动超长列表 + 列数自动适配容器宽；对标 iOS UICollectionView 横向滚轮 / Material NavigationBar 入口 / NutUI React ShortcutBar 收敛为库内自有设计语言（图标 28 圆角 + 文字 12 + 行高 80 + 横向滚动）。
组件库版本 设计阶段锁定基线 = v1.0.8（2026-09-15，未过 C2/D 不升版）
业务回填 KeepAccounts 记账 LedgerShortcutBar 双端均缺（KeepAccounts 评估文档 §5 行 70，2026-09-16 真实状态核对）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 记账 App 首页中部入口栏（记一笔/账本/报表/预算 等 4-6 个等分入口）；② 内容详情页顶部快捷操作（编辑/分享/删除 等）；③ 钱包/银行类 App 首页服务矩阵；④ 横滑长列表场景（>5 个入口时启用横滑）
不适用（N/A）① 底部一级页面导航 → Tabbar（ui.tabbar，#19）；② 页面内顶部内容切换（页签+内容区）→ Tabs（ui.tabs，#20）；③ 顶部单行头部导航 → NavBar（ui.nav-bar，#17）；④ 多宫格固定布局（不滚动固定等分）→ Grid（ui.grid，#8）；⑤ 左侧目录导航轨 → SideBar（ui.side-bar，#18）；⑥ 悬浮面板/悬浮钮 → FixedNav/HoverButton；⑦ 一级页分类导航（带选中态+滑动指示）→ Tabs + Segmented #74 组合
五态适配默认态=白底（bgCard）+ 主色图标（primary）+ 主文字标签；激活/按压=点击瞬态按压反馈（iOS 灰底 vs Android ripple）；禁用=整项 alpha 0.4 + 不可点；加载/成功/失败 N/A（入口非数据态）
与现有组件关系deps=[DesignTokens]；收编现状=Android 无独立 ShortcutBar（业务在 DiscoverHomeScreen 自建私有 Row/Column 拼装）；iOS 无独立 ShortcutBar（业务 MoreViewController 用 Grid + 自定义入口组合），本规格将业务横滑入口栏模式提升为库内统一独立组件（与 Grid #8 划界=Grid 固定多列宫格无滚动，ShortcutBar 滚动超长列表等列宽 + 横滑）；与 Grid 协作非替代

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
内容行高80pt/80dp（含 padding 上下 12 + 图标 28 + gap 4 + 文字 16 + padding 上下 12 ≈ 80）对齐 Material NavigationBar 80 / iOS 横向滚轮 80；与 Grid 行高 72 划界（Grid 单格 72 vs ShortcutBar 整行 80）；行底 hairline 表内放行（iOS 1/scale pt vs Android 0.5dp）
入口宽最小 64pt/64dp，最大占满父宽/n 等分，> 容器宽则横滑等分优先（≤6 项时父宽/n，每项≥64），超长时横滑（≥7 项启用横向滚动，单项固定 64）
图标容器28×28 圆角 6 + bgPrimaryMuted（=DCFCE7 浅绿底）+ icon primary 主色 18 自绘与 Grid #8 图标容器 26pt 划界（Grid 26 vs ShortcutBar 28=图标稍大因行高更宽）；与 AppIcon 复用图标路径（glyph 14 textSecondary 85% 圆 0.44/0.26+斜柄线宽 0.15 双端同坐标）但 primary 染色
文字标签sizeXs=12 Regular textPrimary、单行省略、居中与 Grid #8 文字 sizeXs=12 同字号；长文案单行省略（尾部 ...）双端一致
背景/分隔白底 bgCard；行底 hairline；行内 gap=12（iOS 8pt vs Android 8dp 注释锚定）白底与 Grid 一致；hairline 双端差异表内放行
与 Grid 划界ShortcutBar=横向滚动入口栏，>6 项自动横滑；Grid=多列固定宫格Grid 用于发现页宫格/工具面板（≤12 项固定排列）；ShortcutBar 用于首页快捷入口（>6 项横滑）；Grid 已有 title 分组/卡片壳，ShortcutBar 一期无 title（仅入口按钮组）

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 组件定位：ACE 三选

选项后果评估
A：横向滚动入口栏（一期独立组件）——等列宽图标+文字、≤6 项等分、>6 项横滑、点击回调 onTap(index)、数据驱动 ShortcutItem{icon, label, disabled?}✅ 与业务现状（记账 LedgerShortcutBar 等）1:1 收敛；双端统一独立组件，UIKit UICollectionView horizontal / Compose LazyRow 同构；不依赖 Grid 内部改滚动推荐 A：业务收敛独立
B：复用 Grid #8 + 内部加滚动模式Grid 现状=固定多列宫格+title 分组（业务发现页），加滚动=职责扩张；Grid 的卡片壳+title+onSelect 与 ShortcutBar 无 title+纯入口语义不一致，混入后双 API 难选淘汰：职责分裂
C：children 插槽（宿主自组 Row/Column 自定义）组件退化为无语义壳（仅"滚动容器"），业务必须自管间距/对齐/热区；双端契约松散淘汰：登记二期（仅通用滚动容器另行立项）

P2 · 数据/API 模型：ACE 三选

选项后果评估
A：声明式数据驱动——ShortcutBar(items: [ShortcutItem])，ShortcutItem{icon: AppIconName, label: String, disabled: Bool?=false}；onTap(index: Int) 回调✅ 与 NavBar #17 / Grid #8 数据驱动 API 同构；图标走 AppIconName（库内已落地枚举）避免业务自管 SF Symbol/Material Icon 字符串；label 文案 host 自由传推荐 A：与库内 API 同构
B：children 插槽（iOS UIView 子视图 / Android content slot）自由度大但失去组件语义（每个 item 由 host 自绘图标 + 文字 + 间距对齐），与 NavBar 一期 children 淘汰同理淘汰：children 插槽通用化
C：混合（children + 自带 API）API 复杂度高、双端契约难对齐；少数场景才需淘汰：过度设计

P3 · 横滑 vs 固定：ACE 三选

选项后果评估
A：智能切换——items ≤ 6 时等分父宽；> 6 时启用横向滚动（iOS UICollectionView horizontal + Compose LazyRow），单项固定 64✅ 与业务现状（记账首页 4-6 项 + 工具面板 8-12 项）1:1；无需宿主判断传 mode 参数；视觉连续（无缝）推荐 A：智能模式
B：永远横滑（不分模式）≤6 项时也横滑会留空=视觉不平衡；用户体验不佳淘汰
C：永远等分（>6 项截断或折行）>12 项时折行视觉破碎；用户体验差淘汰

P4 · 一期范围：ACE 三选

选项后果评估
A：一期=数据驱动入口栏（items+onTap）+ 智能横滑 + disabled + 行高 80 + Demo 四段（D1 基础 4 项/D2 等分 6 项/D3 横滑 8 项+末项禁用/D4 受控 disabled 切换）✅ 覆盖业务记账 LedgerShortcutBar 现状；双端 1:1 收敛；验收可达推荐 A：一期收敛
B：一期+二期候选（自定义图标容器/角标 badge/拖拽排序/滑动指示器）超出 LedgerShortcutBar 业务范围；二期候选足够淘汰：登记二期
C：一期=空壳+业务全自管无组件价值淘汰
