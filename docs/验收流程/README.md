# TMO 组件库 · 验收流程（acceptance）

> 定位：**组件开发与验收的总入口**。做任何一个组件，从这里开始。
> 本文件夹收拢「验收流程」全部文档，与 `docs/` 下其他数据/规范文件隔离，避免混淆。

---

## 一、本文件夹文件价值

| 文件 | 作用 | 什么时候看 |
|------|------|-----------|
| `验收标准.md` | **验收标准**：五阶段 + 门禁 A/B/C1/C2/D 的完整定义（设计先行 / API 先 check / 测试门禁 / CR / 自研率） | 开始组件前必读 |
| `flow.html` | **验收流程图**（H5，浏览器打开）：依赖优先 / 暂未使用跳过 / 四阶段产物 / 门禁位置 | 对流程有疑问时 |
| `验收模板.md` | **验收文档模板**：每组件复制为 `component-acceptance-<组件名>.md`（四要素：设计细节/设计测试/API细节/API测试） | 进入阶段 1 时 |
| `评审清单.md` | **评审意见单**：设计/API 验收打勾模板，评审时复制填写留档 | 门禁 A/B 评审时 |
| `component-acceptance-<组件名>.md` | （未来产物）每组件一份验收文档 | 阶段 1-5 逐步填写 |
| `usage-<组件名>.md` | （未来产物）门禁 D 业务接入记录（替换位置/代码量变化） | 发版后 |

## 二、验收流程一页

```
读取组件列表（docs/组件进度.md，按顺序）
  → 🔗 依赖优先：deps 未完成则等待
  → ❓ 用得到？否 → ⏭【暂未使用】跳过（季度复查）
  → 阶段1 设计（①设计细节 + ②设计测试用例）──门禁 A──
  → 阶段2 API（③API 细节 + ④API 测试用例）──门禁 B──
  → 阶段3 双端实现（用例即代码：D*/A* ↔ 测试函数）
  → 门禁 C1 自测（单测 + 快照 + 用例映射）→ 阶段4 CR → 门禁 C2（CR+CI）
  → 阶段5 发版 + 业务真实接入 → 门禁 D → 验收完成 → 更新进度
```

- 完整版见 `flow.html`，细节见 `验收标准.md`。
- **用不到的组件**：在 `组件进度.md` 标 `⏭【暂未使用】` + 备注原因，直接跳过。

## 三、docs/ 根目录其他文件价值（防止混淆）

`docs/` 下除本文件夹外的文件分四类：

**① 数据源（机器/文档共同消费，改这里 = 改全局）**

| 文件 | 作用 |
|------|------|
| `api.json` | 组件 API 契约**单一数据源**（props/events/平台状态/deps），`www` 文档站与测试共用 |
| `design-token.json` | 设计 token **唯一样式数据源**（颜色/字号/圆角/间距），禁止硬编码 |
| `ui-version.json` | 全局唯一版本号（双端发版都以它为准） |

**② 规范/规则（怎么做事，已合并为 3 份）**

| 文件 | 作用 |
|------|------|
| `开发规则.md` | **开发规则**（原 rules + api-contract + schema 三合一）：命名/打包/业务库约束 + API 契约 C1-C16 + api.json 字段规范 ★沟通入口 |
| `设计规范.md` | **设计规范**（原 design-spec + token README 二合一）：Token 铁律、结构语义、双端生成 |
| `治理规范.md` | **治理规范**（原 governance + versioning + containment 三合一）：架构/收纳/版本/发版 |
| `组件分类.md` | 组件分类**唯一文档**：95 个组件分类表 + 完整度指标基准 |
| `平台差异.md` | 双端平台差异白名单（`设计规范.md` 第四节引用） |

**③ 执行进度（现在做到哪了）**

| 文件 | 作用 |
|------|------|
| `组件进度.md` | 组件完善**任务清单 + 达成情况**，验收流程按它推进 ★其他 Agent 接续必读 |

**④ 生成物/资产（不要手工改）**

| 文件 | 作用 |
|------|------|
| `组件审计.md` | 双端 API 一致性审计报告（脚本生成） |
| `design-spec/`（H5 页） | 各组件设计规格 H5 页（如 cell-design-spec.html，门禁 A 的输入资产） |
| `embeddings/`（json） | 向量检索索引数据（组件语义查询，后期功能） |

## 四、阅读路径建议

| 场景 | 先看 |
|------|------|
| 开始验收一个组件 | 本 README → `验收标准.md` → `组件进度.md` 选组件 |

| 写组件验收文档 | `验收模板.md` 复制 |
| 看整体流程 | `flow.html`（浏览器打开） |
| 想改数据/契约 | `api.json`（字段规范见 `开发规则.md` 第七节） |
| 查进度/接续工作 | `组件进度.md` |
