ProgressCircle 进度环 · 设计规格（信息展示组件 · 任务清单 #83 · 收编缺口补独立立项 · 门禁 A）

组件 ID：ui.progress-circle ｜ 定位：环形进度条——展示 0~1 比例的圆形进度环，可选中心文案（默认百分比）+ 可选颜色（primary/warning/error 三态）；对标 iOS CAShapeLayer 圆环 + Material CircularProgressIndicator 收敛为库内自有设计语言（轨道 6pt + 圆头线帽 + 默认 64×64 + 中心文案 sizeMd Semibold）。
组件库版本 设计阶段锁定基线 = v2.0.8（2026-09-15，未过 C2/D 不升版）
业务回填 KeepAccounts 记账 BudgetRing 双端均缺（KeepAccounts 评估文档 §5 行 71，2026-09-16 真实状态核对）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 预算消耗进度环（记账 BudgetRing 等）；② 任务完成度展示；③ 健康步数/活动环（Apple Watch 风格）；④ 加载进度（替代 LinearProgress 圆形变体）；⑤ 数据加载/百分比统计
不适用（N/A）① 横向进度条 → Progress（ui.progress，#74）；② 倒计时 → CountDown（ui.count-down，#60）；③ 数字动画（金额滚到目标值）→ AnimatingNumbers（ui.animating-numbers，#61）；④ 骨架屏 → Skeleton（ui.skeleton，#53）；⑤ 时间戳 → Countdown（ui.countdown，#60）；⑥ 数值格式化（静态排版）→ Price（ui.price，#72）；⑦ 输入数字步进 → InputNumber（ui.input-number，#44）
五态适配默认态=轨道 border 灰底 + 进度 primary 主色填充；颜色三态=primary（正常）/warning（≥80% 警告阈值）/error（≥100% 超额阈值）；加载=可选 indeterminate 模式（持续旋转）；成功/失败 N/A（由宿主语义判断）
与现有组件关系deps=[DesignTokens]；收编现状=Android 无独立 ProgressCircle（业务 BudgetRing 自建 Canvas drawArc）；iOS 无独立 ProgressCircle（业务同样自绘 CAShapeLayer），本规格将业务圆形进度模式提升为库内统一独立组件；与 Progress #74（横条）划界严格（一个圆一个横）；与 AnimatingNumbers #61 划界（一个画环一个滚数字）

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
默认尺寸64×64（可覆盖 32/48/64/96/128）对齐 Apple Watch 活动环 64 / Material CircularProgressIndicator 48/64；宿主可传 size 参数覆盖默认 64
轨道宽6pt/6dp（随 size 比例 = size × 0.094）轨道 strokeWidth=6（size=64 时），size 变时按比例缩放（size=32 → 3 / size=96 → 9）；线帽圆头 stroke-linecap=round
轨道颜色border=E5E7EB 灰底（铺满 360°）未填充部分统一灰底，无动态透明度变化
进度颜色primary=16A34A（默认）+ warning=F59E0B（≥80% 阈值）+ error=DC2626（≥100% 阈值）阈值可由宿主传 warnThreshold=0.8 / dangerThreshold=1.0 覆盖；色彩按 progress 自动切换
中心文案sizeMd=16 Semibold textPrimary、百分比形式（默认）+ 0~100 整数默认显示「progress.toInt()%」；宿主可传 centerText 覆盖（如「今日 ¥128」/「3/10」/「步数 8000」）；centerText 为空时只显示百分比；centerText=null 时无文字只画环
动画进度变化 0.3s ease-out 过渡（iOS CAShapeLayer strokeEnd animation + Android animateFloatAsState）progress 变化时平滑过渡；indeterminate 模式 1.2s/圈线性旋转（可选）
与 Progress 横条划界ProgressCircle=圆环；Progress=横条数据模型同（progress 0~1）+ API 不同（一个圆环一个横条）；可共存

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 组件定位：ACE 三选

选项后果评估
A：纯展示型进度环（独立组件）——value 0~1 + 可选 size + 可选 centerText + 可选 warn/danger 阈值 + 可选 indeterminate✅ 与业务现状（记账 BudgetRing）1:1 收敛；双端统一独立组件（CAShapeLayer / Compose Canvas drawArc 同构）；无 children 复杂度；明确划界 Progress #74 横条推荐 A：业务收敛独立
B：复用 Progress #74 + 加圆形变体Progress 横条职责扩张；横条与圆环视觉差异大（一个矩形轨迹一个圆形轨迹），API 难统一（横条用 width 进度圆环用 strokeEnd）淘汰：职责分裂
C：children 插槽（宿主自组环形 + 文字）组件退化为"画圆工具"，业务必须自管轨道颜色/进度颜色/中心文案/阈值；双端契约松散淘汰：登记二期

P2 · 数据/API 模型：ACE 三选

选项后果评估
A：声明式数据驱动——ProgressCircle(value: Float, size: CGFloat = 64, centerText: String? = nil, warnThreshold: Float = 0.8, dangerThreshold: Float = 1.0, indeterminate: Bool = false)；value 0~1 必传✅ 与 Progress #74 数据驱动 API 同构；value 0~1 直白简单；阈值+size+文案 全部具名化；indeterminate 二期候选一期先不实现推荐 A：与库内 API 同构
B：children 插槽（iOS UIView 子视图 / Android content slot）自由度大但失去组件语义（业务必须自管轨道颜色/进度颜色/中心文案/阈值），与 Progress #74 children 淘汰同理淘汰：children 插槽通用化
C：混合（value + children）API 复杂度高、双端契约难对齐淘汰：过度设计

P3 · 颜色策略：ACE 三选

选项后果评估
A：自动阈值切换——value < warnThreshold 显示 primary；warnThreshold ≤ value < dangerThreshold 显示 warning；value ≥ dangerThreshold 显示 error✅ 与业务预算场景 1:1（80% 警告/100% 超额）；宿主可传阈值覆盖；视觉清晰推荐 A：自动阈值
B：永远 primary（不切换）≥100% 超额仍显示绿色=视觉误导；用户体验差淘汰
C：宿主传 color 完全控制失去组件语义（每个宿主必须自管阈值判断），与业务现状不匹配淘汰

P4 · 一期范围：ACE 三选

选项后果评估
A：一期=value+size+centerText+阈值三态颜色+Demo 四段（D1 基础 30%/D2 进度变化 0.3s 过渡/D3 阈值切换 60%/85%/110%/D4 中心文案自定义「今日 ¥128」）✅ 覆盖业务记账 BudgetRing 现状；双端 1:1 收敛；验收可达推荐 A：一期收敛
B：一期+indeterminate 持续旋转超出 BudgetRing 业务范围；登记二期淘汰：登记二期
C：一期=空壳+业务全自管无组件价值淘汰
