ShortPassword 短密码 · 设计规格

组件 ID：ui.short-password 数据录入区 #39 subcategory=form 全新立项（掩码基座沿用 Input #29 secure 惯例，定长/满位提交为增量） 设计稿 2026-09-06 门禁 A

01 · SCQA 组件定位与边界

适用场景（S）

「定长数字短密码/PIN」的安全输入：① 支付/交易/提现二次确认=6 位短密码掩码输入、满位即提交宿主校验；② 二次验证 PIN=应用锁/隐私区 4 位；③ 安全码/邀请码等 4~8 位定长码=掩码不暴露明文；④ 与库内 NumberKeyboard #32 组合=宿主底部弹层承载位点序列+数字键盘点输（弹层/键盘=宿主组装）。组件只出「掩码位点输入行」，真实校验、错误提示、重试流、提交按钮状态、安全存储=宿主自理。

目标与冲突（C）

需求=「支付级短密码输入=定长、纯数字、掩码、满位即用」的直觉组件；冲突=Input #29 secure 是通用任意长字符串密文输入（无定长、无满位回调、灰底壳+清除钮+trailing 表单语境），直接复用做短密码不表达「满 N 位即完成」的支付码交互；验证码分格 OTP（每格一框自动跳格）是短信验证码/码类形态，与「短密码/PIN」语义不同、易与码组件混编；Android sharedui 既有 PasswordInputField=带明文显隐切换的通用长密码=业务组件库惯例件（收编不动，且其显隐不符合安全默认）。

问题（Q）

库内是否新增定长数字掩码短密码输入组件 ui.short-password（在 Input #29 secure 基座惯例上独立立项）？

答案（A）

定位 是。新增 ui.short-password=短密码输入：内容行=水平居中大字号掩码圆点序列（无灰底壳、无清除钮、无明文显隐切换），每输入一位密文点递增；输入=纯数字（键盘与粘贴均滤除非数字）；length 定长（默认 6）字符满=自动回调 onComplete(明文字符串) 一次、满后继续输入拒收；半受控 value String?（nil=内部自持、外部赋值=回显不触发回调）+ onChange 每字符直通 + disabled 40% 灰 + placeholder（空态居中灰字）；真实校验/错误提示/重试=宿主自理（校验失败宿主外部 value="" 清空重输）；分格 OTP/明文切换=码类与二期候选不混入。

五态适配

默认态 ✅ 空值=placeholder「请输入 N 位数字密码」居中灰字提示；输入中态 ✅ 键入一位=该位即显密文圆点（系统掩码随字号）、已输位数递增可见、onChange 每字符直通、非数字键（含粘贴）一律不进入；完成态 ✅ 字符数满 length=自动触发一次 onComplete(明文字符串)、满后追加输入被拒；禁用态 ✅ disabled=整行 40% 灰、不可输入、无任何回调（同 Input #29 惯例）；边缘态 ✅ 外部赋值满位=仅回显不触发 onComplete（仅输入路径触发，同半受控惯例）、粘贴「ab3#9x」=仅取数字按位截断并入；加载/失败 N/A（校验 loading/错误文案=宿主自理，组件无内部异步态）。

划界与依赖

依赖=DesignTokens（AppColor/AppSpace/字号）+ 已收编 Input #29 secure 的掩码输入实现惯例作基座（复用不复制：ShortPassword 不是 Input 参数扩展，是定长/满位提交的独立支付码语境组件）。与同区组件划界：Input #29=通用单行文本输入（secure=true 时=任意长任意字符密文、灰底壳+清除钮+trailing、无满位回调=表单行）；NumberKeyboard #32=数字键盘宿主组合件（短密码可嵌 NumberKeyboard 数字面板=宿主组装）；短信验证码分格 OTP=码类输入二期或另行组件（自动跳格形态与短密码区分登记）；SearchBar #38 / textarea #42=明文输入语境。业务方（支付密码、交易确认、安全码、二次验证 PIN 等）复用本组件，宿主自理：真实校验、错误提示与重试流、提交/按钮状态、安全存储、弹层与键盘组合布局。

03 · 关键决策（P1–P4 投票表）

P1 组件形态与视觉基座

选项方案后果结论
A无壳水平居中掩码圆点行（系统密文点随字号 22）=干净支付码直觉；数字限定+定长+满位提交为组件语义与 Input #29 secure（灰底壳表单语境长密码）视觉/交互显著区分=独立组件价值清晰；两端实现一致A 推荐 ✅
B复用 Input #29 灰底 radius lg 壳行样式做定长密码与 Input secure 视觉几乎重叠=组件近似 Input 参数扩展、无独立立项价值淘汰
C验证码分格 OTP 形态（每格一方框、自动跳格）短信验证码/码类交互=与「短密码/PIN」语义不符（分格显位数提示跳格=码语境），且会与未来码组件混编码类二期候选（另行组件登记 anti_goals）

P2 满位提交模型

选项方案后果结论
A字符满 length=自动 onComplete(明文字符串) 一次；满后继续输入拒收；宿主校验失败=外部 value="" 清空重输「满 N 位即提」=支付码标准交互、宿主无需监听位数即可接校验；定长语义自然（无溢出追加问题）A 推荐 ✅
B满位不自动回调，宿主自行监听 onChange 位数（或内置「确定」钮）numberPad 键盘无确定键=内置钮无处放且破坏掩码干净视觉；宿主每键算位数=语义倒置淘汰
C满位回调后仍允许继续输入（仅设上限）定长密码不允许溢位=与「N 位即满」定义矛盾淘汰

P3 状态与事件（受控/回调/禁用）

选项方案后果结论
A半受控 value String?（nil=内部自持输入、外部赋值=仅回显不触发 onChange/onComplete）；onChange 每字符直通；disabled=40% 灰无回调；非数字/超长仅截断输入路径支付宿主「满位接校验、失败外部清空重输」无需每一步回写=半受控顺手（与 #25/#35/#36 半受控惯例一致）A 推荐 ✅
B受控 value 必传 + onChange 直通（同 Input #29）支付输入每键强制宿主回写=掩码输入场景回写负担/抖动风险高于普通文本淘汰（Input 才用必传受控）
C纯非受控只读回调（无 value 外部驱动）宿主「校验失败清空重输/预填回显」等回显场景无法驱动淘汰

P4 一期裁剪与 Demo 四段

选项方案后果结论
A一期=length（默认 6）+value+onChange+onComplete+disabled+placeholder+demo 四段：D1 基础 6 位输入（掩码点随键入渐显+onChange 回显+满 6 自动 onComplete+「清空」外部 value=""）｜D2 定长 length=4+受控外部驱动（外部预填 4 位=回显满位不触发 onComplete 证仅输入路径触发+清空重输）｜D3 禁用与粘贴过滤（disabled 40% 灰不可输入无回调+粘贴「ab3#9x」仅取数字按位截断）｜D4 与 NumberKeyboard #32 组装+宿主校验流程（正确码=123456：满位校验通过/错误=提示并外部清空重输演示）定长掩码输入+满位提交+半受控+禁用+数字过滤+键盘组装关键边界全覆盖；校验/错误=宿主边界清晰A 推荐 ✅

06 · API 契约（供门禁 B api.json 立项登记）

#字段/参数类型必填说明
1valueString?否半受控：nil=内部自持输入（宿主可不回写，onChange 实时拿词）；外部赋值=仅回显不触发 onChange/onComplete（校验失败清空重输=外部 value="" 即可）
2onChange回调是(String)：每字符实时直通（含外部清空触发仅当输入路径）；disabled 无回调
3onComplete回调否(String)：字符满 length 自动触发一次（仅键盘输入路径触发）；宿主接走真实校验；disabled 无回调
4lengthInt否定长位数，默认 6（建议宿主传 4~8 支付/二次验证常规区间，实现接受 ≥2）
5placeholderString否空态提示，默认「请输入 N 位数字密码」；textSecondary sizeXl 22 居中
6disabledBoolean否整行 40% 灰、不可输入、无任何回调
7visibleToggle / OTP——明文显隐切换=一期不做（安全默认）；分格 OTP 逐格=码类二期（anti_goals 登记）
