MoneyFormat 金额格式化

组件 ID：foundation.money-format ｜ 任务清单 #95 ｜ 底层能力 foundation ｜ TMO 组件库 v1.4.0

定位：统一对外展示的金额格式（两位小数 + 可选人民币符号 + 可选收支正负号），是记账类业务唯一的金额展示出口。

1. 场景与边界（SCQA）

Situation

账单列表、明细页、图表轴标签、预算卡等所有展示金额的位置，都必须保持同一格式（两位小数、无千分位、千分位由业务决定不做）。

Complication

双端各自用 String.format("%.2f") / NumberFormatter 拼装，易出现「有的地方 38.5 有的地方 38.50」「iOS 有千分位 Android 没有」「四舍五入策略不一致」等展示漂移。

Question

需要一个纯函数式的金额格式化工具，双端输出逐字符一致，且不承载业务语义（收入/支出由调用方映射）。

Answer

MoneyFormat——三个静态方法：string（两位小数）/ currency（人民币符号 + 两位小数）/ signed（按收支方向加正负号）；无状态、无 UI、无业务语义。

2. 组件边界与划界

组件职责与 MoneyFormat 划界
DateFormatters（同文件）日期展示格式化DateFormatters=日期（MM月dd日 等），MoneyFormat=金额；同属 formatter 家族但互不调用
InputNumber #30数字输入控件InputNumber=可编辑的数值输入（有 UI、有回调），MoneyFormat=只读展示格式化（纯函数）
Price #72价格展示组件Price=带样式的价格文本控件（字号/颜色/符号位置），MoneyFormat=无样式的字符串工具；Price 内部可选用 MoneyFormat 生成主体字符串
业务金额计算加减/汇总/汇率MoneyFormat 只格式化已算好的 Double，不做任何计算与单位换算

4. 设计规格

项规格Token / 依据
小数位数固定 2 位（不足补零，超出四舍五入）全局规范：对外展示金额一律两位小数
千分位不分组（无 ,）对齐现有双端实现（iOS groupingSeparator=""）
货币符号固定 ¥，前缀拼接CNY 单一币种（多币种=二期）
正负号由 isIncome 映射，业务无关收入 + / 支出 -
负数string(-1118) → "-1118.00"（负号由数值自带，signed 不再叠加）边界：调用方传负值时以数值符号为准
样式无（不设置字号/颜色）样式由消费方（Price/Text）决定

7. 平台差异表

差异点iOS（Foundation）Android（Kotlin/JVM）判据
格式化实现NumberFormatter（locale en_US_POSIX，min=max=2，groupingSeparator=""）String.format(Locale.US, "%.2f", amount)表内放行（输出逐字符一致：均为两位小数、无千分位、半进位）
兜底路径NumberFormatter 失败时回退 String(format:"%.2f")无（String.format 即主路径）表内放行（仅异常兜底，正常输出一致）

差异风险登记（待 C1 单测兜住）：1.005 这类「第三位为 5」的值，iOS NumberFormatter 默认半偶舍入（1.00）而 Android String.format 半进位（1.01）。一期以「日常金额均为两位以内」为界不强制统一；C1 单测须对 0.005/1.005 双端分别断言并登记 diff-api.json。

8. 反目标

不做原因
多币种 / 汇率换算一期仅 CNY；汇率是业务计算，非展示格式化

万 / 亿 单位缩写二期；业务展示口径未定
