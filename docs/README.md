# docs/ 目录导航（每个文件/文件夹是干什么的）

> 本目录 = 组件库的「数据源 + 规范 + 进度」统一目录。
> 打开 docs/ 后先看本文件，就知道每个东西是什么、该不该碰。
> 按「角色」分五类：**① 验收流程 → ② 数据源 → ③ 规范 → ④ 执行进度 → ⑤ 设计资产**。

## ① 验收流程（开发/验收入口）→ `验收流程/`

> **做任何组件，从 `验收流程/README.md` 开始。**

| 文件 | 是什么 | 干什么用 | 何时碰 |
|------|--------|---------|--------|
| `验收流程/README.md` | 流程索引 | 本文件夹导航 + 全 docs 文件价值盘点 | 开始组件前 |
| `验收流程/验收标准.md` | 验收标准 | 五阶段 + 门禁 A/B/C1/C2/D 的完整定义 | 组件全程 |
| `验收流程/flow.html` | 验收流程图（H5） | 浏览器打开看流程全貌（依赖优先/暂未使用跳过/四要素） | 对流程有疑问时 |
| `验收流程/验收模板.md` | 验收文档模板 | 每组件复制为 `component-acceptance-<组件名>.md`（设计细节/设计测试/API细节/API测试） | 阶段 1 开始 |
| `验收流程/评审清单.md` | 评审意见单 | 门禁 A/B 打勾清单，评审时复制填写留档 | 门禁 A/B |
| `验收流程/component-acceptance-*.md` | （未来产物） | 每组件一份验收文档 | 阶段 1-5 |
| `验收流程/usage-<组件名>.md` | （未来产物） | 门禁 D 业务接入记录（替换位置/代码量变化） | 发版后 |

## ② 数据源（改这里 = 改全局，都是「唯一」的；机器读取，文件名保留英文）

| 文件 | 是什么 | 干什么用 | 谁产出 / 何时碰 |
|------|--------|---------|----------------|
| `api.json` | 组件元数据 + API 契约 **单一数据源** | 每个组件的 id/名称/作用/API（props/events）/平台状态/依赖/设计token 都在这；`www` 文档站构建时读取；门禁 B 冻结契约的对象；向量检索的语料 | AI 维护；改组件 API 时必改；`scripts/merge_contracts_into_catalog.py` 可并入契约 |
| `design-token.json` | 样式 **唯一样式数据源** | 颜色/字号/圆角/间距/行距的 token 定义，代码禁止硬编码，全部引用它（用法见 `设计规范.md`） | AI/设计师；加新视觉时改；改完重跑双端 token 生成脚本 |
| `ui-version.json` | 全局**唯一版本号** | 双端发版都以它为准（version/versionKey/releaseDate/changelog），iOS Package.swift / Android gradle / CI 都从这里读 | 发版时更新 |

## ③ 规范（怎么做事，已合并为 3 份）

| 文件 | 是什么 | 干什么用 | 何时碰 |
|------|--------|---------|--------|
| `开发规则.md` | **开发规则**（三合一：原 rules + api-contract + schema） | 命名/分类收口/特色组件打包/业务库不造轮子/API 完善路径 + api.json 字段规范 + 双端 API 契约（C1-C16 + 状态矩阵 + 铁律） | 任何组件开发前 ★沟通入口 |
| `设计规范.md` | **设计规范**（二合一：原 design-spec + token README） | Token 铁律（唯一数据源/禁硬编码）、Token 结构语义、双端自动生成、平台差异白名单、状态规范 | 写样式代码前 |
| `治理规范.md` | **治理规范**（三合一：原 governance + versioning + containment） | 仓库架构（双仓隔离/submodule）、收纳约定（代码放哪）、版本铁律（SemVer/双端同步）、发版流程、业务接入、迭代、开发指引 | 涉及业务代码/OPC 主仓/发布/不确定代码落哪时 |
| `组件分类.md` | 组件分类**唯一文档** | 95 个组件的分类表 + 完整度指标基准（当前 25.3%），验收流程的顺序来源 | 查分类 / 算完整度时 |
| `平台差异.md` | 双端平台差异白名单 | 允许的系统级原生差异登记表（`设计规范.md` 第四节引用） | 双端视觉有差异时 |

## ④ 执行进度（现在做到哪了）

| 文件 | 是什么 | 干什么用 | 何时碰 |
|------|--------|---------|--------|
| `组件进度.md` | 任务清单 + 达成情况（**唯一进度文档**） | 验收流程按它逐个推进；每个组件过一道门禁就更新一次 | ★其他 Agent 接续必读 |

## ⑤ 设计资产（H5 规格页）

| 文件/夹 | 是什么 | 干什么用 |
|---------|--------|---------|
| `design-spec/` | 设计规格 H5 页 | 每个组件的视觉设计规格页（如 `cell-design-spec.html`），门禁 A 的输入资产、样式走查对照 |
| `design-spec/index.html` | 设计规格总览页（历史快照） | 浏览器打开看历史全部组件设计参考；**不再更新**，新组件以独立 H5 规格页为准 |

> 生成物说明：`组件审计.md`（双端 API 对齐审计报告，`scripts/gen_component_audit.py` 生成）；`embeddings/`（28 个向量索引 json，`scripts/embed.py` 生成，勿手改）。

## 新手一页通（按场景找文件）

| 场景 | 看哪个 |
|------|--------|
| 开始做/验收一个组件 | `验收流程/README.md` → `验收流程/验收标准.md` |
| 想知道还有多少组件没做 | `组件进度.md` |
| 想改某个组件的 API | `api.json`（字段规范看 `开发规则.md` 第七节） |
| 想确认双端 API 对齐 | `开发规则.md` 第八节（C1-C16 + 状态矩阵） |
| 想加一种颜色/字号 | `design-token.json`（用法看 `设计规范.md`） |
| 想查组件属于哪类 / 完整度 | `组件分类.md` |
| 想知道代码该放哪 | `治理规范.md` 第三节 |
| 想看组件设计规格 | `design-spec/`（H5 页，浏览器打开） |
| 想用自然语言搜组件 | `scripts/search.py` + `embeddings/` |
| 想发版 | `ui-version.json` + `治理规范.md` 第六~七节 |
| 想接入业务、度量降本 | `验收流程/验收标准.md` 第七章 + `scripts/measure_adoption.py` |
