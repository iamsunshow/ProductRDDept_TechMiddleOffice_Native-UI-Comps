Uploader 上传 · 设计规格（数据录入组件 #43 · subcategory=form · 门禁 A）

组件 ID：ui.uploader ｜ 定位：通用文件/图片上传 UI 组件——网格展示已选文件列表（缩略图/文件名/上传状态/进度）+ 添加按钮触发宿主选择 + 删除已选文件。组件不负责真实文件选择（系统相册/相机/文件选择器由宿主调起后回写 value）和网络上传（上传请求/进度/结果由宿主驱动 status+progress 字段）；组件纯渲染 + onAdd/onRemove 交互回调。对标 NutUI uploader / Ant Design Upload 收敛为库内自有设计语言；与 Image 图片展示组件（纯展示无交互）、Avatar（头像圆形裁切）划界。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-07，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 图片/文件上传表单（头像、反馈截图、证件照、附件等）；② 多文件批量上传（网格展示 + 逐个状态/进度）；③ 编辑回显：宿主已持文件列表，外部 value 驱动展示；④ 受限上传（maxCount 上限、disabled 锁定）
不适用（N/A）① 纯图片展示画廊（无上传/删除交互）→ Image 图片组件；② 头像圆形裁切展示 → Avatar；③ 大文件分片上传/断点续传逻辑 → 宿主网络层；④ 拖拽排序、图片预览大图 → 二期；⑤ 视频上传专用播放器 → 宿主自理
五态适配默认态 ✅ 空列表=仅显示添加按钮；上传中 ✅ 缩略图蒙层 + 进度条 + "上传中"文案；成功态 ✅ 缩略图正常展示 + 右上角删除按钮；失败态 ✅ 缩略图灰蒙 + "失败"红字 + 点击重试回调宿主；禁用态 ✅ 整件 40% 灰，添加/删除均不可点无回调
与现有组件关系deps=[DesignTokens]；与 FormFieldRow #28 兼容=Uploader 作字段内容区（label/必填/校验走行）；与 Cell 内容区兼容；与 Image 图片组件划界=Uploader 含上传交互+状态机，Image 纯展示；受控 value 惯例同 Input #29（必传+回调直通）

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
网格布局每行 4 列，列间距 spaceSm(8)，行间距 spaceSm(8)4 列=移动端常见上传网格密度（同微信/支付宝上传）；间距 8=spaceSm 紧凑

删除按钮右上角 16pt/16dp 圆形半透明黑底(rgba0,0,0,.5)，白色 × 号 11pt悬浮角标=不遮挡缩略图主体；16=最小可点击视觉
上传状态蒙层上传中=primary 80% 底 + 白字"上传中" + 底部进度条 3pt；失败=error 80% 底 + 白字"失败"状态蒙层=一眼可读；进度条 3pt 细条不抢视觉
进度条高 3pt/3dp，底 rgba(255,255,255,.3)，填充 primary细条=轻量进度反馈；宽度随 progress(0-1) 线性

maxCount默认 9（九宫格）；达上限=隐藏添加按钮9=常见多图上限；可配置；单文件传 maxCount=1

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 组件形态：ACE 三选

选项后果评估
A：纯 UI 展示 + 交互回调组件——网格文件列表（缩略图/状态/进度）+ 添加按钮（onAdd 回调宿主调起选择器后回写 value）+ 删除按钮（onRemove 回调）；上传状态/进度由宿主驱动 UploadItem.status+progress 字段；组件不内置文件选择器、不内置网络上传✅ 职责单一=纯渲染+交互回调，与库内"组件不做业务"惯例一致（同 Signature 导出由宿主截取渲染）；文件选择/上传逻辑平台差异大（iOS PHPicker/Android PhotoPicker/各端文件系统），放宿主=双端同构；宿主可自由组合选择器（相册/相机/文件）推荐 A：纯 UI + 回调
B：内置文件选择器（调起系统相册/相机/文件选择器）选择器封装=开箱即用；但平台选择器 API 差异大（iOS UIImagePickerController/PHPickerViewController vs Android ActivityResultContracts.PickVisualMedia），权限处理复杂，组件库内聚平台差异=维护成本高+宿主定制空间小淘汰：选择器放宿主
C：内置网络上传逻辑（URLSession/OkHttp 请求 + 进度回调）上传全链路=一组件闭环；但上传接口/鉴权/断点续传/错误码=业务强相关，组件库不应内置网络层淘汰：上传放宿主网络层

P2 · 数据模型：ACE 三选

选项后果评估
A：UploadItem { id:String, name:String, size:Long?, thumbnailUrl:String?, localPath:String?, status:UploadStatus(.pending/.uploading/.success/.failed), progress:Float(0-1) }；value: [UploadItem] 受控必传✅ 完整状态机=pending（等待上传）/uploading（上传中+进度）/success（成功）/failed（失败可重试）；thumbnailUrl/localPath 双路=网络缩略图与本地文件均可展示；size 可选展示；progress 0-1 驱动进度条；受控必传=文件列表数据源归宿主推荐 A：完整状态机 + 受控
B：value: [String]（仅文件路径/URL），无状态/进度极简但无上传状态反馈=用户不知上传中/失败=体验缺失；上传进度无展示淘汰：状态机是上传组件核心
C：value 半受控（可选传，内部自持）文件列表=强业务数据源，必须宿主持有（上传结果/提交表单均需宿主数据），内部自持=宿主无法获取完整列表淘汰：受控必传

P3 · 交互回调：ACE 三选

选项后果评估
A：onAdd() → 宿主调起选择器后向 value 追加 UploadItem（status=.pending）；onRemove(index) → 宿主从 value 删除对应项；onRetry(index) → 失败项点击重试回调宿主重新上传（宿主更新 status→.uploading）✅ 三条交互路径全覆盖=添加/删除/重试；回调语义清晰=宿主全权管理数据源；失败项点击=重试语义（非删除，删除走角标）推荐 A：三回调全覆盖
B：仅 onAdd + onRemove，无重试失败项无法重试=用户只能删除重选=体验差淘汰：重试是上传必备
C：组件内部管理上传状态机（点击添加自动选择+上传）内部状态机=宿主无法介入上传流程=鉴权/自定义上传/错误处理无门淘汰：状态归宿主

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：一期=网格文件列表 + 添加按钮 + 删除角标 + 状态展示（pending/uploading/success/failed）+ 进度条 + maxCount + disabled + onAdd/onRemove/onRetry 三回调 + demo 四段✅ 上传核心闭环（添加/展示/状态/进度/删除/重试/上限/禁用）逐项可验；无拖拽排序/大图预览膨胀=验收路径清晰推荐 A：核心闭环可验收
B：一期含拖拽排序拖拽排序=双端手势几何对仗成本高+一期网格展示已满足主场景淘汰：登记二期
C：一期含图片预览大图（点击缩略图全屏预览）大图预览=独立浏览组件范畴（含手势缩放/左右滑动），Uploader 不应内聚浏览能力淘汰：登记二期或宿主自理

05 · 平台差异表（表内放行，表外必须双端统一）

维度iOSAndroid放行原因
网格布局UICollectionView（ UICollectionViewFlowLayout，4 列，spacing 8）Compose LazyVerticalGrid（columns=4，spacing 8）平台列表机制不同、视觉一致（表内放行）
缩略图加载UIImage(contentsOfFile:) 本地 / 三方图片库加载网络 URL（宿主可注入）Coil/Glide 加载（宿主可注入）图片加载库选型由宿主决定、组件提供 localPath/thumbnailUrl 字段（表内放行）
点击命中UIControl / UITapGestureRecognizer（添加格/删除角标/失败重试格分别命中）Modifier.clickable（各区域独立点击）两端命中一致、机制差异（表内放行）
状态回写命令式：value setter → reloadData / 刷新 items声明式：value 参数变化自动重组命令式/声明式机制不同、宿主回写后视觉一致（库内惯例，表内放行）
尺寸单位 / 命名pt；UploaderView（独立 UploaderView.swift）dp；@Composable Uploader（Uploader.kt）Token 同值不同单位；命名差异见门禁 B（表内放行）
无障碍VoiceOver：isAccessibilityElement+label（"添加图片"/"删除"/"上传中 60%"/"失败 点击重试"）TalkBack：语义/状态描述系统无障碍层各读屏实现不同（表内放行）

06 · API 草案（双端一致契约，门禁 B 据此登记 api.json）

端API
共用value: [UploadItem]（文件列表，受控必传）；onAdd: () -> Void（点击添加按钮，宿主调起选择器后向 value 追加）；onRemove: (Int) -> Void（点击删除角标，宿主从 value 删除 index 项）；onRetry: (Int) -> Void（点击失败项，宿主重置 status 重新上传）；maxCount: Int = 9（最大文件数，达上限隐藏添加按钮）；disabled: Bool = false（整件 40% 灰，添加/删除/重试均不可点无回调）
UploadItem：{ id:String, name:String, size:Long?, thumbnailUrl:String?, localPath:String?, status:UploadStatus(.pending/.uploading/.success/.failed), progress:Float(0-1) }
UploadStatus：.pending（等待上传，无蒙层）/ .uploading（上传中，primary 蒙层+进度条）/ .success（成功，无蒙层+删除角标）/ .failed（失败，error 蒙层+点击重试）
iOSfinal class UploaderView: UIView
init(value: [UploadItem] = [], maxCount: Int = 9, disabled: Bool = false, onAdd: (() -> Void)? = nil, onRemove: ((Int) -> Void)? = nil, onRetry: ((Int) -> Void)? = nil)；`var value` 外部赋值驱动刷新；`var disabled` 可运行期更新
Android@Composable fun Uploader(value: List<UploadItem>, onAdd: () -> Unit, onRemove: (Int) -> Unit, onRetry: (Int) -> Unit = {}, maxCount: Int = 9, disabled: Boolean = false, modifier)
value 参数变化自动重组；LazyVerticalGrid 渲染
