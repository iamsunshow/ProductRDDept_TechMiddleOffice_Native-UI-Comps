CalendarCard 日历卡片 · 设计规格（数据录入组件 #2 · 任务清单 #23，subcategory=form · 门禁 A）

组件 ID：ui.calendar-card ｜ 定位：内嵌卡片式单月日历视图（单选日期，不含弹层）——月历 7 列网格展示年月，点选日期高亮并回传 onChange(date)；头部显示 年-月 + 上/下月切换；宿主把视图放表单页/自定义弹层（库内通用 Popup 未实现，#54 待立项，弹层宿主自理）。对标 Vant Calendar / NutUI Calendar（可交互日期选择）收敛为库内自有设计语言（卡片月历网格 + 单选 + 范围禁用）。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-05，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 表单内"单选一个日期"：记账日期/单据日期/到期日等（页面内嵌卡片，所见即所选的月历格）；② 需要直观年月切换、今日定位、区间外禁选的日期选择；③ 双端一致展示的月历（代替平台系统日历 picker 保持库内设计语言统一）
不适用（N/A）① 黄历/节气/年历推算工具 → foundation.calendar（#22）（业务日历计算域，非交互选择器）；② 滚轮式日期（年/月/日分列滚动）→ DatePicker（#26）/ DatePickerView（#27）；③ 日期范围/区间多选 → 登记二期；④ 弹层/全屏日历容器 → 宿主自理（Popup #54 未实现）
五态适配默认态 ✅ 普通日次色文字；今日态 ✅ 今日=主色描边圆 + 主色文字；选中态 ✅ 选中日=主色实心圆白字加粗；禁用态 ✅ min/maxDate 范围外=灰 40% 不可点；加载/失败 N/A（纯本地渲染日期逻辑无网络态）
与现有组件关系deps=[DesignTokens]；双端实现可复用 foundation.calendar-tools（#89，weekday/月天数等纯计算）但为可选依赖（不强制耦合）；与 foundation.calendar（#22）划界：本组件=可交互选择控件（产出 Date），foundation.calendar=黄历工具（ChineseCalendar）；网格布局=7 列等分 + 空位占位（不依赖 Grid 组件，内部自排，避免方向性耦合）

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
卡片容器白底（bgCard）+ 圆角 lg（14）+ 1 边框 + 内边距 xs（4）水平内衬同 Grid 卡壳先例；卡片外壳=组件自身（含边框圆角，宿主外层叠卡片可不重复描边）；阴影=AppShadow 可选（demo 不用阴影）
导航头高 44pt/44dp，标题=Sm Semibold 文本 "yyyy 年 M 月"；左右箭头=点击区 28×28 圆角 sm，符号用字符 ‹ ›（系统文本符号，同库 icon 字符先例）箭头点击区 ≥28 保证可点；当月已到 min/maxDate 边界对应方向箭头置灰禁点（D3 验证）；导航区非月份滚动手势（滑切=二期）
星期行高 22pt/dp，字号 Xs=12，文字=textSecondary；行首=周日（周起始固定周日=双端一致，可配=二期）星期简写=日 一 二 三 四 五 六（单字=无国际化歧义，双端统一）；周起始周日与原生常见日历一致
日期格7 列等分；格高 40pt/40dp（含选中圆形半径=格高/2）；字号 Md=16；选中=primary 实心圆白字；今日=inset 1.5 主色描边圆+主色字；范围外=textDisabled 灰圆形视觉半径=格高一半（同 Cell/Grid 图标圆先例）；6 行自适应（首/尾月空位用空白占位保证 7×6 网格稳定）；横向无滚动
选中语义selected: Date?（半受控）+ onChange(date)点选中日=整格触发 onChange（幂等=点已选中日不重复回调）；外部 selected didSet=同步高亮并自动切到所属月；今日与选中并存=选中圆覆盖今日描边（选中优先）
范围禁用minDate: Date? / maxDate: Date?（默认 nil=不限）范围外日=不可点不回调；month 内部切换被边界限制时=对应箭头置灰（不改列表则日格本身灰+不可点）
跨月/翻月组件内部自管理当前展示月（yearMonth）；外部可驱动 selected 自动切月；month 边界=1900-01 ~ 2099-12 软限制不做无限翻页（年范围足够业务用）；首尾空位占位=保证网格 7×6 稳定（多平台 1:1）

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 组件定位：ACE 三选

选项后果评估
A：内嵌卡片式月历网格单选组件（无弹层）——7×6 网格 + 年-月导航 + 今日/选中/范围禁用 + onChange(date)✅ 与日历"选择器"语义纯粹（产出 Date）；宿主可直接放表单卡片或装入自定义弹层复用；实现不依赖未立项组件，双端 1:1 简单；与 foundation.calendar 黄历工具天然划界推荐 A：收敛可验收
B：一体式弹层日历（遮罩+弹出+选择+确认按钮）遮罩/弹层/确认=Popup 类职责（#54 未实现）；确认按钮=表单容器职责；组件职责膨胀淘汰：登记二期（Popup 立项后宿主弹层装本卡片）
C：直接套 UIDatePicker / DatePickerDialog 系统日历系统日历视觉/语言/区域设置与库内 design token 不可控；iOS 滚轮/UIPicker 与 Android 日历弹窗形态差极大，双端契约难统一淘汰：系统控件不一致（收编先例只覆盖简单近似场景）

P2 · 数据模型：ACE 三选

选项后果评估
A：Date 值模型——selected: Date?（选中）+ onChange(Date)；minDate/maxDate 控制范围；组件内部管理 yearMonth 展示月✅ 双端原生 Date 直接落地（业务落库即 Date）；范围禁用=日期比较天然；所选即 Date 无中间字符串/组件态歧义推荐 A：值语义最简单
B：字符串 yyyy-MM-dd 模型（值与展示双字符串）时区/本地化/比较（范围禁用）都要宿主/组件反复 parse，双端日期格式化实现不同易出差异淘汰：字符串仅展示层表达
C：年/月/日整型元组 (y,m,d) 模型与双端原生日期转换繁琐，业务侧落地成本高；范围比较手工构造日期淘汰：无收益

P3 · 选中态控制：ACE 三选

选项后果评估
A：半受控 selected——内部自管理当前展示月；selected 可外部传入（didSet 同步高亮并自动切月）；点选触发 onChange；点已选中日不重复回调（幂等）✅ 宿主"页面带已有日期=预填回显""外部重置=驱动切月"都成立（编辑场景/表单联动）；与库内半受控语义一致（同 Tabbar/Tabs/SideBar）推荐 A：灵活且行为确定
B：纯受控——value 必传，选中态完全宿主回填对纯月历选择过重（内部无多状态可回填）；默认"当月无选中"起始态宿主也要管理可接受但过度
C：纯自管理 + 仅通知点击编辑场景无法预填回显；表单需要把用户选的日期存宿主时仅靠事件回调（state 靠宿主另存），双份状态易漂移淘汰

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：单月卡片网格单选——年-月导航头 + 7×6 网格（周起始周日）+ 今日态 + 选中态 + min/maxDate 范围禁用 + 首尾空位占位 + 外部 selected 回显自动切月 + demo 四段（基础/翻月与今日/范围禁用/受控驱动）✅ 覆盖"卡片选单个日期"核心闭环；D3 范围禁用=D2 边界箭头置灰 + 日格灰禁 可验；D4 外部回显=编辑预填语义可验推荐 A：验收路径清晰
B：一期即含 日期范围/区间多选（起止双选）范围选择=双日期高亮+中间段态，状态机/触摸跨度处理双端复杂，且非当前业务诉求淘汰：登记二期（卡片+范围两态）
C：一期即含 农历/节日/周起始可配/月滑动切月/多语言星期黄历节日=foundation.calendar 职责；周起始可配/滑切=配置与手势双端差异面拉大淘汰：农历交 foundation；滑切/周配置=二期

05 · 平台差异表（表内放行，表外必须双端统一）

维度iOSAndroid放行原因
日期纯计算Calendar/DateComponents（当前语言区域公历）java.time.YearMonth/LocalDate两端标准日期库均按公历（格列=ISO 周序号换算固定 日=0），结果一致（表内放行）
点击按压反馈UIButton touchDown 高亮/压暗瞬态clickable 系统 ripple（Material 默认点击反馈）系统级原生差异：按压反馈体系不同（表内放行，同全库先例）
网格布局UIStackView 7 列（等分）+ 6 行Compose Column 6 行 × Row 7 格 weight=1f系统布局机制不同、结果同=7×6 等分网格（表内放行）
文本省略截断UILabel 系统文本Text 系统文本日期数字单格短文本无省略场景（表内放行）
尺寸数值单位ptdpToken 同一数值不同单位（表内放行，同全库先例）
数据模型命名final class CalendarCardView: UIView@Composable fun CalendarCard契约同构（表内放行，命名差异见门禁 B）
