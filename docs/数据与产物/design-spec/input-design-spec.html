Input 输入 · 设计规格（数据录入组件 #29 · 任务清单 #29，subcategory=form · 门禁 A）

组件 ID：ui.input ｜ 定位：通用单行文本输入内容组件（受控）——宿主容器给定宽度（Form 字段内容槽/页面布局），Input 提供输入壳（灰底圆角输入条）+ placeholder + 受控 value + 清除钮 + 尾部动作槽 + 键盘类型 + 密码掩码 + disabled；文本校验算法与提交=宿主职责。对标 NutUI field / Ant Input 收敛为库内自有设计语言；Android 业务收编 AppInputField 系列（52dp 灰底圆角壳=同视觉）为前身=新组件视觉无缝可平滑迁移。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-06，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 表单单行文本录入（昵称/标题/金额字符等，置于 FormFieldRow #28 内容槽）；② 页内轻输入（备注一行/筛选词/验证码）；③ 需清除/尾部动作的输入（验证码+发送按钮、可清空关键字）；④ 受控回显：宿主持 value 预填/清空外部驱动（编辑表单、重置）
不适用（N/A）① 多行长文本 → 二期或随 TextArea 类组件立项（本件=单行）；② 标签/必填星/帮助/错误文案 → FormFieldRow #28 职责（Input 壳内不嵌 label/error，表单语义由 Form 承载）；③ 步进式数字改值（无键盘）→ ui.input-number #30；④ 搜索框（放大镜+防抖+回车触发）→ Search 类组件/宿主（若清单立项）；⑤ 登录专用 手机号/邮箱/密码 业务形态 → Android 业务收编 AppInputField/PhoneInputField/EmailInputField/PasswordInputField 先例（未来可平滑迁移 ui.input，见 A5）
五态适配默认态 ✅ 空值=placeholder 灰字（textTertiary）；输入态 ✅ 值主色 Md16+原生光标；聚焦态 ✅ 壳视觉不变（灰底无边框），光标与系统键盘为原生聚焦反馈（无额外描边强调=二期可加 primary 细边方案）；禁用态 ✅ 整壳 40% 灰、不可点不可聚焦；错误/校验态=FormFieldRow 行内红字呈现（壳不变红=表单语义归 Form）
与现有组件关系deps=[DesignTokens]；与 Form #28=Input 作为内容槽放入 FormFieldRow（行高随控件撑开=行高 min48 与 Input 48 对齐）；与 InputNumber #30 划界=Number=−/+/值 步进无键盘、Input=自由文本+键盘；与 Button 尾槽组合=宿主在 trailing 放"获取验证码"按钮；键盘弹出避让=宿主页面容器职责（滚动/inset，双端同语义）

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
输入壳高 48pt/48dp（与 FormFieldRow min48 对齐）；圆角 lg（radius lg）；底 bgPage 灰（无描边无阴影）；内水平 padding md（12）灰底圆角条=库内输入壳视觉（延续 Android AppInputField 52dp 灰底壳同语言，高度 48 对齐表单行）
文本Md16 textPrimary 单行；placeholder Md16 textTertiary文本不自动缩放；超长内部滚动/省略随系统光标位移
清除钮20pt/20dp 圆（radius full）底灰 40%（#D1D5DB 系）+ 白叉 14 居中；非空显示、点击=清空回调；清除钮后置（若有 trailing 槽则清除钮在文本与 trailing 之间）延续 Android 收编 ClearIconButton（20dp 圆灰底白 14 叉）
尾部动作槽宿主自放（宽度自定、垂直居中、与文本间距 sm 8）如"获取验证码"按钮等；Input 不渲染默认尾部内容
键盘/安全keyboard 四值映射：text/number/phone/email；secure=true=密文掩码（输入内容圆点/掩码显示、回调始终回原文）键盘映射两端平台差异表内放行（见 §05）；secure 无显隐切换（=二期）
禁用/限制disabled=整壳 textTertiary 40% 灰+不可点；maxLength（0/缺省=不限）仅对输入路径截断（外部赋值不强制截断）disabled 优先级最高（灰态可读不可编辑）

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 组件定位：ACE 三选

选项后果评估
A：通用单行文本输入内容组件（受控）——输入壳视觉+placeholder+受控 value+清除钮+尾部槽+keyboardType+secure+disabled+maxLength；宿主容器/Form 决定宽度✅ 文本录入核心闭环收敛；与 Android AppInputField（灰底圆角+清除钮+尾槽+keyboardType+掩码）同视觉同 API 家族=业务可平滑迁移；无内嵌 label/校验=与 Form 划界干净；双端实现=基础输入控件包装（UITextField/BasicTextField）+壳，轻量可靠推荐 A：通用内容组件
B：做成 Form 绑定"输入行"（内置 label/必填星/错误渲染）与 FormFieldRow #28（label+required+help/error）职责重复；脱离 Form 不可用=复用性差淘汰：label/校验=Form 职责
C：保持多端业务专用输入不收敛（登录/手机号/邮箱/密码各自为政）Android 收编已 4+ 个专用变体；iOS 无任何独立输入=长期业务自绘淘汰：需库级基础件承载通用场景（专用键盘类型经 keyboardType 参数表达）

P2 · 数据/接口模型：ACE 三选

选项后果评估
A：String value + onTextChange(String) 直通——value 唯一真源、每次编辑回传新文本；配套 placeholder/keyboard/secure/maxLength/clearable/trailing/disabled 参数✅ 与两端原生输入控件（UITextField text/BasicTextField value+onValueChange）同构=实现零转译；宿主天然持全量文本（校验/提交都需要）推荐 A：直通模型
B：细分事件模型（onFocus/onBlur/onChange 分段）iOS UITextField delegate 有 focus/blur 但需宿主多监听点；一期无聚焦态 UI 需求=过度淘汰：二期（若聚焦强调视觉立项再补 onFocus/onBlur）
C：双向绑定包装（宿主传对象引用、组件直接改对象字段）跨端契约对象引用语义不同（iOS 引用类型 vs Android State），回写链隐晦难排查淘汰：与库内值+回调惯例不符

P3 · 状态控制：ACE 三选

选项后果评估
A：受控 value（必传，外部 setValue=直接刷新文本；onTextChange 仅在用户编辑/清空钮触发）——iOS 命令式 text 属性外部赋值即时刷新；Android value 参数变化自动重组✅ 文本组件天然受控（宿主必须存文本=双源不可能）；外部预填/清空/重置=直接改 value 即回显且不触发编辑回调（D4 demo）；两端编辑回调与外部赋值路径清晰分离推荐 A：文本=受控真源
B：半受控（value 可选，nil=组件内部持值自管理）内部自持文本=宿主提交时才问值（UITextField/BasicTextField 已自带内部 text，不传即失联）；与"宿主需全量文本"诉求冲突淘汰：文本组件不自持双源
C：纯自管理+onSubmit 才回传实时编辑过程宿主不知=校验/字数/联动无法做淘汰

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：单行通用输入=壳+placeholder+受控 value+clearable+trailing 槽+keyboard 四值映射+secure 掩码（无显隐切换）+disabled+maxLength（输入截断）+demo 四段✅ 文本录入完整闭环（空态/输入/清空/掩码/禁用/外部驱动/键盘类型）可逐验；secure 覆盖密码表单场景（无显隐切换=UI 简洁）；无 label/校验=与 Form 组合由宿主演示推荐 A：核心闭环可验收
B：一期含 secure 显隐切换（眼睛钮）+字数角标计数 + 前后缀 icon显隐钮/计数/前后缀=各自独立交互面；范围膨胀且非文本录入必需淘汰：登记二期
C：一期含多行 TextArea/搜索框形态多行=独立组件职责（行高/换行策略不同）；搜索=语义+交互独立（防抖/回车触发）淘汰：随对应组件立项/二期

05 · 平台差异表（表内放行，表外必须双端统一）

维度iOSAndroid放行原因
文本编辑内核UITextField（delegate editingChanged/shouldChangeCharacters 截断）BasicTextField（AppInputField 同源，onValueChange 截断）系统输入控件不同、编辑行为一致（表内放行）
键盘映射text→UIKeyboardType.default / number→numberPad / phone→phonePad / email→emailAddressKeyboardType.Text / Number / Phone / Email平台枚举不同、语义映射固定（表内放行）
密文掩码UITextField.isSecureTextEntryPasswordVisualTransformation掩码实现不同、视觉一致（表内放行）
清除钮自绘圆叉 UIButton（trailing 动态显隐）Icons.Default.Clear 圆钮（同收编 ClearIconButton）平台图标机制不同、视觉一致（表内放行）
禁用机制isUserInteractionEnabled=false + 灰化enabled=false（BasicTextField readOnly 语义）平台禁用实现不同（表内放行）
状态回写命令式：外部 text 属性赋值即时刷新声明式：value 参数变化自动重组受控组件两端真源一致、刷新机制不同（表内放行）
键盘避让宿主 scrollView insets/keyboardWillShow 通知宿主 adjustResize/imePadding宿主职责双端同语义（表内放行）
尺寸单位 / 命名pt；InputView（独立 InputView.swift，含 UITextField+清除钮+尾槽壳）dp；@Composable Input（Input.kt）Token 同值不同单位；命名差异见门禁 B（表内放行）
