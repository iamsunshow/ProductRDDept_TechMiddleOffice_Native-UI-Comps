Toast 吐司

组件 ID：ui.toast ｜ 任务清单 #59 ｜ 操作反馈区第十五件 ｜ TMO 组件库 v1.4.14

定位：全局轻量提示浮层——屏幕居中短时显示文本/图标，自动消失，不阻断用户操作。

1. 场景与边界（SCQA）

Situation 情景

用户执行操作后需要轻量反馈（保存成功/复制成功/网络错误），不需要用户确认，2~3 秒后自动消失。

Complication 冲突

无统一组件时=各业务自拼 Android.widget.Toast / iOS MBProgressHUD，视觉不统一、无类型图标、无自定义时长、无堆叠管理。

Question 问题

需要一个全局轻量提示浮层，支持文本+类型图标（success/error/warning/info/loading）、自定义时长、自动消失、多条堆叠，双端视觉一致。

Answer 方案

Toast——Window 层级浮层（iOS UIWindow / Android WindowOverlay），屏幕居中或顶部，纯展示无交互，自动消失。

5. 关键决策 PREP/ACE（P1–P4，AI 代评待用户总审）

P1 · 组件形态：ACE 三选

选项后果评估
A：Toast 静态方法 + 单例容器（Toast.show() 触发，内部单例管理显示/消失/堆叠）✅ 调用最简（一行 API），与 Vant Toast / NutUI Toast 一致，自动管理生命周期。推荐 A：一行 API + 自动管理
B：ToastView 组件声明式声明式但需宿主管理 visible 状态，调用繁琐。淘汰：提示场景指令式更友好
C：宿主自拼重复造轮子。淘汰

P2 · 浮层层级：ACE 三选

选项后果评估
A：Window 层级（iOS UIWindow + windowLevel / Android WindowOverlay/Popup）✅ 脱离当前 ViewController/Compose 树，全局顶层，不阻断下层交互。推荐 A：全局顶层不阻断
B：ViewController presentiOS 会阻断下层交互（modal 遮罩）。淘汰：阻断交互
C：Compose 树内 Box 叠层Android 局限于 Compose 树，跨页面不持久。淘汰：跨页面不持久

P3 · iOS 实现路径：ACE 三选

选项后果评估
A：UIWindow + windowLevel = .alert + 透明 rootVC + UIView 淡入淡出✅ UIKit 原生，独立 Window 不阻断下层，UIView.animate 淡入淡出，定时器自动消失。推荐 A：UIWindow 顶层不阻断
B：UIViewController presentmodal 阻断下层交互。淘汰
C：MBProgressHUD 第三方库依赖外部库，不符合组件库自包含原则。淘汰

P4 · Android 实现路径：ACE 三选

选项后果评估
A：ComposeWindow + ComposableContent + Box 居中 + animateAlpha 淡入淡出✅ Compose 原生，独立 Window 不阻断下层，animateFloatAsState 淡入淡出，协程延迟自动消失。推荐 A：ComposeWindow 顶层不阻断
B：android.widget.Toast系统原生但样式不可定制（系统主题约束）。淘汰：样式不可控
C：Dialog会阻断下层交互（dim 遮罩）。淘汰：阻断交互

8. anti_goals 反目标（二期不做）

  • 自定义 Toast 内容（插槽/自定义视图）——一期纯文本+图标覆盖 80%
  • 可点击交互（Toast 内按钮）——Toast 纯展示，交互用 Dialog
  • 堆叠多条（一期同一时刻只显示一条，新 Toast 替换旧的）
  • 位置可配（顶部/底部）——一期固定居中
  • Lottie 动画图标
