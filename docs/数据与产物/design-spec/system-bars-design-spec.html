SystemBars 系统栏

组件 ID：foundation.system-bars ｜ 任务清单 #90 ｜ 底层能力 foundation ｜ TMO 组件库 v1.4.0

定位：按页面统一配置系统栏（状态栏 / 导航栏）背景色与内容明暗，支撑沉浸式头图页与常规白底页的视觉切换。

1. 场景与边界（SCQA）

Situation

明细页使用品牌绿沉浸式头图，状态栏须为绿底白字（浅色图标）；其余页面为白底深字。

Complication

Android 可直设 window.statusBarColor 并切换图标明暗；iOS 系统不支持设置状态栏背景色（只能控制内容样式 preferredStatusBarStyle），且 iOS 工程内仅有 StatusBarNavigationController（容器委托）没有独立能力出口——双端能力面不对等。

Question

需要一个双端语义对齐的系统栏配置能力：「按页声明状态栏样式」，随页面进入/离开自动生效，离开无需手工还原。

Answer

SystemBars——Android 侧为 @Composable ConfigureSystemBars(statusBarColor, navigationBarColor)（颜色 + 依亮度自动判定图标明暗，DisposableEffect 随组合生效）；iOS 侧为 StatusBarNavigationController（容器把样式决策委托栈顶页）+ 新增轻量工具 SystemBars（样式枚举 + 页面应用辅助）。

2. 组件边界与划界

组件职责与 SystemBars 划界
SafeArea #10内容避开状态栏/Home 指示条的安全区避让SafeArea=「内容不进入系统栏区域」（padding/inset），SystemBars=「系统栏自身外观（底色+图标明暗）」；常配合使用：沉浸页先用 SystemBars 改色，再让头图延伸至安全区
NavBar #17页面顶部导航条（返回/标题/右侧动作）NavBar 是页面内自绘的一条 UI，SystemBars 是系统级状态栏；NavBar 不负责状态栏底色
Sticky #12滚动吸顶Sticky 只管内容吸附，不改变系统栏外观

3. API 契约

Android

API签名说明
ConfigureSystemBars@Composable fun ConfigureSystemBars(statusBarColor: Color, navigationBarColor: Color = AppColor.bgCard)按页设置状态栏/导航栏底色；DisposableEffect 在组合进入时生效；图标明暗由 statusBarColor.luminance() > 0.5f 自动判定
transparentStatusBarColorfun transparentStatusBarColor(): Int透明状态栏初始值，由各页 ConfigureSystemBars 覆盖

iOS

API签名说明
StatusBarNavigationControllerfinal class StatusBarNavigationController: UINavigationController重写 childForStatusBarStyle/childForStatusBarHidden，将状态栏决策委托给栈顶 VC
SystemBars新增·补齐缺口enum SystemBars + enum Style { case light, dark } + static func style(for:) + static func apply(_:in:)轻量工具：把「亮色/深色状态栏」语义映射到 UIStatusBarStyle（.lightContent / .darkContent）并触发 setNeedsStatusBarAppearanceUpdate()，供页面在 preferredStatusBarStyle 中调用

Events

事件说明
无声明式配置，无回调

4. 设计规格

项规格依据
默认态白底 + 深色图标（AppColor.bgCard）App 常规页基线
沉浸态品牌绿底 + 浅色图标（AppColor.primary）明细页头图
透明态透明底 + 深色图标（头图自绘延伸）整屏图片头图
图标明暗判定亮背景(luminance>0.5)→深色图标；暗背景→浅色图标对比度可读性（WCAG 建议 ≥4.5:1）
导航栏（Android）默认 AppColor.bgCard，图标固定深色Android 手势/三键导航条默认浅色底
导航栏（iOS）无对应 API（Home 指示条区域随页面背景）系统限制，见 §7 差异表
生效时机页面进入即生效；Android 随组合生命周期；iOS 随 viewWillAppear 后刷新避免手工还原导致的跨页串色

6. 决策投票表

编号决策点选项选定理由
P1双端能力对齐口径A. 对齐到「按页声明状态栏样式（底色+图标明暗）」
B. 只对齐图标明暗（放弃底色）
C. 只 Android 支持		A业务核心诉求是沉浸式头图的底色；iOS 侧底色由页面在安全区自绘实现等价视觉（见差异表）
P2iOS 缺口处理A. 新增轻量工具 SystemBars（样式枚举+应用辅助）补独立出口
B. 沿用 StatusBarNavigationController 不改
C. iOS 侧不做（标 partial）		AiOS 现有能力仅为导航容器，组件无独立出口；补轻量工具后双端各有明确入口，Demo 才可 1:1（api.json 从 partial 升 available）
P3图标明暗判定A. Android 依背景亮度自动判定 + iOS 显式声明
B. 双端都显式声明
C. 双端都自动		AAndroid 能读到底色可自动推导（少一处误设）；iOS 本就无法读底色，显式声明是其唯一可行路径
P4一期范围A. 底色+图标明暗三态（默认/沉浸/透明）+ Demo 4 段
B. 二期=渐变状态栏/状态栏随滚动渐变/深色模式		A一期覆盖记账类全部页面；随滚动渐变属特效，二期

7. 平台差异表

差异点iOS（UIKit）Android（Compose）判据
状态栏背景色不可设置（系统 API 限制）；由页面在安全区自绘色块实现等价视觉window.statusBarColor = color 直接设置表内放行（视觉等价，实现不同；Demo 双端呈现一致观感）
图标明暗preferredStatusBarStyle（.lightContent/.darkContent）显式声明isAppearanceLightStatusBars 依 luminance() > 0.5 自动判定表内放行（结果一致，决策路径不同）
导航栏无对应 API（Home 指示条区域随页面背景）window.navigationBarColor（默认 bgCard，图标深色）表内放行（iOS 无实体导航栏底条）
生效/还原页面 preferredStatusBarStyle 随栈顶自动生效（容器委托）DisposableEffect 随组合进入/离开表内放行（均为声明式，无需手工还原）

8. 反目标

不做原因
状态栏随滚动渐变特效，二期
渐变 / 图片状态栏底由页面自绘，组件只提供纯色/透明
深色模式联动二期（DesignTokens 亦不做深色）
状态栏显隐控制一期保留 childForStatusBarHidden 委托但不做 UI 开关
