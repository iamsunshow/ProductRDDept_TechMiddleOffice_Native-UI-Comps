FixedNav 悬浮导航 · 设计规格（导航组件 #3 · 任务清单 #15，subcategory=navigation · 门禁 A）

组件 ID：ui.fixed-nav ｜ 定位：页面边缘常驻悬浮入口钮 + 展开导航项列表的"快捷导航器"——收起态=单胶囊钮，点击展开=钮旁列表面板，点项回传并自动收起，对标 NutUI React FixedNav（active/nav-list/type/text）。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-04，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 2-6 个高频功能入口需要"不占主内容区、边缘常驻、随时展开"的悬浮导航（账单页 导出/筛选/分享、报表页切换口径、工具页更多操作）；② 收起态不干扰浏览、展开态一次可见全部入口并点选回传；③ 左/右边缘可切换摆放
不适用（N/A）① 单功能悬浮回顶 → BackTop（ui.back-top）；② 仅一个悬浮按钮且无列表（自定义点击动作）→ HoverButton（ui.hover-button，#16）；③ 底部主导航 Tab → Tabbar（ui.tabbar）；④ 页面顶部导航/面包屑 → NavBar（ui.navbar）
五态适配默认态 ✅ 收起胶囊钮（un-active-text）；交互态 ✅ 点击展开=钮旁弹出导航列表面板（钮文字切 active-text）；选择态 ✅ 点项触发 onSelect 并自动收起面板；禁用/加载/成功/失败 N/A（导航入口类组件，数据为空态=钮仍可用但不弹内容，本期不引骨架）
与现有组件关系deps=[DesignTokens]；钮视觉基线对齐 BackTop 悬浮钮（高 40pt/dp 主色系）；面板行=组件自有极简行（圆底图标位+文本+可选角标+间隔线），不依赖 Cell（Cell 语义=页面内容单元格带五态/箭头，FixedNav 面板是短入口列表=行视觉更轻）。与悬浮类划界：BackTop=回顶单功能、HoverButton=无列表单钮自定义、FixedNav=带列表的多入口悬浮导航

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
悬浮钮高/最小宽40pt/40dp（对齐 BackTop 悬浮钮直径），圆角=full，水平 padding 16文本胶囊钮：图标位（可选）+un-active-text/active-text 文本；钮底=primary 白字（BackTop 主色圆钮同款视觉族）
面板宽/行高面板宽=内容撑开（行 最小 140pt/dp），行高 44pt/44dp行=圆底图标位 20 + 间距 8 + 文本 + 可选 num 角标；末行无下边线；面板=卡片壳（bgCard/圆角 md/边框/投影）
行图标位20pt/20dp 圆角 6，bg=primaryMuted，字符 primaryicon 一期=单字符/emoji 文本（不走 Icon 组件映射，二期接系统图标）
num 角标高 16pt/dp 圆角 full，bg=primary 白字，字号 12pt/dp（=AppFont.sizeXs，令牌零硬编码）可省略（0/缺省=不显示）
位置宿主锚定（右下/左下），组件悬浮于滚动内容之上由宿主层级保证组件不自带 window 级浮层/滚动监听/拖拽，type 只定面板相对钮展开侧

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 形态与展开交互：ACE 三选

选项后果评估
A：收起=文本胶囊钮（un-active-text），点钮=钮旁弹出竖排列表面板，展开态钮文字切 active-text（再点收起/点项收起/点外部收起），面板相对钮向左/右展开由 type 定✅ 对齐 NutUI 核心交互（active 双向控制）；双端同构（iOS UIButton+UIView 面板 / Compose 按钮+Card）；无额外浮层 API。推荐 A：范围收敛、可验收直观
B：展开=底部 Popup/全屏半层弹列表接近 ActionSheet/选择器语义，与"悬浮导航"轻量定位冲突，交互偏重。淘汰
C：拖拽自由摆放 + 长按排序（NutUI Drag 组合）拖拽涉及手势与布局持久化，一期成本高且非核心。淘汰：登记二期（Drag 集成）

P2 · 数据模型与回调：ACE 三选

选项后果评估
A：FixedNavItem(key/text/icon?/num?) + navItems + type(left/right) + activeText/unActiveText(自定义文案) + onSelect(item)（选中自动收起）✅ 对齐 NutUI nav-list/type/active-text/un-active-text/selected；key=唯一标识回传稳定；文案可本地化覆盖。推荐 A：契约干净、覆盖演示差异
B：数据用 id/text 命名 + icon 必填图片地址（NutUI 原样）原生无"图片地址"数据习惯，icon 需改造为库内资源引用，契约与 iOS/Android 资源系统强耦合。淘汰：icon 一期简化文本位
C：只传文本数组无 key/icon/num覆盖不到角标诉求，行内图标位固定空置，观感差。淘汰

P3 · 悬浮钮通用层：ACE 三选

选项后果评估
A：组件=纯内容视图（钮+面板自身排版），"悬浮"=宿主放入非滚动覆盖层并锚定边角；type 仅决定面板展开方向（right 钮在右=面板向左伸；left 对称）✅ 与 BackTop 同款宿主定位约定（BackTop 也是宿主摆放）；无 window 侵入；demo 直接复用展示容器。推荐 A：与 BackTop 先例统一
B：组件包 window-level overlay + 自动吸附滚动页面边角iOS 需 UIWindow 或 keyWindow 注入，Android 需 WindowManager，脱离"组件=可嵌入视图"库定位。淘汰
C：包一层容器自动完成页面滚动区域右侧锚定（复杂 layout 魔法）与宿主滚动容器结构强耦合，双端难以 1:1。淘汰

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：胶囊钮 40 高 + 展开面板（竖排行 ≤7：图标位/文本/num 角标/分割线）+ 点项 onSelect 自动收起 + 点钮切换展开收起 + 点面板外收起 + type 左右 + 文案自定义 + demo 四段✅ 覆盖悬浮导航核心闭环；≤7 行不引滚动=面板内不滚动。推荐 A：验收路径清晰
B：面板标题条（active-text 放面板顶部 + 展开收起把手）NutUI 有该布局，但组件将多一层内嵌 bar，收起语义有两入口，视觉冗余。淘汰：文案放钮本身
C：行内容插槽/自定义渲染 + 图标系统 Icon 接入 + 拖拽三项均为扩展能力，拖慢核心验收。淘汰：登记二期（自定义插槽/Icon 映射/Drag）

05 · 平台差异表（表内放行，表外必须双端统一）

维度iOSAndroid放行原因
展开/收起动画UIView animate（透明度+位移/scale）animate*AsState + AnimatedVisibility系统级原生差异：各自平台动画原语
点面板外收起宿主页 tapGestureRecognizer 回调 onOutsideTap 或容器提供收口（demo 用展示容器 tap）Compose 外部 pointerInput/容器级收口平台事件模型不同（表内放行，均以"点外部收起"验收对齐）
钮文本胶囊UIButton（主色底白字圆角 full）Surface/Button 同视觉系统级原生差异：按钮实现不同、视觉契约同
尺寸数值单位ptdpToken 同一数值不同单位（表内放行，同 Grid/Layout/Elevator 先例）
数据模型命名struct FixedNavItem / FixedNavTypedata class FixedNavItem / enum FixedNavType契约同构（表内放行，命名差异见门禁 B）
