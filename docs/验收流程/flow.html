TMO 组件库 · 组件验收流程图

按 docs/组件进度.md 列表顺序逐个推进；依赖优先叠加约束；五阶段 + 门禁 A/B/C1/C2/D；用不到的组件标【暂未使用】跳过。
阶段节点 门禁/判断 依赖检查 业务落地 跳过分支
▶ 开始：读取组件列表
任务清单 docs/组件进度.md，按分类从上到下，一个组件一个组件来。
▼
🔗 依赖优先：该组件的 deps 完成了吗？
⏳ 未完成 → 等依赖（或先做依赖组件）
从 api.json 的 deps 读取依赖，如 Cell 依赖 Icon/Image。避免"组件完成了、依赖还没实现"。
▼ 依赖就绪后回到本组件
▼ 依赖就绪 → 进入下一判断
❓ 该组件业务用得到吗？
⏭ 用不到 → 标注【暂未使用】
在列表备注登记原因，跳过全部门禁。每季度复查一次，业务变化可重新入队。
▼ 跳过后回到「读取下一组件」
▼ 用得到 → 进入设计阶段
阶段 1 · 设计（无代码）
产出设计规格 H5（用途/五态/尺寸引 token/交互/双端差异/组件关系/参考图）+ ②设计测试用例（D1-D8：五态渲染、token 取值、交互反馈）。
验收文档 ① 设计细节 验收文档 ② 设计测试用例 设计规格页 cell-design-spec.html
▼
门禁 A · 设计评审
✅ 通过 → 冻结设计 ❌ 打回 → 只改设计，不动代码
▼
阶段 2 · API 契约（无代码）
基于冻结的设计，在 api.json 定义契约：props / events / methods / capabilities / scenarios / visual_tokens，并定义 ④API 测试用例（A1-A7：属性取值、事件回调、能力覆盖）。
验收文档 ③ API 设计细节 验收文档 ④ API 测试用例 api.json + 开发规则.md（第八节）
▼
门禁 B · API 评审
✅ 通过 → 冻结契约 ❌ 打回 → 只改契约，不动代码
▼
阶段 3 · 双端实现（iOS + Android）
双端按冻结契约并行实现，测试函数与用例 ID 一一对应（test_D1_defaultState…），实现 ② + ④ 全部用例。
ios/*.swift android/*.kt 用例即代码：D1-D8 / A1-A7 ↔ 测试函数
▼
门禁 C1 · 自测对齐
✅ 通过 → 提交 PR ❌ 打回 → 修复后重测
检查：双端单测全绿 + 快照比对（Roborazzi / SnapshotTesting）+ 用例映射核对（CI 自动）
阶段 4 · CR + 合并（PR）
PR 强制清单（契约/测试/Demo/CHANGELOG/版本同步）+ Review 清单（双端对齐/token/无重复轮子）。
▼
门禁 C2 · CR + CI
✅ 通过 → merge ❌ 打回 → 修改后重提 PR
检查：CI（单测 + token 硬编码校验）+ Review 通过，才可 merge
阶段 5 · 发版 + 业务落地验证
发版：Demo 更新 → CHANGELOG → ui-version 双端同步 → tag。
落地：业务 App 真实接入该组件（替换一处自绘实现），记录替换前后代码量 / 自研率变化 → usage-<组件名>.md。
demo/CHANGELOGui-version.jsontag docs/验收流程/usage-<组件名>.md（接入记录）
▼
门禁 D · 业务落地验证
✅ 接入成功且代码量下降 → 验收完成 ❌ 接入失败 → 回退排障 / 组件回修
▼
更新进度文档
在 docs/组件进度.md 更新状态 + 达成情况，同步完整度指标。
▼ 回到「读取下一组件」… 直到列表末尾
✅ 完成：95 个组件全部处理（实现 + 落地验证 或 【暂未使用】）
──────── 贯穿规则 ────────
1依赖优先：组件 deps 必须先于它完成（列表顺序之上叠加的约束）。
2用例即代码：验收文档用例 ID（D*/A*）↔ 测试函数一一对应，CI 在 C1 自动核对，缺 → 打回。
3季度复查：每季度扫一遍 ⏭【暂未使用】清单，业务变化则重新入队。
4回归清单：基础组件（Button/Icon…）发版后，从 deps 反查下游受影响组件，纳入回归范围。
5打回不动代码：门禁 A/B 打回只改文档/契约，从源头拦截返工。
