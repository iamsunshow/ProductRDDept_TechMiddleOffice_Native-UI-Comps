Sticky 粘性布局 · 设计规格（布局组件 #6 · 任务清单 #12，subcategory=layout · 门禁 A）

组件 ID：ui.sticky ｜ 定位：粘性容器——把一行内容在父滚动容器滚动时固定在可视区顶部，对标 Web position:sticky / Android LazyColumn stickyHeader / iOS UITableView 浮动 section header 的跨端封装。用于「分组列表的分组标题吸顶」「筛选条吸顶」「表头吸顶」等需在滚动中保持可见的标题类行内容。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-04，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 分组列表（账单/联系人/通讯录按日期/首字母分组的组标题在滚动时吸顶）；② 筛选/排序条随内容滚动吸顶；③ 数据表头（列头在长列表滚动时吸顶）；④ 长表单章节标题吸顶提示当前位置
不适用（N/A）① 悬浮操作类（回到顶部/发布按钮等全局悬浮层）→ BackTop（ui.back-top）/HoverButton（ui.hover-button）；② 底部操作栏固定 → 页面级 bottomBar（Tabbar/自绘）而非内容吸顶；③ 侧边导航吸顶 → SideBar（ui.side-bar）；④ 内容不滚动的单屏布局 → 无需粘性
五态适配默认态 ✅ = 未滚到顶：随内容流正常排布；吸顶态 ✅ = 滚过原点：钉在滚动容器可视区顶部。点击/禁用/加载/成功/失败 N/A（吸顶条自身交互由内容承担）
与现有组件关系deps=[DesignTokens]（视觉走内容组件自身 token，Sticky 只负责"吸顶行为"）。与 Space/Layout/Grid 划界：布局组件管"静态排布"，Sticky 管"滚动中保持可见"。可为 Cell 分组列表、Grid 宫格页、Layout 表单行的组标题提供吸顶外层。Divider 可作为吸顶条内部分隔或列表行间分隔复用

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
吸顶条视觉内容组件自含Sticky 为行为容器不提供视觉：背景/圆角/阴影/文字由吸顶条内容（如 Cell/标签+按钮行）自带
吸顶偏移（offset）数字 pt/dp（默认 0）吸顶位置距滚动容器顶部的偏移（如需要给 AppBar 让位时传入）
层级（z 序）规则吸顶后需浮于滚动内容之上（高于普通行内容 z 序）
吸顶后阴影/底色变化一期不做吸顶态与常态视觉一致（除位置外不变式）——变化样式登记二期（避免一期状态样式蔓延）

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 一期形态：ACE 三选

选项后果评估
A：单吸顶行封装——列表/滚动容器内嵌 StickyItem（原生 stickyHeader 或 offset 监听）✅ 覆盖「分组标题吸顶」核心场景；Android LazyColumn stickyHeader 原生、iOS 监听 contentOffset 改 pinned 约束，双端可行且一致。推荐 A：一期克制，覆盖分组列表与筛选条两大高频诉求
B：任意内容多级 sticky（多个不同高度吸顶块互相替换）iOS 需复杂 z 序管理+多 pinned 约束切换，成本数倍且业务场景（多级分组+替换动画）当前未出现。淘汰：登记二期候选（多 sticky 段逐节替换）
C：Web position:sticky 语义完整复刻（含 bottom 吸底、粘在容器边界内）端上原生无此语义，iOS 自实现成本高收益低。淘汰：端上场景以 top 吸顶为主

P2 · 承载滚动容器：ACE 三选

选项后果评估
A：Sticky 面向「列表容器」（LazyColumn / TableView / UICollectionView / 自管 UIScrollView）通用提供✅ 列表型（分组标题）是绝对主流；组件内部区分列表原生 sticky 能力与通用滚动监听两条实现路径，对外 API 单一。推荐 A：覆盖列表+通用滚动两大形态
B：仅列表 stickyHeader 模式（Android LazyColumn / iOS TableView section header）实现最简（双端皆原生），但 UIScrollView 型长页（表单章节标题/长文小标题吸顶）无解。淘汰：砍掉通用滚动场景则组件价值减半
C：仅通用滚动监听模式（双端统一 offset 驱动）列表用也要手接 offset，违背"分组标题吸顶开箱即用"。淘汰：反直觉

P3 · iOS 实现路径：ACE 三选

选项后果评估
A：pinned 约束方案——内容随滚动容器平移，Sticky 监听 contentOffset，命中阈值即把吸顶块从滚动内容平移为钉在容器顶部（约束/ frame 切换 + z 序提升）✅ 不依赖 TableView/CollectionView 特定结构，可包装任意可滚动内容的普通视图容器，与 Android「滚动容器 + stickyHeader」语义对应。推荐 A：demo 用 UIScrollView 验证，行为确定
B：UITableView sectionHeader 原生浮动仅列表可用、行为受系统 section 模型约束（必须整节数据驱动），无法承载自定义筛选条等非行内容。淘汰：场景面窄
C：UICollectionView 自定义 layout（layoutAttributes zIndex）性能最优但实现复杂度高，且只覆盖 collection 型。淘汰：一期用不上（二期多段 sticky 时再评估）

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：单吸顶点 + offset + 双端各一条 demo 路径（iOS 通用滚动 pinned / Android LazyColumn stickyHeader + UIScrollView pinned 对照）✅ 四个 demo 段可控、可实机 1:1 验收；吸顶态视觉不变式一期。推荐 A：范围收敛、先跑通行为再谈样式
B：一期追加吸顶态样式（阴影/底色加深/边线）需要状态分发与样式 token，双端状态语义新增（吸顶态埋点与测试面积扩大）。淘汰：登记二期
C：一期追加多吸顶段（各分组各吸顶）iOS 多 pinned 切换复杂度陡增。淘汰：登记二期候选（P1-B）

05 · 平台差异预告

维度iOSAndroid差异说明
列表路径UIScrollView 容器 + pinned 平移方案（P3-A）LazyColumn + Modifier.stickyHeader / 或 Column+offset 监听原生能力差异；对外均为「滚动容器 + Sticky 内容块」
实现引擎contentOffset 监听 → 吸顶块约束/位置切换LazyLayout 自带 sticky 语义（无需自算）行为对齐（吸顶位置/替换时序）
offset 支持手动传入（pt）stickyHeader 下方留位或 topPadding语义一致：吸顶点偏移量
命名StickyView / StickyHeaderContainerSticky / StickyHeaderItem双端同名 Sticky 前缀统一（P1 表决后定）

06 · API 速览（门禁 B 冻结前草案）

类别名称类型必填说明
PropsoffsetCGFloat/Dp否吸顶位置距滚动容器顶偏移（默认 0）
Slotcontent（header 内容）任意 View/Composable是吸顶行内容（Cell/标签+按钮/任意自绘行）
容器host（滚动容器）UIScrollView 子类 / LazyColumn 等是Sticky 绑定的滚动宿主（用于监听 offset / 提供 sticky 语义）
事件onStickChange回调 (Bool)否吸顶态切换回调（一期登记，供业务埋点/UI 反馈，不参与视觉）

使用示例（草案）：StickyView(host: scrollView, offset: 0) { 标题行 } / item(key=分组) { StickyHeaderItem(offset=0.dp) { 标题行 } }
