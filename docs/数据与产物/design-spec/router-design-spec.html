Router 应用路由

组件 ID：foundation.router ｜ 任务清单 #92 ｜ 底层能力 foundation ｜ TMO 组件库 v1.4.0

定位：应用内导航机制的唯一出口——一级 Tab 切换 + 二级及以下 push/pop + 路由表集中声明 + 目标页由宿主注入（中台包不依赖业务控制器）。

1. 场景与边界（SCQA）

Situation

App 有 5 个一级 Tab（明细/图表/记账/发现/我的）与 20+ 个二级页（账单、预算、资产、房贷、汇率、设置、帮助…），任意页面都可能跳向二级页。

Complication

若各页面直接 new 出目标控制器并 push，中台包里会出现对全部业务页的编译依赖，无法独立编译、无法单测。

Question

需要一个只管「导航机制」、不知道「页面从哪来」的路由层，且路由标识集中声明、便于审计。

Answer

Router——集中声明目的地（iOS AppRouter.Destination / Android MainDestination+SecondaryRoutes），目标页构造交由宿主注入（iOS RouterDestinationProvider / Android NavHostController 的 NavGraph）；未注入时回退占位页，保证中台包可独立编译。

2. 组件边界与划界

组件职责与 Router 划界
NavBar #17 / Tabbar #19 / Tabs #20 / SideBar #18导航的「视觉与交互」这些是 UI 组件，点击后调用 Router 完成跳转；Router 不含任何导航 UI
BackTop #13 / FixedNav #15页内快捷导航视觉同上：只触发 Router，不承载路由表
业务页构造具体页面的创建由宿主注入（provider / NavGraph），Router 只按标识请求
Deep Link / URL Scheme外部唤起二期；一期仅应用内跳转

iOS（enum AppRouter，静态命名空间）

API签名说明

Android（class AppRouter(navController) + 路由常量）

API签名说明

Events

事件说明

4. 设计规格

项规格依据
路由标识集中声明，不得在页面内写裸字符串路由可审计、防拼写漂移
一级页Tab 切换，保留各 Tab 栈状态（Android saveState/restoreState）用户预期：切回 Tab 仍在原位
二级页一律 push，隐藏底栏，系统返回iOS hidesBottomBarWhenPushed / Android NavGraph 二级图
未注入兜底iOS 回退 NativePlaceholderViewController；Android else → placeholder(title)保证中台包独立编译与可运行
重复点击Android launchSingleTop；iOS 由宿主控制防栈内重复页
业务解耦Router 不 import 任何业务控制器/Composable中台包可独立编译红线

7. 平台差异表

差异点iOS（UIKit）Android（Compose Navigation）判据
导航容器UINavigationController / UITabBarController（宿主持有，Router 静态访问）NavHostController（构造 AppRouter 时注入）表内放行（平台原生导航体系不同）
目标页解析协议注入 RouterDestinationProvider（返回 UIViewController?）宿主 NavGraph 注册 Composable（路由串由 Router 提供）表内放行（语义一致：Router 只请求、宿主构造）
路由标识Destination 枚举（类型安全）路由字符串常量（SecondaryRoutes）表内放行（Android Navigation 原生为字符串路由）
Tab 状态保留系统 UITabBarController 天然保留各 Tab 栈需显式 popUpTo(start){saveState=true} + restoreState=true表内放行（行为一致，实现不同）
入口签名open(Destination, from: host)（需宿主 VC）open(title: String)（AppRouter 已持有 navController）表内放行（iOS 静态命名空间需显式传宿主；Android 实例已绑定）
