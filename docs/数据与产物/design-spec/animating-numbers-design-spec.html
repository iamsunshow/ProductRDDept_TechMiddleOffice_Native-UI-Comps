AnimatingNumbers 数字动画

组件 ID：ui.animating-numbers ｜ 信息展示区组件 #61 ｜ TMO 组件库 v1.9.36

定位：数值变化时以「逐位滚动」动画展示数字过渡过程的展示型组件——每位数字是一个独立滚动窗口，值变化时各位从当前字形滚动到目标字形，用于余额、收益、统计面板等金额/数值的变化呈现，双端 1:1 视觉一致。

1. 场景与边界（SCQA）

Situation 情景

记账、理财、统计面板类 App 中，金额与统计数值会因刷新/入账/筛选而跳变（如余额 0 → 12,345.68）。

Complication 冲突

数值直接替换显示过于生硬，用户来不及感知"数字变了多少"；业务想加动画又没有统一实现——手写逐位滚动在各页面重复，缓动时长、位数对齐、千分位分隔符是否参与滚动，双端各自实现必然漂移。

Question 问题

需要一个数字滚动动画展示件，统一「位数对齐 + 逐位滚动 + 千分位分隔 + 延迟/时长控制」，并与库内静态金额排版件（Price）职责互不重叠。

Answer 方案

AnimatingNumbers 数字动画——value 数值驱动的逐位滚动展示件：每位数字为一个竖排 0~9 的定高滚动窗口，挂载后延迟 delay、在 duration 内从 0 滚到目标值；length 控制最大位数（不足前补 0），thousands 决定千分位分隔符（分隔符不参与滚动）。

2. 组件边界与划界

组件职责与 AnimatingNumbers 划界
Price #72静态金额排版（前缀+货币符号+整数+小数+后缀）Price=静态排版，不含任何动画；AnimatingNumbers=数值滚动过渡。组合用法=宿主用 Price 排「符号/前后缀」，其数值部分替换为 AnimatingNumbers（Price 规格第 2 节已登记「数字动画=二期」即本件）
CountDown #60倒计时：按时间戳自驱每秒递减刷新CountDown=时间自驱（秒级持续跳动，无终值语义）；AnimatingNumbers=值驱动的一次性过渡（外部给目标值，滚到位即停）
Progress #74 / CircleProgress #58进度条/环形进度进度件以「长度/角度」表达比例；AnimatingNumbers 只表达数值本身的字形变化
InputNumber #44数字步进输入InputNumber=可交互输入；AnimatingNumbers=纯展示不可交互
Skeleton #53加载占位骨架Skeleton=数据未到位时的灰块占位（无真实数值）；AnimatingNumbers 展示的是真实数值

4. 决策投票表（ACE 模型：选项 / 评估后果 / 选最优）

编号决策点选项（Alternatives）评估后果（Consequences）选最优（Evaluate）理由
P1字号档位 A. 复用 Price 的 size 三档（small/medium/large）+ medium 默认 18
B. 只暴露裸 fontSize 数值		 A. 与库内 Price 尺寸语言一致，宿主切换档位无需换算；medium 18 略高于库内 sizeLg(16)、低于 sizeXl(22)=数字动画专用档
B. 灵活但双端各写数值易漂移，且与库内档位语言脱节		 A 保持库内尺寸语言统一；medium 字号 18/窗口高 32 为注释锚定的数字动画专用档，small/large 复用 sizeSm(14)/sizeDisplay(32)
P2动画时长单位 A. duration 毫秒（默认 1000ms）+ delay 毫秒（默认 300ms）
B. 秒（NutUI 原样，duration 默认 1s）		 A. 双端毫秒是库内动画惯例（Switch 180ms / Drag 250ms），与 Android Compose tween 的 Int 毫秒参数直通、iOS DispatchTimeInterval.milliseconds 直通
B. 浮点秒在两端都要乘 1000，多一次换算易错		 A 库内动画参数统一毫秒；默认值等价于 NutUI（delay 300ms / duration 1000ms）
P3value 变化时各位起点 A. 每位都从 0 重新滚到目标位（NutUI 行为）
B. 每位从"当前位"滚到目标位（就近滚动）		 A. 视觉统一（整串数字一起"刷"一遍），实现简单，位数增减时不会出现位错位
B. 更省动画，但位数变化（如 99 → 12345）时新旧位对不齐，需额外补位逻辑，且 tween 起点随值漂移难断言		 A 对齐 NutUI 且行为可断言（每次 value 变化 = 全体从 0 起滚）；C1 单测可锁定"值变化后初始偏移=0"
P4千分位分隔符是否参与滚动 A. 分隔符独立静态渲染（不滚动）
B. 分隔符也作为一位参与竖排滚动		 A. 分隔符本质是标点，滚动会产生无意义字形穿插，且长度计算简单（按位插入）
B. 视觉混乱，且分隔符位滚动目标无意义		 A 分隔符静态渲染、颜色可独立覆盖（separatorColor），与 NutUI 一致

6. 平台差异预告

差异点iOS（UIKit）Android（Compose）判据
滚动驱动器UIViewPropertyAnimator 驱动每位数位列的 transform 位移（startAnimation(afterDelay:) 实现 delay；value 变化先全体归零再重滚）Animatable(0f→1f) + graphicsLayer translationY（draw-phase 直读 state）实现差异，起止状态与时长语义相同=结果一致，表内放行
缓动曲线UICubicTimingParameters(controlPoint1: 0.4,0 / controlPoint2: 0.2,1)tween(durationMillis, easing = FastOutSlowInEasing)同一 cubic-bezier(0.4, 0, 0.2, 1) 曲线，视觉一致放行
等宽数字UIFont.monospacedDigitSystemFontFontFeature "tnum"结果一致（滚动宽度不抖动）放行
数字窗口结构UIView + clipsToBounds + 竖排 UILabel(0~9)Box + clipToBounds + Column { Text(0..9) }结构同构，放行
duration/delay 单位DispatchTimeInterval.millisecondstween(durationMillis = …) / withContext delay库内统一毫秒，放行

行为契约（C1 单测断言点）

#契约断言方式
B1挂载后 delay 内不滚动、delay+duration 后到达目标字形Robolectric 主时钟推进 delay 前断言偏移=0、推进 delay+duration 后断言显示文本=目标值
B2value 变化 → 全体从 0 重滚到新目标（P3-A）值变化瞬间断言初始偏移=0
B3length 补 0：value=12、length=4 → 显示「0012」文本断言
B4thousands：value=1234.5 → 显示「1,234.5」，分隔符位数不计入 length 补位文本断言
B5非法值 fallback「0」不崩溃传 NaN/空串断言不抛异常
B6小数位与整数位均逐位滚动；小数位数随 value 变化（无强制截断）文本断言（本件不负责小数位格式化，格式化归 Price）

anti_goals（一期不做）

货币符号 / 前后缀 / 小数位格式化归 Price #72，本件只滚数字（宿主可组合 Price 与 AnimatingNumbers）
循环播放 / 定时刷新值驱动一次性过渡；周期刷新归 CountDown #60 或宿主
数字字形自定义（字体替换/手写体）二期
滚动结束回调一期不提供（动画视觉件，业务无需感知）；如需由宿主按 duration 自行计时
