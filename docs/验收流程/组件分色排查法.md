# 组件分色排查法 · 视觉定位 Layout 问题通用方案

> 定位：**非客户端背景同学定位 UI Layout 问题的通用方法论**。当一个视觉现象
> （空白块、错位、点击态断层、横竖屏差异）无法一眼看出根因时，先用颜色把组件
> 各组成部分涂出来，让"现象→根因"的归因从猜测变成肉眼可判。
>
> 来源：Cell v1.23-v1.27 横屏"白色块点击不变灰"问题两天排查过程提炼。
> 同类历史教训见 `regression-lessons-cell-demo.md`（双端对称性/自动化门禁）。

---

## 一、为什么需要这套方法

**痛点**：非客户端背景同学（产品/设计/业务方）看 UI 现象时，无法把"看到的白色块"
对应到代码里的某个视图层级。沟通只能靠描述"前面后面有块白的"，Agent 拿到的信息
不足，只能靠数学推导 + 多版本试错，耗时长（Cell 案例两天）。

**解法**：先把组件的**组成结构**讲清楚（有哪些层），再给每层涂**不同诊断色**，
让用户实机一眼看出"哪个颜色的区域出问题了"，直接定位到代码里的视图层级。

**效果**：Cell v1.25 引入诊断色后，用户一次反馈"红色块"即锁定根因
（contentView 没充满 cell），v1.26 当版修复，从两天试错降到一轮定位。

---

## 二、适用场景

| 场景 | 是否适用 | 说明 |
|------|----------|------|
| 空白块/多余区域 | ✅ 强适用 | 直接看出多余区域是哪一层的背景 |
| 点击态断层（部分变灰部分不变） | ✅ 强适用 | 变灰区在点击目标内、不变灰区在外，一眼区分 |
| 横竖屏/尺寸切换后布局异常 | ✅ 强适用 | 切换后看哪一层没跟随尺寸变化 |
| 文字/图标错位 | ⚠️ 辅助 | 颜色能定位到层级，但像素级错位仍需约束排查 |
| 颜色/主题问题 | ❌ 不适用 | 本身就是颜色问题，诊断色会干扰 |
| 逻辑/数据问题 | ❌ 不适用 | 非视觉布局问题 |

## 三、实施步骤（5 步）

### 步骤 1 · 拆解组件组成结构

先列出组件由哪些视图层级组成，画成树状图（用户能看懂的结构，不是完整视图树）。

**Cell 示例**：
```
Cell（UITableViewCell）
├─ contentView（系统容器，点击态变灰的目标）
│   ├─ iconView（左侧图标）
│   ├─ textStack（中间文本列）
│   │   ├─ titleLabel（主标题）
│   │   └─ subtitleLabel（副标题）
│   ├─ valueLabel（右侧值）
│   ├─ arrowView（右侧箭头）
│   └─ divider（底部分隔/间隙）
└─ cell 自身背景（contentView 没充满时透出）
```

**关键**：要包含「容器层级」（contentView/cell 自身/tableView 父视图），不只是
内容子视图——空白块往往来自容器层级没充满。

### 步骤 2 · 分配诊断色

给每个层级分配一个高饱和、易区分的系统色。推荐用 `UIColor.system*` 系列
（iOS）/ `Color(0xFF...)` 醒目色（Android），避免用 AppColor 主题色（会被主题覆盖）。

**标准色卡**（按层级从外到内）：

| 颜色 | iOS | Android | 分配给 |
|------|-----|---------|--------|
| 红 `.systemRed` | `0xFFFF0000` | cell/根容器**自身背景** |
| 蓝 `.systemBlue` | `0xFF0000FF` | contentView/直接容器 |
| 黄 `.systemYellow` | `0xFFFFFF00` | 文本列容器（Stack） |
| 橙 `.systemOrange` | `0xFFFF9800` | 单个 Label/文字视图 |
| 紫 `.systemPurple` | `0xFF9C27B0` | tableView/父列表背景 |
| 绿 `.systemGreen` | `0xFF4CAF50` | 备用（图标/装饰视图） |

**原则**：外层用暖色（红/橙），内层用冷色（蓝/紫），容器用中间色（黄/绿），
便于从色相判断层级深浅。

### 步骤 3 · 涂色代码模板

涂三个地方，缺一不可：

```swift
// ① init 时涂容器背景
backgroundColor = .systemRed          // cell 自身
contentView.backgroundColor = .systemBlue  // contentView
textStack.backgroundColor = .systemYellow   // 文本列
titleLabel.backgroundColor = .systemOrange   // 单个 label

// ② apply/绑定数据时保持诊断色（否则会被业务色覆盖）
//   只在禁用/特殊态用业务色，正常态保持诊断色
contentView.backgroundColor = disabled ? AppColor.gray4 : .systemBlue

// ③ setHighlighted/点击态保持诊断色（否则松手恢复就看不到了）
contentView.backgroundColor = highlighted ? AppColor.gray4 : .systemBlue
```

**Android Compose 模板**（用 `Modifier.background()`）：
```kotlin
Box(Modifier.background(Color.Red)) {           // 根容器红
    Box(Modifier.background(Color.Blue)) {       // 内层容器蓝
        Column(Modifier.background(Color.Yellow)) {  // 文本列黄
            Text("title", Modifier.background(Color.Orange))  // label 橙
        }
    }
}
```

### 步骤 4 · 用户实机反馈

用户实机看现象，按色卡反馈："出问题的是 X 色块"。

**反馈话术模板**（教用户怎么说）：
> "横屏后 Cell 前面和后面多出来的区块是 **红色**"

Agent 收到颜色后，直接对照色卡定位到代码层级，无需猜测。

### 步骤 5 · 定位根因 + 修复

按颜色 → 层级 → 根因的路径定位：

| 反馈颜色 | 对应层级 | 常见根因 |
|----------|----------|----------|
| 红 | cell/根容器自身背景 | 内层容器没充满根容器，根背景透出 |
| 蓝 | contentView/直接容器 | 容器内有空白未被内容填满，或点击态未覆盖该区 |
| 黄 | 文本列容器 | 文本布局异常（行高/居中）撑出空白 |
| 紫 | tableView/父列表 | cell 之间出现列表间隙，cell 宽度没跟随列表 |
| 橙 | 单个 label | 文字本身渲染区异常 |

**Cell 案例定位链**：
红色 → cell 自身背景 → contentView 没充满 cell → 查 contentView 宽度来源 →
发现 `insetsContentViewsToSafeArea` 默认 true，横屏 safeArea 把 contentView inset →
根因锁定。

### 步骤 6 · 收尾移除诊断色

修复验证通过后，**当版移除所有诊断色**恢复 AppColor 主题色，做正式收尾版。
诊断色是临时排查手段，不进正式版（会污染主题）。

## 四、Cell 案例完整复盘（v1.23-v1.27）

### 4.1 问题现象

> Cell v1.24 横屏后 Cell 前后出现白色区块，竖屏无此问题；点击 Cell 主体变灰，
> 但前后区块不变灰。

### 4.2 试错阶段（v1.23-v1.24，纯数学推导，效率低）

| 版本 | 尝试 | 结果 |
|------|------|------|
| v1.23 | 移除 centerY 与 top/bottom 约束冲突，仅用 centerY+height | 主体正常，但横屏仍有白色块 |
| v1.23 | 临时改绿色背景排查 | 暴露 cell 内部空白（绿色铺满），但仍无法定位区块来源 |
| v1.24 | 改回 bgCard + 仅标题设行高 24pt | 白色块依旧，文字居中修复 |

**效率低的根因**：纯数学推导约束冲突，没看到"白色块"到底是哪一层的背景，
反复试错 4 个版本仍定位不到。

### 4.3 分色定位阶段（v1.25，一轮锁定）

引入组件分色排查法，给 5 个层级涂不同色：

| 层级 | 颜色 | 涂色代码 |
|------|------|----------|
| cell 自身背景 | 红 | `backgroundColor = .systemRed` |
| contentView | 蓝 | `contentView.backgroundColor = .systemBlue` |
| textStack | 黄 | `textStack.backgroundColor = .systemYellow` |
| titleLabel | 橙 | `titleLabel.backgroundColor = .systemOrange` |
| tableView 父背景 | 紫 | `tv.backgroundColor = .systemPurple` |

**用户一次反馈**：横屏后 Cell 两侧多出的区块是**红色**。

**立即定位**：红色 = cell 自身背景 → contentView 没充满 cell → 查 contentView 宽度
来源 → 锁定 `insetsContentViewsToSafeArea` 根因。

### 4.4 修复 + 收尾（v1.26-v1.27）

| 版本 | 动作 | 结果 |
|------|------|------|
| v1.26 | 重写 layoutSubviews，super 后强制 `contentView.frame = bounds` | 实机验证通过，无红色块 |
| v1.27 | 移除诊断色恢复 AppColor + Demo2 箭头配置修正 | 正式收尾 |

### 4.5 根因总结

`UITableViewCell.insetsContentViewsToSafeArea` 默认 true（iOS 11+），横屏时
iPhone X+ 系列 safeArea 左右各 44pt，系统把 contentView inset 到 safeArea 内，
cell 两侧（safeArea 外）露出 `cell.backgroundColor`，形成"白色块点击不变灰"
现象（区块在 contentView 外不受 setHighlighted 影响）。竖屏 safeArea 左右=0
故无此问题。

## 五、注意事项

1. **诊断色必须用系统高饱和色**（`.systemRed`/`.systemBlue` 等），不要用 AppColor
   主题色——主题色会被主题切换覆盖，且与业务背景混淆。
2. **三个地方都要涂**：init、apply/绑定、点击态回调。只涂 init 会被业务数据覆盖，
   看不到诊断色。
3. **修复验证通过后当版移除**：诊断色是临时手段，不进正式版。收尾版同时升版本号
   记录"曾用诊断色排查"。
4. **拆解结构要包含容器层级**：不只涂内容子视图，cell/contentView/tableView 等容器
   层级是空白块的常见来源，必须涂。
5. **与自动化门禁互补**：分色排查法用于"现象→根因"的肉眼定位；定位后把根因固化为
   单测/ORC 门禁（见 `regression-lessons-cell-demo.md`），防止回归。
6. **适用范围**：视觉布局问题。逻辑/数据/颜色主题问题不适用，不要滥用。

## 六、色卡速查（打印贴墙）

```
红 = 根容器自身背景（内层没充满时透出）
蓝 = 直接容器（contentView/Box）
黄 = 文本列容器（Stack/Column）
橙 = 单个文字视图（Label/Text）
紫 = 父列表/页面背景（tableView/Scaffold）
绿 = 备用（图标/装饰）
```

**反馈话术**："X 现象中，出问题的区域是 [颜色]，对照色卡是 [层级]。"
