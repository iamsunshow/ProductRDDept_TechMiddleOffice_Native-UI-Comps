01 组件用途与能力范围

一句话：以统一 API 渲染图片内容（本地资源 / 平台图像对象），提供对象填充模式、占位与事件，替代裸 UIImageView / Compose Image 的重复样板。
能力（对齐 NutUI）说明本期范围
src 图片来源本地资源名 / 平台图像对象（iOS UIImage、Android ImageBitmap|Painter|@DrawableRes）；网络 URL 加载为独立决策点（见 08）✅ 本地
fit 填充模式fill 拉伸铺满 / contain 完整显示 / cover 等比裁剪铺满 / none 原始尺寸 / scale-down 不放大缩小✅ 全 5 值
position 对齐center|top|right|bottom|left（配合 contain/none 时的内容停靠）✅ 全 5 值
width / height显式布局尺寸（逻辑 pt/dp）；不传则撑满父容器✅
radius 圆角默认 0（直角）；可引 token 档位（6/10/14）或传任意数值；radius = 宽/2 即圆形（头像场景）✅
alt无障碍描述 → iOS accessibilityLabel / Android contentDescription✅
loading 占位加载期间占位：默认样式（灰底 + 呼吸扫描 + 转圈）；可传自定义占位内容✅
error 占位加载失败占位：默认样式（灰底 + 破图图标 + 「加载失败」）；可传自定义占位内容；可选失败重试（点击）✅
lazy 懒加载滚动进入可视区才加载⏭ 一期 N/A（依赖滚动容器，双端需自实现可视区检测，见 08）
事件onTap 点击 / onLoad 加载完成 / onError 加载失败✅
图片预览（放大查看）NutUI 由独立 ImagePreview 组件（本库 #68）提供，Image 不内置⏭ 不越界
定位边界：本组件是「显示容器」，不做图片裁剪/编辑/上传；网络加载、缓存策略是基础设施能力，与本组件解耦（见 08 决策点）。

02 五态定义

有视觉组件五态对齐：默认 / 禁用 / 加载 / 成功 / 失败。图片的「成功态」即加载完成后的正常渲染（与默认态视觉一致，区别在生命周期）。
默认 Default
禁用 Disabled
N/A —— 图片无「禁用」语义；需要置灰/不可点时由外层容器控制（组件不产禁用手势态）
加载中 Loading
成功（加载完成）Success
= 加载成功即正常渲染（onLoad 触发），视觉同默认
失败（加载失败）Error
✕
加载失败
占位语义：默认占位使用 bgCard 底 + gray.* 图形 + 说明文字（字号引用 font.sizeSm 14），不依赖未完成的 Icon/Loading 组件（组件库 #4/#50），零 deps；Icon/Loading 组件落地后可替换默认占位为组件化实现（向后兼容，非 breaking）。

03 尺寸规格（token 引用）

布局尺寸（宽/高）由业务决定（头像 40、缩略图 80、banner 320…）；组件自身装饰性尺寸全部引用 design-token。

04 交互细节 · 填充模式与对齐

fit（内容铺排）与 position（内容停靠）等同原生 object-fit / object-position，双端以系统能力直接映射（iOS contentMode、Android ContentScale + alignment），无自绘、无误差。
fill拉伸铺满
contain完整显示
cover等比裁剪
none原始尺寸
scale-down取小
position 停靠（fit=none / contain 且容器大于内容时生效；fit=fill/cover 时内容已铺满容器，position 无视觉影响）：
position行为映射（双端）
center（默认）内容在容器内水平垂直居中，四周对称留白iOS contentMode = .center / .top / .right / .bottom / .left；Android ContentAlignment = Center / TopStart(或 TopCenter) / …——position 全部为「单边或居中」停靠，无居中+单边组合，双端映射一一对应，见 平台差异.md
top顶对齐（水平居中）
bottom底对齐（水平居中）
left左对齐（垂直居中）
right右对齐（垂直居中）
交互细节：① 点击：可选 onTap 回调（默认无点击态背景变化，避免「图片按钮」误判；需要按压反馈时由外层包 Button/手势层）；② 加载/失败不阻塞布局（容器尺寸始终为 width×height，占位在容器内层切换，不抖版）；③ 失败后再次设置 src 自动重新加载（重置 loading→success/error）；④ 无 hover 语义（触屏优先），iOS 3D Touch / Android 长按由外层手势层扩展。

07 待决策点（门禁 A 评审拍板，写进 API 契约/anti_goals）

决策点选项建议
P1 · 网络图 URL 加载 A. 一期支持（iOS 原生 URLSession+NSCache；Android 引 Coil）
B. 一期仅本地（URL 抛业务侧预下载后传图对象），二期双端统一加载方案
C. 一期 iOS 支持、Android N/A		 建议 B：保持组件库零第三方依赖与双端一致；网络头像/封面属少数场景，业务侧（KeepAccounts 等）通常已有预取链路，传 UIImage / ImageBitmap 即可；B 也避免「Android 引 Coil、iOS 原生」的双端加载语义分裂（缓存/失败重试行为难对齐）
P2 · lazy 懒加载 A. 一期实现（双端滚动可视区检测）
B. 一期 N/A，标注缺口		 建议 B：lazy 依赖宿主滚动容器（UICollectionView/RecyclerView 各自 prefetch 语义不同），双端自实现可视区检测成本高且易出滚动 bug；本地资源图无网络代价，lazy 收益集中在长列表网络图（P1=B 后自然 N/A）
P3 · 圆形快捷方式 A. 仅 radius=数值（宽/2 即圆形）
B. 额外 radius="circle" 快捷值		 建议 A：抽象 props 少一个魔法值，圆形=radius=宽/2 语义直白；双端实现均免特判
P4 · 失败重试 A. 默认 error 占位可点击重试（内部自动重载）
B. 仅暴露 onError，重试由业务改 src 触发		 建议 B：与 NutUI 对齐（无内置重试）；本地资源失败=代码错，重试无意义；URL 场景（P1=B）重试也归业务加载层
