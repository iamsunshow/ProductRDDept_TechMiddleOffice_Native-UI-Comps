## 三、关键决策与依据（后续 Agent 勿推翻）

1. **v1.9.40 不构成版本倒挂**：v1.9.40 是库名为 `components`（旧名）时代的发版 tag；`tmo-native-ui-comps` 新名序列自 v2.0.0 起（commit `dab8a3f` 改名）。用户指令「应该是从 1.x.x 开始」后，新名序列改标 v1.0.x，与 v1.9.40 分属不同产品标识，语义无冲突。
2. **Package.resolved 被 .gitignore 忽略是仓库既有约定**：组件库用 `exactVersion` 精确约束，克隆后重解析无漂移风险；隐患仅在第三方非精确依赖（Charts upToNextMajor 4.1.0 / Alamofire 5.x 等）跨机器解析可能不一致。**用户已知悉，未要求入库**；若后续要求可复现构建，再将其移出 .gitignore。
3. **xcodegen 不可用**（本机无此命令）：iOS 工程的 SPM 版本变更需**手工三处同步**：`project.yml`（源）→ `project.pbxproj`（exactVersion）→ `Package.resolved`（revision 用 tag 完整 40 位 hash）。
4. **GitHub Packages 上已发布的 `2.0.12` AAR 无法删除**（Maven 构件不可覆盖不可清理），留存但不被引用，无实际影响。`1.0.12` 已发布成功（第二次发布 409 Conflict = 已存在，即为发布成功证据）。

## 四、踩坑记录（重要，勿重蹈）

1. **全局批量 sed 误伤**：`sed -E 's/2\.0\.([0-9]+)/1.0.\1/g'` 误伤了：
   - `ios/Vendor/**`（第三方库 CHANGELOG、**png 二进制**）
   - `www/pnpm-lock.yaml`
   - `.gitignore`
   - **Kotlin 插件版本 `2.0.21` → `1.0.21`**（libs.versions.toml、demo 两个 gradle、Overlay.kt 注释）
   - 教训：版本号批量替换**必须白名单限定文件清单**，替换后全局 grep 残留 + 误伤特征（如搜 `1.0.21`）双重复核。本次已全部回滚修复，终检干净。
2. **zsh 下 `git tag x v2.0.0^{commit}` 报 no matches**：`^{...}` 被 zsh 当 glob，直接 `git tag 新 旧tag名` 即可（自动 deref 到 commit）。
3. **git grep 中文路径带引号转义，sed 报 No such file**：必须用 `git grep -lz ... | xargs -0 sed`。
4. **网络间歇性故障**（DNS 解析 github.com 失败、Recv failure 超时）：push/ls-remote/xcodebuild 解析可能随机失败，**重试即可**；用端到端解析（SPM checkout / Gradle dependencies）作为远端可达性的权威验证，不要只信 ls-remote。
5. **宿主 Android 依赖验证**：`./gradlew :app:dependencies --configuration debugRuntimeClasspath | grep zhiqihuayun`，无 `FAILED` 即解析成功。
