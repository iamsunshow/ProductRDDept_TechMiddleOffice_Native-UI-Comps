## 二、流程规范修正（重要）

### 2.1 状态流转规范（2026-09-11 用户强调）

**开发完 ≠ 已通过**。状态流转：

```
⬜ 未开始 → 📐 设计中（门禁A） → 📋 已评审（门禁A/B/C1通过+编译通过，待C1.5验收） → ✅ 已通过（C1.5用户验收通过）
```

- **📋 已评审**：门禁 A/B/C1 通过 + 双端编译验证通过，但用户尚未 C1.5 Demo 实机验收
- **✅ 已通过**：用户 C1.5 Demo 实机验收通过后才能翻 ✅
- **禁止**：开发完直接标 ✅

### 2.2 Demo 状态标记语义（iOS/Android 统一）

| 标记 | 颜色 | 含义 |
|------|------|------|
| `passed=true` | 绿色 | 已通过（C1.5 用户验收通过） |

## 五、关键约束与经验（后续 Agent 必读）

### 5.1 版本号管理

- 全局版本号在 `docs/数据与产物/ui-version.json` 的 `version` 字段
- 双端版本永远一致，禁止手工改工程内版本
- 版本变更同步更新 CHANGELOG.md
- **子 agent 不得自行修改版本号和 CHANGELOG**，由主线程统一合并避免冲突

### 5.2 并行开发约定

- 多组件并行时，各子 agent 完成门禁 A→B→C1+Demo，独立编译验证通过后报告
- 版本号和 CHANGELOG 由主线程统一合并更新

### 5.3 api.json reviewed 字段

- `reviewed=true` 必须在用户 C1.5 Demo 实机验收通过后才能设置
- 门禁 B（api.json 契约登记）阶段不设 reviewed=true

### 5.4 submodule 推送顺序

1. 先 `git push` 子仓（Native-UI-Comps）
2. 再 `git push` 主仓（OPC）
- 子仓路径：`ProductRDDept/TechMiddleOffice/Native-UI-Comps`

### 5.5 编译验证命令

```bash
# Android
cd ProductRDDept/TechMiddleOffice/Native-UI-Comps/demo/android
./gradlew assembleDebug

# iOS
cd ProductRDDept/TechMiddleOffice/Native-UI-Comps/demo/ios
xcodebuild -project ZhiqihuayunDemo.xcodeproj -scheme ZhiqihuayunDemo -destination 'platform=iOS Simulator,name=iPhone 14' build
```

### 5.6 关键修复经验

- **CountDown iOS**：`Date.timeIntervalSince1970` 是实例属性，需用 `Date().timeIntervalSince1970`
- **TrendChartView Android**：单 Canvas 统一绘制网格线+Y轴标签+折线+圆点+X轴标签，避免多层叠加覆盖
- **Demo 状态**：开发完默认无标记（已评审），用户验收通过后才加 `passed=true`
