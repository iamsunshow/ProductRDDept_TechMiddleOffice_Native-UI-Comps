HoverButton 悬浮按钮 · 设计规格（导航组件 #4 · 任务清单 #16，subcategory=navigation · 门禁 A）

组件 ID：ui.hover-button ｜ 定位：页面边缘常驻的"单功能悬浮动作钮"——常驻显示（无滚动阈值自动显隐）、图标字符 + 可选文本、点击交回业务回调，对标同族"悬浮按钮"语义（Material FAB 业务动作形态的库内自有设计语言版本）。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-04，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 单个业务功能入口需要"不占主内容区、页面角落常驻可点"的悬浮动作钮（发布 / 扫码 / 记一笔 / 打开工具书 / 语音），点击后由业务 onTap 自行处理（弹窗/跳转/计数器…）；② 图标钮（icon 单字符，圆形）或 图标+文本/纯文本（胶囊）两种形态按内容自适应；③ 位置由宿主锚定（右下/左下/任意），常驻不随滚动消失
不适用（N/A）① 多入口悬浮导航列表（点钮展开面板多行）→ FixedNav（ui.fixed-nav，#15）；② 长内容"回到顶部"（滚动超阈值出现 + 点击回顶）→ BackTop（ui.back-top，#13）；③ 底部主导航 Tab → Tabbar（ui.tabbar）；④ 页面顶部导航/标题 → NavBar（ui.nav-bar）
五态适配默认态 ✅ 常驻主色钮（图标单字符 圆钮 / 图标+文本或纯文本 胶囊）；交互态 ✅ 点击触发 onTap（业务自理动作，组件不代管）；禁用/加载/成功/失败 N/A（单动作入口类组件，业务态由宿主反馈承载，本期不引）
与现有组件关系deps=[DesignTokens]；悬浮钮视觉基线=BackTop 悬浮钮同族（主色底白字、圆角 full、高 40pt/dp、无图片依赖=icon 为单字符文本位）；与悬浮类划界：HoverButton=单钮常驻自定义动作（无列表、无滚动阈值）、BackTop=滚动触发回顶、FixedNav=多入口列表悬浮导航

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
icon-only 圆钮直径 40pt/40dp，圆角=直径一半（full）仅 icon 时圆形钮：主色底 + 白字单字符（如 ✚/✎），圆角随实际 bounds 动态（同 BackTop 默认钮先例），字重 bold 字号 Lg
icon+text / 纯文本 胶囊高 40pt/40dp，圆角 full，水平内边距 = AppSpace.lg（16），icon 与 text 间距 sm（8）含 text 时=胶囊钮：主色底白字，text 字号 Sm 常规字重；宽随内容自适应（不写死魔法值）
icon 字符单字符/emoji 文本（默认 "✚"，U+271A；零图片依赖）icon 一期=字符文本位（不走 Icon 组件映射，同 FixedNav/BackTop 先例；系统图标映射登记二期）
icon 缺省规则icon=null 且 text=null → 显示默认 ✚ 圆钮icon=null 仅 text 有值 → 纯文本胶囊（无 icon 位占位）；icon 有值 text 缺省 → icon-only 圆钮
位置宿主锚定（右下/左下/自定义偏移），组件常驻不自动显隐组件=纯内容视图（self 尺寸=钮内容），宿主只锚边/角即可撑开（同 FixedNav intrinsic 先例）
点击行为onTap 业务回调（必选语义：悬浮动作钮无内置动作）按压缩放/压暗反馈=平台级放行（见 §05）

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 形态与交互：ACE 三选

选项后果评估
A：单钮常驻悬浮动作钮——主色钮（icon 字符圆钮 / icon+文本或纯文本胶囊，内容自适应）+ onTap 业务回调；常驻不随滚动显隐；位置宿主锚定✅ 语义=单功能动作入口（发布/扫码/记一笔），与 FixedNav 列表面板、BackTop 回顶划界清晰；无滚动监听无浮层 API；双端同构易验收。推荐 A：范围收敛、验收直观
B：带展开面板的"单入口悬浮菜单"（点钮弹操作组）与 FixedNav 悬浮导航面板重复（FixedNav 已覆盖多入口列表），二期 HoverButton 若需动作组应并入 FixedNav。淘汰：与 FixedNav 语义重叠
C：整视图可替换 face（仿 BackTop setFace）+ 自动隐藏/角标全内置BackTop 已提供 setFace 供宿主自定义；HoverButton 再引 face 会与"icon/text 声明式"定位冲突，宿主自定义走宿主自己做。淘汰：保持声明式轻量（icon/text）

P2 · 数据模型与回调：ACE 三选

选项后果评估
A：icon: String?（缺省="✚" 默认圆钮，仅 text=纯文本胶囊）+ text: String?（缺省=nil）+ onTap: (() -> Void)?（nil=点击无动作，仅点击样式反馈）✅ 覆盖圆钮/胶囊/纯文本三形态；onTap 缺省不崩（可先验证形态再接线）；与 FixedNav/BackTop 字符位约定一致。推荐 A：契约干净、Demo 覆盖形态差异
B：icon 必填图片 URL/资源名 + 固定主色矩形资源系统强耦合，违背库内"字符文本零图片"惯例。淘汰
C：整个按钮由宿主传 View/Composable（内容插槽）组件退化为纯点击壳，形态契约失控，双端 1:1 难排查。淘汰：二期自定义插槽再评估

P3 · 圆钮/胶囊形态判定：ACE 三选

选项后果评估
A：内容驱动——text 为空=icon-only 圆形（宽=高=40）；text 非空=胶囊（高 40、圆角 full、宽=内容+padding lg）；纯文本=无 icon 位的胶囊✅ 无需新增 mode 枚举，宿主只喂 icon/text 即可得到正确形态，1:1 双端同判。推荐 A：零枚举、行为确定
B：显式 shape 枚举（round/pill）多一层 API 让宿主决定形态，且 round+长文本 会产生宽扁椭圆不成立。淘汰
C：统一固定胶囊（文本长按钮，无圆形钮）覆盖不到 icon-only 圆形悬浮钮常见诉求（扫码/语音等常用圆形）。淘汰

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：主色钮三形态（icon-only 圆钮 / icon+text 胶囊 / 纯文本胶囊）+ onTap 回调 + 常驻 + 宿主定位 + demo 四段（含与 BackTop 同容器共存划界）✅ 覆盖悬浮动作钮核心闭环；常驻语义（与 BackTop 滚动显隐对照）可在 D4 直接验证。推荐 A：验收路径清晰
B：一期即支持自定义颜色/渐变/阴影主题扩展属 token 体系职责，业务可用 ConfigProvider/自绘覆盖，非核心。淘汰：登记二期（色板自定义）
C：支持拖拽摆放 + 边界吸附手势与吸附状态双端实现重、与"位置宿主定"矛盾。淘汰：登记二期（Drag 能力评估）

05 · 平台差异表（表内放行，表外必须双端统一）

维度iOSAndroid放行原因

06 · API 草案（双端一致契约，门禁 B 据此登记 api.json）

端API
iOSfinal class HoverButton: UIView
init(icon: String? = nil, text: String? = nil, onTap: (() -> Void)? = nil)
（icon 缺省="✚"；text 非空=胶囊；内容自适应 intrinsic 尺寸=钮宽×40/40×40；宿主只锚边角即可撑开；"悬浮"由宿主置于覆盖层锚定，组件不代管布局）
Android@Composable fun HoverButton(modifier: Modifier = Modifier, icon: String? = null, text: String? = null, onTap: () -> Unit)
（icon/text 同 iOS 缺省规则；组件自身 wrap 内容不撑满父级；位置由宿主 offset/Box 摆放）
