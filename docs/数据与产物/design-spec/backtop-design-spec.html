BackTop 返回顶部 · 设计规格（导航组件 #1 · 任务清单 #13，subcategory=nav · 门禁 A）

组件 ID：ui.back-top ｜ 定位：长滚动内容（列表/长页）右下角的"回到顶部"浮层入口——滚动超过阈值出现、点击回滚到顶，对标 NutUI React BackTop。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-04，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 长列表/长表单页滚动一段距离后提供"一键回顶"（账目明细/消息流/长文阅读）；② 悬浮入口位：右下/左下角常驻（位置由宿主容器摆放）；③ 自定义内容：默认主色圆钮 ↑，可用任意视图/文案替换（如"回顶"字样、计数徽标组合）
不适用（N/A）① 吸顶类（标题/筛选条在滚动中钉顶）→ Sticky（ui.sticky）；② 常驻全局悬浮按钮（发布/扫码等业务功能按钮）→ HoverButton（ui.hover-button）；③ 页面底部标签栏 → Tabbar（ui.tabbar）；④ 交互式引导按钮、拖拽悬浮钮（Drag/HoverButton 一期范围外）
五态适配默认态 ✅ 未超阈值：隐藏（不占位、无层级）；出现态 ✅ 滚动超阈值：淡入显示；点击态 ✅ 点击回顶；禁用/加载/成功/失败 N/A（纯行为入口无业务态）
与现有组件关系deps=[DesignTokens]（默认视觉用主色/白/字号 token，零硬编码零图片依赖）。与导航批其他组件划界：HoverButton=常驻功能悬浮钮；FixedNav=悬浮导航菜单组；Elevator/SideBar=内容定位导航；Tabbar=底部标签栏；BackTop 只做"回顶"一件事

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
出现阈值 appearAfter数字 pt/dp（默认 120）滚动位移超过该值后显示（px 比较，不做单位换算魔法）
默认尺寸直径 40pt/40dp（demo 摆放值；组件不强约束，由宿主布局决定）圆角=直径一半（胶囊/圆钮），在组件内按实际 bounds 计算，不写死魔法值
默认视觉bg=主色 primary / 前景=白 / 字号 Lg 级（↑ 字符）字符 ↑（U+2191）为文本非图片，零资源依赖；全部 token 取系统色板
显隐动效一期淡入淡出（alpha 过渡，iOS .15s / Android 默认 fade）弹性/缩放动效二期候选（不引入动画引擎魔法）
位置宿主容器自行摆放（如右下 16/24 偏移）组件不自行约束，避免与宿主布局系统耦合

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 一期形态：ACE 三选

选项后果评估
A：浮层按钮模式——组件 = 悬浮按钮 + 滚动源（target scrollView / scrollState）+ 阈值 + 点击回调，位置由宿主容器在右下摆放✅ 覆盖"长页回顶"全部诉求；滚动源解耦=任意滚动容器可用（UIScrollView/UITableView/Compose 任意 scrollable）；iOS 监听 contentOffset / Android 读 scrollState 即可，双端一致。推荐 A：语义单一只做回顶，位置交给宿主（与组件库其他行为组件一致：SafeArea/Sticky 均不代管布局上下文）
B：自包含滚动容器模式（滚动+按钮封装一体，类似 StickyView）组件可 demo 即插即用，但把滚动内容构建方式锁死（用户被迫用组件内容 API），与页面既有的 LazyColumn/TableView 冲突。淘汰：过度封装，限制业务
C：自动吸底常驻（页面级全局 float，scroll 出现后始终停底部导航之上）牵涉全局定位与底部导航感知，双端各需页面容器约定。淘汰：一期以容器内浮层为主，页面级全局位登记二期

P2 · iOS 实现路径：ACE 三选

选项后果评估
A：KVO 监听 target.contentOffset 驱动显隐 + 点击 setContentOffset(.zero, animated:)✅ 不占用业务 delegate；UIView.animate alpha 平滑淡入；回顶使用系统滚动动画与既有滚动体验一致。推荐 A：行为确定、代码最少
B：UIScrollViewDelegate scrollViewDidScroll 回调若业务已设 delegate 则需转发链，宿主约束多。淘汰：KVO 更松耦合
C：CADisplayLink 自驱平滑滚顶（自定义缓动）与系统滚动动画手感/打断行为难对齐，维护成本高。淘汰：登记二期（如要自定义缓动再评估）

P3 · Android 实现路径：ACE 三选

选项后果评估
A：参数 scrollState（ScrollState/LazyListState 派生）+ SnapshotFlow 监听 + scrollState.animateScrollTo(0)✅ 与任意 Column/LazyColumn 组合；滚动值驱动重组即显隐；动画与系统一致。推荐 A：Compose 惯用、无额外耦合
B：组件内部自建 LazyColumn 容器（list 内容直接喂组件）与 iOS 浮层模式不对齐（iOS 不代管内容）。淘汰：破坏双端同构
C：Scaffold/Box 级全局 FloatingActionButton 替代语义变为 Material FAB，非组件库自有设计语言。淘汰：用组件自有视觉

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：默认视觉（主色圆钮 + ↑）+ 内容可替换 + 阈值可配 + 点击回调（默认回顶）✅ demo 四段可 1:1 验收；默认视觉覆盖 90% 场景，自定义兜底剩余。推荐 A：范围收敛
B：一期即支持拖拽自由摆放手势冲突/边界吸附复杂，且与"位置宿主定"矛盾。淘汰：登记二期（配合 Drag 能力评估）
C：多滚动源绑定（同按钮服务多滚动区）罕见需求，双端状态管理复杂。淘汰

05 · 平台差异表（表内放行，表外必须双端统一）

维度iOSAndroid放行原因
滚动源UIScrollView 引用（KVO contentOffset）ScrollState 参数（snapshotFlow 派生）系统级原生差异：两端滚动模型不同（对象引用 vs 状态快照）
回顶动画setContentOffset(.zero, animated: true)scrollState.animateScrollTo(0)系统级原生差异：各自系统滚动动画
显隐过渡UIView.animate(alpha)AnimatedVisibility(fadeIn/fadeOut)系统级原生差异：动画 API 不同
出现阈值判定offset.y > appearAfterscrollState.value > appearAfter语义一致：均为 px 位移比较（表内放行）
默认 ↑ 字符UILabel/Button 文本 ↑Text("↑")同一字符不同端渲染（表内放行）
