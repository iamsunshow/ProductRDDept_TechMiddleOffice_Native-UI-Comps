Notify 消息通知 · 设计规格（操作反馈区 #52 · 门禁 A）

组件 ID：ui.notify ｜ 定位：顶部/底部全局消息通知浮层——命令式 API（Notify.show()）+ 自动消失（duration）+ 可关闭+左右图标 slot，对标 NutUI React Notify + Vant Notify。
组件库版本 设计阶段锁定基线 = v1.4.3（2026-09-08，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 顶部/底部全局消息通知浮层（轻量级、非阻断式反馈）；② 命令式 API（Notify.show() / Notify.clear()）；③ 自动消失（duration 默认 3000ms，0=常驻）；④ 双位置（top/bottom）+ distance 距离；⑤ 可关闭 closeable（右侧 ×+onClose 回调）；⑥ 左右自定义图标 slot
不适用（N/A）① 页面内嵌公告栏 → NoticeBar（ui.notice-bar）#51（页面内嵌占位 vs Notify 全局浮层）；② Toast 轻提示 → Toast（ui.toast）#59（Toast=纯文本居中 vs Notify=顶部/底部带图标）；③ Dialog 弹窗 → Dialog（ui.dialog）#46（Dialog=阻断式 vs Notify=非阻断）；④ Loading 加载 → Loading（ui.loading）#50
五态适配默认态 ✅ 显示+自动消失；禁用 N/A（Notify 是瞬态浮层，无"禁用"语义）；其余态 N/A
与现有组件关系deps=[DesignTokens, Overlay #6]。与 NoticeBar #51 划界：NoticeBar=页面内嵌占位栏（持续展示，需手动关闭或 scrollable 循环），Notify=全局浮层（自动消失，不占位）；与 Toast #59 划界：Toast=纯文本居中（屏幕中央），Notify=顶部/底部带图标+背景色；与 Overlay #6 划界：Overlay=通用遮罩层，Notify=消息通知（基于 Overlay/keyWindow 挂载，但非全屏遮罩）

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 一期形态：ACE 三选

选项后果评估
A：命令式 API（Notify.show() / Notify.clear()）+ 全局浮层+自动消失+可关闭+左右图标 slot✅ 与 NutUI/Vant Notify 命令式 API 一致；全局 keyWindow 挂载+自动消失+top/bottom 位置+distance 距离+navHeight 适配推荐 A：命令式是 Notify 标准用法
B：声明式组件（）需宿主管理 visible 状态，不符合 Notify 命令式调用习惯。淘汰：命令式是标准
C：Toast 样式（屏幕居中纯文本）与 Toast #59 职责重叠。淘汰：归 Toast

P2 · 一期范围裁剪：ACE 三选

选项后果评估
A：命令式 API+top/bottom+distance+navHeight+duration+closeable+leftIcon/rightIcon+type(primary/success/warning/danger)+Demo 4 组✅ 覆盖 NutUI 全部主流 props；type 变色补充 NutUI 缺失（NutUI 需 CSS 变量，一期直接 API 参数化）推荐 A：范围收敛但覆盖完整
B：一期仅 top 位置（无 bottom）缺 bottom 位置场景，与 NutUI position=bottom 对不齐。淘汰：bottom 是基础
C：一期即支持自定义内容 slot（JSX.Element/UIView 传入）增加复杂度，一期无强需求。淘汰：登记二期

P3 · iOS 实现：ACE 三选

选项后果评估
A：静态方法 Notify.show()→ keyWindow 挂载 UIView+Timer 自动消失✅ 命令式调用，keyWindow 挂载确保全局顶层；Timer duration 后 removeFromSuperview；navHeight 适配 safeArea+navHeight推荐 A：keyWindow 挂载是全局浮层标准
B：UIViewController present需 present/dismiss 生命周期管理，多余。淘汰：直接 keyWindow 挂载
C：UIAlertController系统样式不可定制。淘汰：自定义 UIView

P4 · Android 实现：ACE 三选

选项后果评估
A：单例 Activity contentHost 挂载 Compose+LaunchedEffect delay 自动消失✅ 命令式调用，Activity findViewById(android.R.id.content) 挂载；LaunchedEffect duration 后移除；navHeight 适配 statusBar+actionBar推荐 A：contentHost 挂载是全局浮层标准
B：Dialog/Popup需 dismiss 生命周期，多余。淘汰：直接 contentHost 挂载
C：Toast 系统组件系统样式不可定制。淘汰：自定义 Compose
