TextArea 文本域 · 设计规格（数据录入组件 #42 · 任务清单 #42，subcategory=form · 门禁 A）

组件 ID：ui.textarea ｜ 定位：通用多行文本输入内容组件（受控）——宿主容器给定宽度（表单内容槽/页面布局），TextArea 提供文本域壳（灰底圆角多行输入区，沿用 Input #29 壳视觉语言）+ placeholder（顶部左对齐）+ 受控 value/onTextChange + rows 可视行 + 内部滚动 + maxLength（输入路径截断）+ disabled；label/必填/校验文案/字数统计/提交=宿主职责。对标 Ant Design TextArea 收敛为库内自有设计语言；业务端备注/简介类多行录入迄今为宿主直拼系统控件未沉淀=本件双端纯从零（视觉语言对齐已收编 Input #29）。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-06，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 表单单字段多行文本录入（个人简介/备注/留言/收货说明/地址详情等，置于 FormFieldRow #28 内容槽，行高随控件撑开）；② 页内长文本编辑（意见反馈/补充说明）；③ 受控回显：宿主持 value 预填/清空/追加外部驱动（编辑页、草稿恢复）
不适用（N/A）① 富文本/格式文本（加粗/颜色/图片粘贴/提及@/表情面板）→ 专项组件或宿主自研；② 自动增高（autoGrow 随输入撑高）→ 二期（一期固定可视行+内部滚动）；③ 字数统计角标 → 宿主或二期（宿主读 value 自理=展示语义归宿主）；④ 单行输入/掩码/键盘类型/尾槽/清除钮 → ui.input #29（Input=单行文本域、TextArea=多行文本域=同一壳语言的两形态）；⑤ label/必填星/帮助/错误文案 → FormFieldRow #28 职责（TextArea 壳内不嵌 label/error，校验态壳不变红）
五态适配默认态 ✅ 空值=placeholder 灰字（textSecondary）顶部左对齐；输入态 ✅ 值 textPrimary Md16 行高 24 多行换行+原生光标；聚焦态 ✅ 壳视觉不变（灰底无边框），光标与系统键盘为原生聚焦反馈（无额外描边强调=二期可加 primary 细边方案）；禁用态 ✅ 整壳 textSecondary 40% 灰、不可编辑不可滚动不可聚焦（已填灰文可读）；错误/校验态=FormFieldRow 行内红字呈现（壳不变红=表单语义归 Form）
与现有组件关系deps=[DesignTokens]；与 Form #28=TextArea 作为内容槽放入 FormFieldRow（label/错误行）+ 宿主定宽定高；与 Input #29=同壳语言同受控模型同 maxLength/disabled 惯例（单行→多行形态）、复用为升级路径；键盘弹出避让=宿主页面容器职责（滚动/inset，双端同语义）

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
文本域壳底 bgPage 灰（无描边无阴影）；圆角 lg（radius lg=同 Input #29 壳）；内边距 md（12）四向（上下与左右一致=内容与壳留白呼吸感）灰底圆角多行输入区=库内输入壳视觉（与 Input 灰底圆角条同语言，仅单行 48→多行按行排版）
文本排版文本 Md16 textPrimary；行高 24=cellTitleLineHeight 库 token（Md16 文本基准行高，两端同值注释锚定）；多行顶部对齐可换行；光标原生行高 24 为库内已有 token（Android AppTokens.cellTitleLineHeight=24sp / iOS cellTitleLineHeight=24pt 注释锚定），非新造硬编码
可视行高rows 参数（Int，默认 3）决定可视行数；整件高 = rows × 行高24 + 上下内边距 md12×2；默认 3 行 = 3×24+24 = 96pt/96dp（96=2×48 交互行基准，同 Signature #40 默认板高 96 注释锚定）rows 由宿主传（1~N），空态/输入态/长文态同高（超限内部滚动，不抖动）；宽度=宿主决定
placeholdertextSecondary Md16 顶部左对齐（不居中=多行阅读起点在左上）库内无 textTertiary token=placeholder 用 textSecondary（同 Input #29 实现惯例=InputView/Input.kt placeholder=textSecondary，注释锚定）
滚动内容行数超过可视 rows 时内部滚动（内容滚动查看+光标随键入滚到可视底部）iOS UITextView 原生滚动 / Android 内容容器 verticalScroll（平台差异表 §05）
禁用/限制disabled=整壳 textSecondary 40% 灰+不可编辑不可滚动不可点；maxLength（0/缺省=不限）仅对输入路径截断（外部赋值不强制截断）disabled 优先级最高（灰态可读不可编辑）；maxLength 含粘贴/连续输入只收前 N（同 Input #29 惯例）

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 组件定位：ACE 三选

选项后果评估
A：通用多行文本域内容组件（受控）——灰底圆角壳+多行文本排版（Md16 行高 24）+placeholder（顶部左）+受控 value/onTextChange+rows 可视行+内部滚动+maxLength 截断+disabled；宿主容器/Form 决定宽度与 label/校验✅ 长文本录入核心闭环收敛；视觉语言复用 Input #29 壳=同一输入语言的两形态（单行/多行）；无内嵌 label/校验=与 Form 划界干净；双端实现=系统多行控件（UITextView/BasicTextField）+壳+滚动，轻量可靠推荐 A：通用内容组件（多行形态）
B：做成 Form 绑定"文本行"（内置 label/必填星/错误渲染/字数）与 FormFieldRow #28（label+required+help/error）职责重复；脱离 Form 不可用=复用性差；字数=宿主展示语义淘汰：label/校验/字数=Form/宿主职责
C：承载富文本编辑（加粗/颜色/图片/emoji 面板）体量与原生控件能力远超文本录入域；双端富文本内核各自体系（iOS TextKit vs Android Span）1:1 极难；与组件库文本录入主线无关淘汰：专项自研/宿主场景，二期候选专项

P2 · 数据/接口模型：ACE 三选

选项后果评估
A：String value + onTextChange(String) 直通——value 唯一真源、每次编辑回传新文本；配套 placeholder/rows/maxLength/disabled 参数✅ 与 Input #29 完全同构（单行直通模型升多行），两端原生多行控件（UITextView.text/BasicTextField value+onValueChange）零转译；宿主天然持全量文本（字数统计/校验/提交都需要）推荐 A：直通模型（同 Input）
B：细分事件模型（onFocus/onBlur/onChange 分段）一期无聚焦态 UI 需求=过度；与 Input #29 惯例不一致淘汰：二期（若聚焦强调视觉立项再补）
C：双向绑定包装（宿主传对象引用、组件直接改对象字段）跨端契约对象引用语义不同、回写链隐晦难排查；与库内值+回调惯例不符淘汰

P3 · 状态控制：ACE 三选

选项后果评估
A：受控 value（必传，外部 setValue=直接刷新文本；onTextChange 仅在用户编辑触发）——iOS 命令式 text 属性外部赋值即时刷新；Android value 参数变化自动重组✅ 文本组件天然受控（宿主必须存文本=双源不可能）；外部预填/清空/追加=直接改 value 即回显且不触发编辑回调（D2 demo）；两端编辑回调与外部赋值路径清晰分离（同 Input #29）推荐 A：文本=受控真源
B：半受控（value 可选，nil=组件内部持值自管理）内部自持文本=宿主字数统计/提交时不可得；与"宿主需全量文本"诉求冲突淘汰：多行文本不自持双源
C：纯自管理+onSubmit 才回传实时编辑过程宿主不知=字数/校验/联动无法做淘汰

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：多行文本域=灰壳+多行排版（Md16 行高 24）+placeholder（顶部左）+受控 value+rows 可视行（默认 3）+内部滚动+maxLength（输入截断）+disabled+demo 四段✅ 长文本录入完整闭环（空态/输入/长文滚动/禁用/外部驱动/截断）可逐验；rows 宿主可控高度=适用简介/备注/留言多场景；无 label/校验/字数=与 Form 组合由宿主演示推荐 A：核心闭环可验收
B：一期含 autoGrow 随内容自动增高 + 字数统计角标autoGrow=内容变化改组件高（需测量/回写宿主布局=交互面大）；字数=宿主可读 value 自理（TextArea 内置角标=越界展示职责）淘汰：登记二期（autoGrow/字数=宿主或二期）
C：一期含工具栏（emoji/@/图片附件）或富文本片段工具栏=宿主场景能力；富文本=P1-C 已淘汰淘汰：宿主自理

05 · 平台差异表（表内放行，表外必须双端统一）

维度iOSAndroid放行原因
文本编辑内核UITextView（scrollEnabled=true；delegate textViewDidChange/shouldChangeCharacters 截断；textContainerInset=0 对齐壳内边距由组件布局给）BasicTextField 多行（同 Input #29 同源；onValueChange 截断；外层容器 verticalScroll）系统输入控件不同、多行编辑行为一致（表内放行）
placeholderUITextView 无原生 placeholder=自绘 UILabel 叠放（textSecondary Md16 顶部左；空值且有输入焦点仍显示=轻量实现/输入即隐）decorationBox 内空值 Text（textSecondary Md16 顶部左）平台 placeholder 机制不同、视觉一致（表内放行）
行高排版textView.font=Md16 + attributedText/typingAttributes 段落行高 24（NSMutableParagraphStyle minimum/maximum lineHeight）textStyle Md16 + lineHeight 24sp（Compose TextLineHeightStyle 默认）平台排版 API 不同、行高 24 数值同（表内放行）
内部滚动UITextView 原生 scrollEnabled（内容超高自动可滚、光标随输入滚入可视）内容 BasicTextField 外层 verticalScroll(rememberScrollState)（光标跟随=ScrollableTextState 焦点滚动，见实现）平台滚动机制不同、行为一致（表内放行）
软键盘回车UITextView return 默认=换行（无 done 键）；键盘收起=宿主外部（demo 提供"收起键盘"段内钮）KeyboardOptions imeAction=Default 多行换行；键盘收起=宿主 IME 避让/外部钮多行文本语义=换行非提交；收起宿主职责（表内放行）
禁用机制isEditable=false + isSelectable=false + 整壳灰化 40%enabled=false（BasicTextField 只读语义）+ 整壳灰化 40%平台禁用实现不同（表内放行）
状态回写命令式：外部 text 属性赋值即时刷新（不触发 delegate）声明式：value 参数变化自动重组受控组件两端真源一致、刷新机制不同（表内放行）
尺寸单位 / 命名pt；TextAreaView（独立 TextAreaView.swift，含灰壳+UITextView+placeholder 层）dp；@Composable TextArea（TextArea.kt）Token 同值不同单位；命名差异见门禁 B（表内放行）
