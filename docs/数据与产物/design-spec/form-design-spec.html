Form 表单 · 设计规格（数据录入组件 #? · 任务清单 #28，subcategory=form · 门禁 A）

组件 ID：ui.form ｜ 定位：表单布局容器组件（表单容器 + 字段行 + 校验文案渲染，不含具体输入控件）——宿主用 Form 卡片分组承载一批 FormFieldRow 字段行（分组标题/字段标题/必填星/帮助文案/行内校验错误文案/提交区槽），具体输入控件（Input/Checkbox/Radio/Switch/TextArea/InputNumber 等）为库内独立组件由宿主放入字段内容区；校验算法与表单状态管理=宿主职责（校验结论经 error 文案传入组件渲染），本组件=纯布局+校验态渲染管道。对标 NutUI Form（FormItem label/required/error 字段行 + 提交）收敛为库内自有设计语言（分组卡片 + 字段行 + 校验文案），与已验收录入三件（Address/CalendarCard/Cascader）同属数据录入区。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-06，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 任何"一组字段 + 提交"的表单页布局：把字段行按分组卡片组织（label 左 + 内容右 + 下方校验错误行）；② 必填标记（label 前主色 *）+ 帮助文案（字段下方或行内次色小字）展示；③ 校验反馈：宿主校验后把 error 文案传入对应字段行，组件渲染行内红字（成功态=无 error 即默认）；④ 提交动作区：卡片内提交按钮槽（按钮用库内 Button #? /宿主样式）
不适用（N/A）① 具体输入控件（Input/TextArea/Checkbox/Radio/Switch/InputNumber/Rate/Signature 等）→ 各自独立组件（本组件不做渲染）；② 声明式 rules 校验引擎/整体提交流程/必填自动判定 → 宿主职责（校验算法与业务强相关）；③ 弹层/弹出键盘 → 宿主自理；④ 页头页尾工具条 → NavBar/宿主布局
五态适配默认态 ✅ 字段行 label 主色文字、内容次色或宿主控件；必填态 ✅ label 前主色 *；校验态 ✅ error 非空=行内红字 12 展示（表单无禁用/加载/完成态=组件仅容器）
与现有组件关系deps=[DesignTokens, Button 提交槽宿主可自选]；与 Checkbox/Input/Radio/Switch 等"录入字段件"划界=本组件只做行容器不产输入；与 Cell #? 划界=Cell 是列表行（内容居中/箭头跳转导航语义），FormFieldRow 是表单字段行（label+内容+错误三区排版、无导航箭头）；字段间分隔 hairline 同 Cell 先例

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
字段行行 min 高 48pt/48dp；label 字号 Md=16 主色；内容区字号 Md=16（宿主控件/文案自定）；行内左右 padding=spaceLg（16）一行=label 区 + 内容区同高基线；内容超高时行随内容增高（min-height 语义）；行间不设固定间距=直接纵排
必填星* 字号 Md=16、主色 primary、位于 label 前required=true 显示；可选字段不显示
帮助文案字号 Sm=12、次色 textSecondary；位置=行内 label 右侧/内容下方？=行内（label 后紧跟，仅一行 max 单行省略）help 可空；默认字段无 help 不占位
校验错误字号 Sm=12、错误红 error（库红 token，实现时对齐 DesignTokens）；位于字段行内容下方独立行error 非空=行高展开追加一行红字；error 空=不占位（校验通过/未校验无错误行）
分组Form 分组卡片：卡片容器=DesignTokens 卡片（bgCard/圆角 lg/border 线宽 hairline/padding lg 内容）复用既有 Grid 卡片语言；分组标题=字号 Sm=12 次色（可选，卡片间空档 spacingMd）Form 可嵌套 1~N 分组；单组（无分组标题）即纯字段卡
分隔线字段行间 hairline（iOS 1/scale pt vs Android 0.5dp，表内放行）；卡内边距 inset 16、分隔线 inset=0 通卡（同 Cell）本卡片内相邻字段行以 hairline 分隔
label 换行label 单行优先；超长时可占多行（label 顶部对齐、行高保持 20+），最大宽=行宽的 45%长 label 不强制省略（表单语义=完整标题可见）

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 组件定位：ACE 三选

选项后果评估
A：表单布局容器（分组卡片 + FormFieldRow 字段行：label/必填/help/error + 提交槽），输入控件=库内独立组件由宿主放入，校验算法宿主自理✅ 与"录入字段件各自独立"的库路线一致（不重复造输入）；校验文案管道=表单组件核心差异点、可独立验收；不依赖具体字段组件实现进度（demo 用已实现或宿主 mock 控件填充）推荐 A：收敛可验收
B：完整表单引擎——声明式 rules 校验 + 提交聚合 + 字段级 onValidate 绑定需定义 rules 表达式语言/与每类字段组件绑校验回调（多件字段组件尚未实现）；规则 DSL 双端各一套；面大且难独立验收淘汰：登记二期（随字段组件齐备后单独立项）
C：退化为"仅单列排版容器"（无 label/required/error 语义的通用 Stack）与 Space/Layout 等既有容器重复；表单语义丢失（label/必填/校验展示无标准落点）淘汰：与既有容器重叠无增量

P2 · 字段行建模：ACE 三选

选项后果评估
A：FormFieldRow(label, required?, help?, error?, content) 声明式字段行——label/必填星/help 展示于左侧与行内，error 展示于字段内容下方红字；content=宿主内容视图/组合子区✅ 表单字段行的四要素齐（label/必填/帮助/错误）且行内结构固定=双端排版确定可对齐；content 开放=能放任何输入控件推荐 A：结构化字段行=容器价值核心
B：仅"错误文案槽"（ErrorText 组件独立，字段行=通用行）字段行排版退化为通用行（label 对齐/必填/help 无固定语义）；表单页各行 label 区宽度需宿主逐个手调=无组件价值淘汰：编排成本转移宿主
C：双向表单模型绑定（每行 value 从组件回传宿主再回填）字段值语义=各输入控件职责；Form 不持有 value（P1-A 无引擎），重复建模淘汰：与 P1-A 自洽（引擎二期）

P3 · 状态与校验管道：ACE 三选

选项后果评估
A：纯展示无状态——FormFieldRow 的 error/required/help 均"只进不出"（宿主持有校验结论，组件仅渲染）；字段内容交互（输入等）走各自控件回调（宿主自行收）✅ 单方向数据流、组件无内部状态机=最简单可靠；与"无表单引擎"定位闭环；双端行为天然一致推荐 A：容器不骗状态
B：半受控校验态——组件内部记住 lastError、宿主可重置多余状态面（宿主本就持有校验结论）；表单提交时批量清错需再同步可接受但无收益
C：内置必填自动校验（required+空值即红）判定"空"需感知各字段控件值（同 P1-B 引擎问题）；规则耦合宿主字段模型淘汰：校验规则宿主自理

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：分组卡片容器 + FormFieldRow（label 左内容右 + required 星 + help 行内 + error 行下红字）+ 单分组/多分组 + 提交槽（宿主按钮）+ demo 四段（基础字段布局/多行校验态/长 label 与无 label/多分组提交）✅ 覆盖"表单页排版 + 校验文案渲染"核心闭环；字段内容用宿主 mock/既有控件填充（不依赖字段组件实现进度）；对齐 Cell 行分隔先例推荐 A：验收路径清晰
B：一期即含 rules 引擎 + 多类字段组件内置字段组件缺口多（Input/Checkbox iOS 等未实现）；rules DSL 双端成本高（P1-B 同问题）淘汰：登记二期（引擎随字段组件齐备另立项）
C：一期即做"表单页整页模板"（页头页尾 + 提交全局壳）页框架=宿主页面职责（NavBar/安全区由宿主叠）；组件强行整页壳=宿主难复用局部表单块淘汰：宿主页面自由组装

05 · 平台差异表（表内放行，表外必须双端统一）

维度iOSAndroid放行原因
字段内容嵌入contentView（UIView 宿主传入）content lambda（Composable 槽位）容器内容区插槽：命令式/声明式各自槽语法（表内放行，同 Space/Layout 先例）
分隔线线宽1/scale pt0.5dphairline 视觉一致（表内放行，同全库先例）
行容器UIStackView/约束排列Column 纵排系统布局机制不同、结果一致（表内放行）
文字省略UILabel truncateTailText ellipsis两端系统文本省略行为一致指向（表内放行）
尺寸数值单位 / 命名pt；struct Form/FormFieldRowdp；data class FormFieldRow + @Composable FormToken 同值不同单位；模型命名差异见门禁 B（表内放行）

06 · API 草案（双端一致契约，门禁 B 据此登记 api.json）

端API
共用FormFieldRow：label: String（空=无 label 内容全宽）+ required: Boolean = false + help: String? = nil（行内小字）+ error: String? = nil（非空=内容下红字行）+ 内容槽；label 超长折行（≤ 行宽 45%，顶部对齐）；Form：分组标题 groupTitle: String? 可选 + 内放 1~N 字段行 + 提交区槽（宿主自放按钮）
iOSfinal class FormFieldRow: UIView
init(label: String?, required: Bool = false, help: String? = nil, error: String? = nil, content: UIView)
final class Form: UIView
init(groupTitle: String? = nil, rows: [FormFieldRow]) + addRow(_:) + submitView: UIView?（槽）；error/required 可后续 set 刷新（var error: String? didSet 重排）
Android@Composable fun Form(groupTitle: String? = null, modifier: Modifier = Modifier, content: ColumnScope.() -> Unit) + FormFieldRow(label: String? = null, required: Boolean = false, help: String? = null, error: String? = null, modifier: Modifier = Modifier, content: RowScope.() -> Unit)
宿主在 content 内放任意输入控件；error 变化触发重组渲染红字行
