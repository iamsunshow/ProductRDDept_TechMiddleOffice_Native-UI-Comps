LineChart Android · 设计规格（业务展示组件 · 任务清单 #96 · 业务展示补全 · 门禁 A）

组件 ID：ui.line-chart（Android 端补全，iOS 已 v1.7.5 收编）｜ 定位：折线图 Android 端——业务展示通用折线图组件，支持单/双折线 + 数据点 + 网格 + Y 轴自适应 + x/y 轴标签；与 iOS LineChartView（DGCharts 同构）双端 1:1 收敛；对标 iOS Charts (DGCharts) LineChartView 收敛为库内自有设计语言（Canvas drawLine 自绘 + 圆点 3dp + 网格 0.5dp）。
组件库版本 设计阶段锁定基线 = v1.0.8（2026-09-15，未过 C2/D 不升版）
业务回填 KeepAccounts 记账 DualLineChart 双端均需替换（评估文档 §5 行 72，2026-09-16 真实状态核对）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 业务报表趋势展示（记账月度收入/支出）；② 健康数据（心率/步数）；③ 销售趋势（电商 GMV）；④ 任何时序数据可视化；⑤ 双系列对比（如计划 vs 实际）
不适用（N/A）① 横向条形图 → BarChart（ui.bar-chart，#97 立项）；② 饼图/环形分布 → PieChart（业务二期）；③ 数字动画 → AnimatingNumbers #61；④ 单一数值 → Price #72；⑤ 时间戳自驱 → Countdown #60；⑥ 比例表达 → Progress #74 / ProgressCircle #83；⑦ 高频实时流（K 线图/股票）→ 业务自管不沉淀
五态适配默认态=白底（bgCard）+ 主色折线（primary）+ 数据点 3dp 圆；加载=空数据骨架（保留网格不画线）；空态=空数据文案「暂无数据」+ 文案 sizeSm textSecondary；成功/失败 N/A
与现有组件关系deps=[DesignTokens]；收编现状=iOS LineChartView 已 v1.7.5 收编（基于 DGCharts/Charts 第三方库，业务展示区 #381 ui.line-chart，api.json 行 3617 已登记）；Android 当前无独立 LineChart（业务 DualLineChart 自建 Canvas drawLine），本规格=Android 端补全独立组件，与 iOS 同库同绘图语言（双端 1:1 Canvas 自绘，不引入第三方库）；与 BarChart #97（立项）严格划界（线 vs 条）

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 组件定位：ACE 三选

选项后果评估
A：Android 端独立组件（双端 1:1 Canvas 自绘）——与 iOS LineChartView v1.7.5 同库同绘图语言同构；不引入第三方库；单/双折线 + 数据点 + 网格 + x/y 标签✅ 与业务现状（记账 DualLineChart）1:1 收敛；双端同一组件；不引入第三方库=无版本依赖推荐 A：业务收敛独立
B：引入 MPAndroidChart 第三方库（与 iOS DGCharts 对齐）Android 引入第三方库=版本维护负担；与 iOS 同为第三方库双端一致性高但库体本身可纯自绘达到同效果淘汰：自绘可达同效果
C：children 插槽（宿主自组 Line/Point/Label）组件退化为"画布"，业务必须自管所有绘图细节；双端契约松散淘汰：登记二期

P2 · 数据/API 模型：ACE 三选

选项后果评估
A：声明式数据驱动——LineChart(values: [Float], data: [Float]? = nil, xLabels: [String]? = nil, yLabels: [String]? = nil, fixedYMin: Float? = nil, fixedYMax: Float? = nil)；data 非 nil 时为双折线（series2）✅ 与 iOS LineChartView 数据模型 1:1 同构；单/双折线统一 API（data 切换）；xLabels/yLabels 可选覆盖；fixedYMin/Max 可选推荐 A：与 iOS 同构
B：双 API（LineChart 单 + DualLineChart 双）两个组件职责重叠；双折线场景业务必须判断选哪个淘汰：单 API 覆盖两场景
C：children 插槽失去组件语义淘汰

P3 · Y 轴自适应策略：ACE 三选

选项后果评估
A：默认自适应 + 宿主可传 fixedYMin/Max 覆盖——yFor(value)= (maxY-minY) × (1 - (value-minY)/(maxY-minY))，domain = [min(values)-0.1×range, max(values)+0.1×range]✅ 与 iOS LineChartView v1.7.5 spaceTop/Bottom=0.1 同构；宿主可锁死对比基线；视觉合理推荐 A：自适应 + 可覆盖
B：永远自适应（不覆盖）业务对比场景无法对齐基线；用户体验差淘汰
C：永远 fixed（必传）失去自适应易用性；常见场景多此一举淘汰

P4 · 一期范围：ACE 三选

选项后果评估
A：一期=数据驱动单/双折线+数据点+网格+xLabels/yLabels+fixedYMin/Max+Demo 四段（D1 单系列基础/D2 双系列对比/D3 xLabels 月份/D4 fixedYMin/Max 锁死基线）✅ 覆盖业务记账 DualLineChart 现状；双端 1:1 收敛；验收可达推荐 A：一期收敛
B：一期+二期候选（曲线/区域填充/多系列 3+/滚动缩放）超出 DualLineChart 业务范围；二期候选足够淘汰：登记二期
C：一期=空壳+业务全自管无组件价值淘汰

05 · 平台差异表（表内放行）

差异点iOS（v1.7.5 已收编）Android（本规格立项）放行原因
绘图引擎DGCharts (Charts 第三方库) LineChartView + ChartDataEntryCompose Canvas drawLine + drawCircle（自绘不引第三方库）与 iOS 同效果双端独立选择实现方式
数据点ChartDataEntry x+y + MarkerViewdrawCircle 直接传 cx/cy/radiusAPI 差异视觉同
网格DGCharts gridConfigCanvas drawLine 4 条横线视觉同
Y 轴DGCharts leftAxis spaceTop/Bottom=0.1yFor() 函数 domain + 0.1 padding算法同实现异
坐标转换CGFloat CGPoint 像素Dp + Float 像素（Compose dp→px 转换）类型系统差异

特别说明：iOS 现状=第三方库（DGCharts/Charts）非纯库侧实现，本规格=Android 端从零自绘 Canvas drawLine = 与 iOS 视觉效果 1:1 同构但实现路径不同。本批 §5 修正段已澄清 iOS 是 Vendor/Charts 第三方库非组件库实现；本规格 Android 端按 Canvas 自绘不引入第三方库。
