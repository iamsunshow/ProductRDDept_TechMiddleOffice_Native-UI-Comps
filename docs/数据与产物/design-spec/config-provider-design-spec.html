01用途与场景

本库 token 体系（design-token.json → 双端 AppTokens）是编译期静态基准；ConfigProvider 是其运行时覆盖层，解决「同一包不同皮肤 / 同一 App 不同子区域微调」的诉求，避免业务逐组件改样式或全局写死。
  • 典型场景：品牌皮肤切换（主题色覆盖）、紧凑模式（iPad/管理页密度）、局部区块圆角风格统一、多语言入口预留。
  • 组合关系：应用根节点挂一个（全局生效），也可在某子树再挂一个（局部覆盖，内层优先）。
  • 反模式（anti-goals）：不做远程动态配置下发（Remote Config 属 business.content-config）；不做多主题包管理（主题包业务维护）；不替代 design-token.json 静态基准。
    • 范围边界：本组件是配置通道（Provider/上下文），不产出任何视觉像素；「配置如何消费」由消费组件按 token 引用实现，因此本组件无五态（默认/禁用/加载/成功/失败不适用），设计测试改为「配置生效测试」（见 04 节与验收文档 D 系列）。

    02配置能力清单

    v1 覆盖四项，每项给出覆盖目标、影响的 token、双端生效方式。
    配置项类型 / 默认覆盖目标影响 token双端生效方式
    primaryColor string?（十六进制） 主题色系（主色 / 按压 / 浅底） color.primary、color.primaryPressed、color.primaryMuted iOS：全局覆盖 AppColor.primary 解析；Android：CompositionLocal 注入
    rounded boolean?，默认 false 圆角整体提升一档 radius.sm→md、md→lg、lg→xl（无 xl 时 lg 封顶） 双端：圆角解析函数读覆盖档位
    compact boolean?，默认 false 间距整体降一档（紧凑密度） space.md→sm、lg→md、xl→lg 双端：间距解析函数读覆盖档位
    locale 'zh-CN' | 'en-US'?，默认 'zh-CN' 组件文案语言 文案表（v1 建立通道，业务文案后续接入） 双端：语言上下文透传
    覆盖语义：覆盖是对「静态基准 + 父级配置」的叠加替换（见 03 优先级）；未覆盖项完全沿用静态基准，保证未挂 Provider 的场景零行为变化。

    03运行机制与优先级

    配置沿组件树向下穿透：任意后代组件读取「最近一层 ConfigProvider」的合并结果，无需逐层透传 props。
    ConfigProvider
    primaryColor=#4F46E5
    应用根节点挂载
    →
    全局配置上下文
    合并：静态基准 + 覆盖项
    →
    任意后代组件
    Button / Cell / Form… 读取即用
  • 优先级（内层优先）：嵌套 <ConfigProvider> 时，内层覆盖外层同名项；外层未覆盖项继承。
  • 合并规则：每层 primaryColor / rounded / compact / locale 独立合并，未设项取父级，全未设取静态基准。
  • 静态基准不变：design-token.json 与双端 AppTokens 静态常量不被修改；覆盖仅发生在「读取解析」层，保证 D5（不污染基准）可测。
  • 实现方案：iOS 用 UIAppearance（UIKit 外观）+ 环境对象（SwiftUI/声明式）；Android 用 CompositionLocal（Compose 原生上下文）。
