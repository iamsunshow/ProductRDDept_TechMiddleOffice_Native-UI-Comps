SearchBar 搜索栏 · 设计规格

组件 ID：ui.search-bar 数据录入区 #38 subcategory=form 全新立项（基座沿用 Input #29，检索语义独立） 设计稿 2026-09-06 门禁 A

01 · SCQA 组件定位与边界

适用场景（S）

「输入关键词发起检索」的通用入口：① 首页/列表页顶部搜索入口=占位提示+键盘「搜索」键直接检索；② 页面内检索过滤=输入即触发宿主本地筛选（onTextChange 实时拿词）；③ 显式搜索按钮布局=后置按钮与键盘搜索键双路径（trailing 槽宿主放钮）；④ 多端列表/联系人等过滤场景复用。组件只出「搜索输入行」，真正的检索执行、命中结果/历史/联想列表=宿主自理。

目标与冲突（C）

需求=「搜索输入壳+放大镜+清除+触发检索」的直觉入口；冲突=Input #29 是通用单行文本输入（无放大镜无 onSearch 检索语义，不做搜索栏直接用=缺检索触发与前置放大镜视觉）；iOS 系统 UISearchBar（独立白底圆角条+自动取消钮、36 高）与 Android 系统 SearchBar（Material 3 样式）视觉均脱离库内设计语言不可直接入库；NutUI 的圆角胶囊变体需按库内壳惯例收敛。

问题（Q）

库内是否新增通用「SearchBar 搜索栏」内容组件（在 Input #29 已收编基座上扩展检索语义）？

答案（A）

定位 是。新增 ui.search-bar=搜索输入栏：壳=48 灰底 radius lg 圆角输入行（同 Input #29 壳 token），前置放大镜图标（自绘 glyph 灰）+ 文本输入 + 非空显示清除钮（点击清空回传空串）；半受控 value String? + onTextChange（实时直通）+ onSearch（键盘「搜索/回车」触发一次=宿主执行真实检索自理结果）+ disabled 40% 灰 + placeholder + maxLength 截断 + trailing 尾槽（宿主放搜索/取消钮=与键盘搜索键双路径）；真实检索/结果/历史/联想=宿主自理；胶囊 shape、自动聚焦、语音/相机搜索=二期/不做。

五态适配

默认态 ✅ 空串=placeholder 灰提示、无清除钮；壳 bgPage 灰底 radius lg 无边框；输入中态 ✅ 文本 primary 黑、非空即显示清除钮（20 圆灰底白叉）、输入实时 onTextChange 直通、超长文本壳内左滚（scrollable 不折行）；触发态 ✅ 键盘「搜索」键/回车=onSearch(当前文本) 一次性回调（空串也回调=宿主自行决定是否忽略），清除钮点击=文本清空并回调 onTextChange("")；禁用态 ✅ disabled=整行 40% 灰、不可输入、清除钮隐藏、无任何回调（同 Input #29 惯例）；边缘态 ✅ maxLength 仅截断键盘输入路径（外部赋值不截断，同 Input #29）、文本非空+disabled=回显灰文不显示清除钮；加载/失败 N/A（搜索中的 loading/结果态=宿主自理，组件无内部异步态）。

划界与依赖

依赖=DesignTokens（AppColor/AppSpace/AppRadius）+ 已收编 Input #29 的壳/清除钮/键盘/截断实现惯例作基座（复用不复制：SearchBar 不是 Input 参数扩展，是带检索语义的独立组件）。与同区组件划界：Input #29=通用单行文本输入无检索语义（SearchBar=放大镜+onSearch 触发=专为检索而生的壳）；ShortPassword #39=掩码短密码专用（SearchBar 明文关键词）；Picker #33 / Menu #31 / Cascader #24=选项选择（SearchBar 自由文本）；Cascader/Address #24/#21=结构化录入。业务方（首页搜索、列表过滤、通讯录/标签检索等）复用本组件，宿主自理：真实检索执行、防抖、历史/热词/联想下拉、结果页/空态、loading。

03 · 关键决策（P1–P4 投票表）

P1 组件形态与视觉基座

选项方案后果结论
A搜索输入壳=48 灰底 radius lg（对齐 Input #29 壳 token）+ 前置放大镜（自绘 glyph 14 灰）+ 文本输入 + 非空清除钮 + trailing 宿主槽与已收编 Input #29 同壳语言=视觉家族一致可平滑迁移（AppInputField/Input 场景换用即得检索语义）；无系统控件视觉分裂A 推荐 ✅
BNutUI 圆角胶囊（round-large）壳样式区分化与库内 Input 方形圆角壳（radius lg）双体系=破坏壳语言统一二期 shape 参数候选（默认方形）
CiOS 系统 UISearchBar / Android 系统 Material SearchBar 直接收编iOS=36 高白底+自动取消钮、Android=Material 3 样式，双端视觉语义脱离库内设计语言且两端不自洽淘汰（不收编）

P2 检索触发模型

选项方案后果结论
AonSearch=软键盘「搜索」键/回车触发一次回调（空串也回调由宿主自行忽略）；组件不内置提交文字钮=后置搜索按钮走 trailing 宿主槽（与键盘双路径）；清除钮=点击清空回调 onTextChange("")触发点收敛到键盘一主路径（宿主 trailing 钮自调 onSearch 语义=第二路径），端侧差异最小（iOS/Android 软键盘搜索键语义一致）；检索执行完全宿主A 推荐 ✅
B内置「搜索」文字提交钮（壳右内嵌）与 iOS 系统取消钮/两端搜索钮显示惯例冲突（nutUI 无内置提交文字钮），且空串提交判定边界多淘汰（按钮类=宿主尾槽自理）
C无 onSearch 仅 onTextChange（纯过滤输入框）与 Input #29 撞车、无检索提交语义=组件价值不足淘汰

P3 状态与事件（受控/回调/禁用）

选项方案后果结论
A半受控：value String? 可选（nil=内部自持输入=宿主无需回写也可正常打字，onTextChange 实时拿词）；外部赋值=同步回显不触发 onTextChange；disabled=整行 40% 灰不可输入、清除钮隐藏、无任何回调；maxLength 仅截断键盘输入路径检索宿主大多「拿词即用不回写」=半受控免回写最顺手（与 #25/#35/#36 半受控惯例一致）；需要受控（联想清空联动）时外部回写即可A 推荐 ✅
B受控 value 必传（同 Input #29）+ onTextChange 直通搜索场景强制宿主每一步回写=检索过滤宿主（只读回调不回写）光标抖动/输入丢失风险高淘汰（Input 才用必传受控）
C纯非受控只读回调（无 value 外部驱动）宿主「清空按钮/外部导航带词」等回显场景无法驱动淘汰

P4 一期裁剪与 Demo 四段

选项方案后果结论
A一期=搜索输入壳+放大镜+清除钮+半受控 value+onTextChange+onSearch+disabled+placeholder+maxLength+trailing 槽+demo 四段：D1 基础搜索输入（placeholder+onTextChange 回显+非空清除钮点击清空回传空串）｜D2 键盘搜索键触发 onSearch（回显「搜索：xxx」+下方静态列表按词过滤=演示宿主检索自理的接法）｜D3 禁用与外部驱动（disabled 开关 40% 灰不可输入+外部 value 赋值仅回显不触发 onTextChange+重置）｜D4 trailing 定制槽（后置「搜索」按钮=与键盘搜索键双路径触发演示）主输入+清除+提交触发+禁用+外部驱动+尾槽关键边界全覆盖；检索执行/历史/联想=宿主自理边界清晰A 推荐 ✅
B一期含胶囊 shape 参数 + 自动聚焦 + 防抖内置形状参数化破坏壳统一、聚焦/防抖=宿主职责=一期膨胀二期候选/宿主自理
C一期内置搜索历史/热词联想下拉数据源/交互端差异大=浮层组件职责（随 Popup 二期体系）淘汰（宿主自理）

06 · API 契约（供门禁 B api.json 立项登记）

#字段/参数类型必填说明
1valueString?否半受控：nil=内部自持输入（宿主可不回写，onTextChange 实时拿词）；外部赋值=仅同步回显不触发 onTextChange
