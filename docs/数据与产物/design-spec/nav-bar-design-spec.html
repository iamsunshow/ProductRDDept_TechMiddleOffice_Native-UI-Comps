NavBar 头部导航 · 设计规格（导航组件 · 任务清单 #17 · 收编缺口补独立立项 · 门禁 A）

组件 ID：ui.nav-bar ｜ 定位：页面顶部单行头部导航条——页面顶栏常驻一行：可选返回钮（左侧）+ 居中标题 + 可选右侧动作，点击回传 onBack / onAction；页面内容与导航栈由宿主自理；对标 iOS UINavigationBar / Material TopAppBar / NutUI React NavBar（title + 左右插槽 + 返回）收敛为库内自有设计语言（内容行 44pt/44dp + 白底 + 底部 hairline + 标题单行省略）。
组件库版本 设计阶段锁定基线 = v1.4.0（2026-09-04，未过 C2/D 不升版）

01 · 组件用途 & 不适用边界（SCQA）

维度说明
适用场景① 二级/详情页顶栏：返回上一级 + 当前页标题（最常用）；② 一级页顶栏：仅标题居中（无返回）；③ 顶栏右侧放单动作（"保存/编辑/更多/完成"文字或单字符 icon），点击交业务回调；④ 需要品牌化顶栏标题/动作色的页面；⑤ 顶栏标题为长文案需单行省略的页面
不适用（N/A）① 底部一级页面导航 → Tabbar（ui.tabbar，#19）；② 页面内顶部内容切换（页签+内容区）→ Tabs（ui.tabs，#20）；③ 左侧目录导航轨 → SideBar（ui.side-bar，#18）；④ 悬浮面板/悬浮钮 → FixedNav（ui.fixed-nav，#15）/ HoverButton（ui.hover-button，#16）；⑤ 沉浸式/透明渐变叠加图顶栏 → 二期候选（anti_goals）；⑥ 系统级导航栈容器（UINavigationController 栈管理/转场）→ 宿主自理，组件只出"条"
五态适配默认态=白底（bgCard）+ 主色返回钮 + 主文字标题/动作；激活/按压=返回钮与动作点击有瞬态按压反馈（平台差异见 §05）；禁用/加载/成功/失败 N/A（顶栏非数据态组件，业务态由宿主承载）
与现有组件关系deps=[DesignTokens]；收编现状=Android ScreenTopBar（sharedui/components/CommonComponents.kt，页面内嵌 scaffold 共享件）为业务近似，非库内独立组件；iOS 无独立 NavBar（业务用系统 UINavigationBar），本规格将近似收编升级为双端统一独立组件（同 Grid v2.0 NavigationGrid→Grid 收编升级先例）；顶部系统 inset（状态栏）避让=宿主（页面）自理：宿主可用 SafeArea 组件包裹，或置于系统导航栈内（demo 用卡片内模拟场景，卡片顶即组件条起点）；与 SafeArea（ui.safe-area，#10）协作而非内置

02 · 尺寸/Token 规格（零硬编码）

要素Token说明
内容行高44pt/44dp（宿主可高度约束覆盖）对齐 iOS UINavigationBar 标准 44 / Android ScreenTopBar 现状 44；行业基线=M3 TopAppBar 64 含 inset、NutUI NavBar 44+状态栏，库内取 44=业务现状（ScreenTopBar）保持一致；顶部状态栏 inset 不在组件行内（宿主自理，见 §01）
标题字号 Lg（18pt/18dp）Semibold、textPrimary、单行省略（行尾）标题在无左右槽/短文案时严格居中；有返回+右动作时以剩余可用区居中（iOS 系统导航标题居中语义），长标题单行省略、双端一致
返回钮（可选）字符 22pt/22dp（=AppFont.sizeXl）主色 primary；点击热区 ≥40×44（整行高）onBack 非 nil 时显示；icon=库内文本字形（如 "←"，门禁 B 锁定双端同一 glyph，不走 Icon 组件资源映射=登记二期）；热区左对齐热区含 padding
右侧动作（可选）文字 14pt/14dp（=sizeSm）Regular 或主色，热区 ≥44 高rightAction 文案非空时显示（文字形态）；纯文字/单字符均支持；颜色默认 textPrimary（宿主可传 color 覆盖品牌色）；点击交 onAction
背景/分隔白底 bgCard；行底 hairline（iOS 1/scale pt vs Android 0.5dp 表内放行）与系统导航条白底 + 底部细线视觉一致；无左右内边距常态（左右热区自带内边距）
与 Tabbar/Tabs 区分NavBar=顶部一行导航条（返回+标题+单动作）Tabbar=底部多标签跨页导航（icon+文字、56 行高）；Tabs=页内顶部页签切换内容；NavBar 无选中态概念

03 · 关键决策 PREP / ACE（人为决策 4 条，编号 P1–P4，AI 代评待用户总审）

P1 · 组件定位：ACE 三选

选项后果评估
A：纯顶部导航条（收编升级）——内容行 44、可选返回钮 + 居中标题 + 可选右侧动作，onBack/onAction 回调；页面内容与导航栈/转场宿主自理；状态栏 inset 宿主叠 SafeArea/系统栈处理✅ 与业务现状 ScreenTopBar 语义对齐、双端 1:1 清晰；把"页面内嵌近似"提升为库内独立可验收组件（同 Grid v2.0 先例）；宿主可自由决定嵌系统栈或页面内嵌；无系统容器强绑定推荐 A：收编升级收敛
B：收编系统 UINavigationBar / Material TopAppBar 容器本体（含 inset、大标题、导航栈联动）系统栏含 inset/大标题/转场联动等多能力，双端行为（大小标题切换、bar 联动、appearance 差异）难 1:1，非单 UI 组件职责；验收周期失控淘汰：系统容器联动=宿主/二期
C：复合功能头（搜索框/下拉选择/多级标题/分段等业务型复合顶栏）业务形态差异大（各页顶栏内容完全不同），做成"通用条 + 任意插槽"才可覆盖=插槽化，一期组件边界失守淘汰：登记二期候选（通用插槽化顶栏另行立项）

P2 · 数据/API 模型：ACE 三选

选项后果评估
A：声明式单参数——NavBar(title: String, onBack: (() -> Void)? = nil, rightAction: (text: String, onTap: () -> Void)? = nil, actionColor: ... = nil)；右动作=文本 + 回调（单动作一期）；onBack=nil 不显示返回钮✅ 与 ScreenTopBar(title, onBack) 现状 1:1 升级（仅增右动作）；参数少而直白、Demo 可验；无 children/插槽复杂度；标题/返回/动作全部具名化推荐 A：声明式最简模型
B：children 插槽（iOS 任意子视图槽位 / Android content slot，左右槽自由排布）自由度过高：等分/间距/热区统一由宿主维护，组件仅"白条容器"，退化为无语义壳；双端契约（任意插槽）难对齐淘汰：登记二期（复合头部另行立项）
C：全配置对象（NavBarConfig 多字段：leftItems[] / rightItems[] / titleStyle / bg / ... 数组化）一期只有 返回+标题+右单动作 的确定形态，数组/多按钮/样式字典远超需求=过度设计淘汰：形态确定时不做通用配置化

P3 · 返回/动作语义与幂等：ACE 三选

选项后果评估
A：onBack 回调触发返回（宿主路由自理，可自行决定是否入栈/弹栈/关闭）；onAction 触发右动作；点击即回调（顶栏动作无"选中态"无幂等需求）；同屏重复点按每次均回调✅ 顶栏是"命令钮"非"选中钮"——每次点击都应执行（如"保存"连点需宿主侧去抖，不归组件管）；语义与系统导航条一致；组件无内部状态、无需受控推荐 A：命令式无状态语义
B：带选中/受控态的"导航条"（selected 概念、幂等、受控高亮）顶栏没有选中态语义（无多选一），硬套选中状态=概念错位；受控/高亮需求不存在淘汰：概念不适用
C：自动执行导航栈 pop（iOS 内部 UINavigationController.pop / Android finish）组件内部动宿主导航栈=强耦合（pop 目标、present 场景、深链场景都不一致），无法跨宿主复用；违反"宿主自理"总原则淘汰：导航动作宿主自理

P4 · 一期范围裁剪：ACE 三选

选项后果评估
A：title + 可选返回钮 + 可选右单动作（文本）+ 长标题单行省略 + 白底 hairline + Demo 四段（基础返回/一级页无返回/右动作回调/长标题省略对照）✅ 覆盖顶栏 90% 使用（返回+标题+单动作闭环）；Demo 可 1:1 排查返回回调/动作回调/标题省略；双端契约收敛到 5 参数内推荐 A：验收路径清晰
B：一期即做 左右双动作 + 自定义背景色/透明沉浸 + 多行标题 + 字号分级左右双动作热区挤压标题/沉浸与大标题复杂化（状态栏深浅/渐变），一期验收失控；与"系统导航栈容器"职责边界冲突淘汰：登记二期（沉浸/双动作/大标题）
C：一期内置状态栏 inset 与页面边缘避让（免宿主 SafeArea）组件自带 inset 需感知 WindowInsets/safeArea 环境，Demo 卡片内无法正确呈现、双端感知差异大；与 SafeArea 组件职责重叠淘汰：inset 宿主自理（同 Tabbar 底部安全区宿主叠 SafeArea 先例）

05 · 平台差异表（表内放行，表外必须双端统一）

维度iOSAndroid放行原因

文字省略截断UILabel 单行 truncateTailText overflow=Ellipsis（maxLines=1）两端系统文本省略行为一致指向（表内放行，同全库先例）
标题严格居中实现UIStackView：左右槽为等宽占位或 centerX 标题Box + align(Center) / Row weight 对称占位系统级布局机制不同、结果同=视觉居中（表内放行）
尺寸数值单位ptdpToken 同一数值不同单位（表内放行，同全库先例）
数据模型命名class NavBar / NavBarAction@Composable NavBar(...) / data class NavBarAction契约同构（表内放行，命名差异见门禁 B）
