Price 价格

组件 ID：ui.price ｜ 信息展示区组件 #72 ｜ TMO 组件库 v1.4.31

定位：用于商品、订单、营销等场景的价格展示——支持货币符号、千分位、小数位、符号大小与位置、前缀后缀文本，双端 1:1 视觉一致。

1. 场景与边界（SCQA）

Situation 情景

电商、交易、账本等 App 中价格是最高频的信息单元，商品卡片、订单详情、营销会场、对账列表都需要展示金额。

Complication 冲突

各业务页手写字符串拼接「¥」+ 数字 + 「元」，千分位/小数位规则不统一，符号大小与数字脱节、前后缀颜色字号各自实现，双端表现漂移且易错（如缺小数位、符号间距过大）。

Question 问题

需要一个价格展示组件，统一货币符号、千分位分隔、小数位数、符号相对数字的大小与位置，支持前缀后缀文本，双端 1:1 视觉一致。

Answer 方案

Price——由「前缀文本 + 货币符号 + 整数部分 + 小数部分 + 后缀文本」组成的行内价格组件，price 数值驱动，decimal-places 控制小数位、thousands 千分位、symbol 货币符号及大小/位置、prefix/suffix 自定义前后缀，颜色与字号通过 color/size 配置。

2. 组件边界与划界

组件职责与 Price 划界
Badge #64右上角数字/圆点徽标Badge=提醒标记；Price=金额展示，形态是「符号+数字+前后缀」行内排版
Tag #37状态/分类标签Tag=胶囊文本标签；Price 无背景胶囊，是金额数字本身
InputNumber #44数字步进输入InputNumber=可交互输入数字；Price=纯展示不可编辑
CountDown #60倒计时数字展示CountDown=时间倒计时动态刷新；Price=静态金额展示（数字动画=二期）

4. 决策投票表（ACE 模型：选项 / 评估后果 / 选最优）

编号决策点选项（Alternatives）评估后果（Consequences）选最优（Evaluate）理由
P1price 输入类型 A. number 数值
B. string 字符串		 A. 数值可参与计算、可统一做千分位/小数位格式化，业务无需手动格式化
B. 使用方需提前格式化，组件做不了千分位/小数位，且无法防非法		 A number 驱动千分位与小数位逻辑，与 NutUI 一致；非法/非数字 fallback「0」保证不崩
P2千分位与小数位 A. thousands=true 显示逗号，decimal-places=2 默认两位小数
B. 不格式化原样输出		 A. 大金额更易读，小数位统一对齐；电商金额惯例保留两位
B. 简单但金额可读性差、小数位不统一		 A 默认 thousands=true、decimal-places=2，与金额场景惯例一致；decimal-places=0 可隐藏小数
P3符号大小与位置 A. symbol 单独字号（默认 = 小数位字号）+ symbolPosition front/after
B. 符号与整数同字号		 A. 视觉上符号略小于整数是价格排版惯例，front/after 适配「¥199」「199元」两种形态
B. 符号与整数同高会显得符号突兀		 A 符号用独立 symbolSize（默认跟随 size 阶梯的小数位字号），position 支持前/后，覆盖「¥199」与「199元」
P4前后缀文本 A. prefix/suffix 自定义文本（textSecondary、小字号）
B. 仅支持 symbol		 A. 覆盖「￥199 起」「到手 ￥199」等组合文案
B. 复杂场景需业务外层再拼文本		 A prefix/suffix 支持组合文案，颜色默认 textSecondary、字号 sizeXs，与价格主体形成层级
